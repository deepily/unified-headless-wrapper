# The fleet (T16): how personas are staffed, housed, re-spun and retired once the kernel owns every process

**As of:** 2026-11-09 · **Author:** Rick (with Claude) · **Claude doc:** https://claude.ai/artifact/7HbgHzYUmsFoPKRCbkrDTs · **Ruled as D59;** design of record `specs/2026.11.09-t16-fleet-spec.md`

## Why this matters

The fleet layer is where today's harness spent the most code defending against itself, and the kernel removes the cause of most of that defence. Roughly 13,300 lines in lupin staff, house, re-spin and retire seats. A large share exists because no single process knows the fleet: a manager writes a lineage file before its child has registered, every seat runs its own frozen copy of the policy code, and a seat's death is inferred from a terminal pane.

Under the kernel, one process starts every engine, holds one registry and sees every turn end. Six fleet jobs change hands:

| Fleet job today | How it works today | Owner under the kernel |
| --- | --- | --- |
| Staff a seat | a manager's tool call runs a launcher script inside a terminal multiplexer | a kernel route, called by the same tool |
| Limit the fleet | a cap checked in each seat's own tool process, then again in the launcher | one admission check in the kernel |
| House a seat | a private git worktree under the main checkout, named after the pane | a worktree keyed on the persona id |
| Retire a seat | ask for a memento by direct message, poll the disk, kill the pane, tear down the tree | the re-spin handshake with a different ending |
| Re-spin a seat | the seat types `/clear` into its own pane through a detached injector | already ruled with persona bootstrap and context exhaustion |
| Bill a seat to the cloud | a launcher flag that sets Claude's Vertex variables | a manifest field, built with the Claude adapter |

Three questions were handed to this item by earlier rulings and have no answer yet. The log and console rulings asked whether a fleet spans more than one host. The credential ruling asked whether personas on a production host run under an unprivileged account. The fleet register row asked whether Vertex billing has an equivalent outside Claude.

Host capacity (how many engine processes a machine holds) and system broadcasts are the next two items and are not decided here. This document leaves each a named slot.

## The principles this item rests on

1. **One process knows the fleet.** The registry is the census, the lineage and the liveness record. Nothing is inferred from files a child may not have written yet.
2. **Rick's three cap rulings of 2026-09-03 stand.** One number for the whole fleet; over the cap, new spawns are refused and nobody is reaped; every persona counts, managers included.
3. **A rule that depends on someone acting on a message is not a control.** Lupin's own lesson from the shared-checkout incident: where a hazard is known, the default placement fixes it; an alarm does not.
4. **Work is never lost at retirement, and nobody becomes immortal.** A persona whose own account of its work is not on disk is not stopped without an explicit override. The override always exists.
5. **Keep and report beats clean and silent.** A tree with uncommitted or unmerged work is kept and named to its manager. Nothing is pushed, ever.
6. **Re-spin is not staffing.** The persona keeps its id, its tree, its voice and its task rows. No admission, no credit, no reconciliation.
7. **The kernel is on the control path.** It decides whether a spawn may happen. It does not route work between hosts.
8. **Engine-neutral names.** Nothing introduced here carries `cc`, `claude_code` or `tmux`.

## The problems, stated one at a time

**Problem 1: the staffing verbs have no kernel contract.** The first-cut route takes one manifest template and returns one row. The tool a manager calls takes a count, a brief, a role, a project, a voice preference, a seed memento and a model. Nothing says how the second becomes the first, how a batch behaves, or how the kernel knows which persona is asking. Engine choice is a new argument the old verb never had.

**Problem 2: the cap has three mechanisms and none fits.** The per-call cap, the fleet cap with its second check in the launcher, and the skeleton-crew switch with its credit file total about 1,980 lines. Most of that exists because the census is a scan of files and the policy code is frozen in each seat. The kernel has neither defect, and it also has no launcher to put a check in.

**Problem 3: nothing creates a persona's worktree, and the old location is unsafe to share.** The provisioner renders into a tree that must already exist. The old lane sits under `.claude/`, is named after a pane, and is swept by the arbiter's janitor, which decides a seat is gone partly by the absence of a pane. During the first build phase the old harness and the kernel run on the same host.

**Problem 4: retirement has four hard-won gates and no kernel form.** Memento before the kill, with a withhold and an override. The branch probe, which names and never withholds. Tree teardown, which keeps and reports. Task rows, which are reassigned. Each was added after a measured loss. The kernel already owns a handshake that asks for a memento and waits for the turn to end, but only re-spin uses it.

**Problem 5: harvest-before-reap is a message, and nothing checks it.** The steward's `harvest-complete` is a direct message the manager is trusted to have read. Principle 3 says that is not a control.

**Problem 6: lineage has an owner now, so orphans need a rule.** A manager can be dismissed while its workers live. Today a time limit reaps idle seats so they stop holding a login. Under the kernel an idle engine costs memory, not tokens, and the registry never loses track of it.

**Problem 7: whether a fleet spans hosts was deferred here twice.** The log ruling and the console ruling each left a fallback (a tail served by the kernel) pending this answer. Jetski runs only on the work cloud workstation; AGY and Claude run on the development server and the test VM.

**Problem 8: on a production host the persona account can read whatever the human can.** The test VM is accepted as it is because nothing human lives there. The development server is Rick's own machine.

**Problem 9: Vertex billing is a launcher flag for one engine.** The launcher goes away. The 890 lines of region guards behind the flag should not.

## Proposed solutions

### Solution 1: The staffing routes and who is asking (Problem 1)

The three tool names stay. A spawn is a role's manifest template plus a short list of named overrides, and the kernel learns who is asking from its own gate record.

| Route on the kernel socket | Body | Does |
| --- | --- | --- |
| `POST /personas` | `{ role, count, overrides, persona_id?, tool_call_sha256? }` | admits the batch, then per child: mints the id, creates the tree, provisions, starts the engine |
| `GET /personas?manager_id=&subtree=` |  | roster rows; a manager sees its own subtree |
| `POST /personas/{id}/dismiss` | `{ memento: required or skip, force, reason, reports: refuse, cascade or a new manager id }` | Solution 4 |
| `POST /personas/{id}/respin` | `{ trigger, engine?, model? }` | the ruled handshake; an engine or model given here is how a persona changes engine |
| `PATCH /personas/{id}` | `{ manager_id }` | reassigns a report |
| `POST /personas/{id}/harvest` |  | Solution 5 |
| `DELETE /personas/{id}` |  | kept from the first cut: the operator's immediate stop, equal to dismiss with `force` and `memento: skip` |

- **Template plus overrides.** `role` selects `~/.lupin/manifests/<role>.yaml`. The overrides allowed are `engine`, `model`, `project`, `brief`, `voice_preference`, `seed_memento` and `billing`; any other key is refused by name. The tool's `task_prompt` becomes `brief`, rendered once per child with the role, the manager's id and the index, as today.
- **Batches.** Admission is all or nothing and the refusal names how many fit. After admission a child that fails to start is reported on its own row and the rest proceed, as today.
- **The roster has one axis.** The kernel mints the id and starts the process, so a row is never "alive but unidentified". The four identity states and the age heuristic are not ported.

Who is asking, three options:

| Option | For | Against |
| --- | --- | --- |
| **A. The gate's own record.** A persona's tool server sends its persona id and a hash of the call's arguments. The kernel accepts the route only against an unused gate allow for that persona, tool and hash, at most 30 seconds old. The CLI sends neither and is logged as the operator. | `manager_id` is witnessed, not asserted. Every gate record already carries the hash. It is the in-kernel half of the signed-grant mechanism filed under authenticated persona identity, so nothing is thrown away. | About 40 lines. The tool server must hash the arguments exactly as the hook saw them; one check at the build. |
| B. Trust the id in the tool server's environment. | Nothing to build. | A confused persona can staff or dismiss as another; lineage becomes a claim. |
| C. Wait for authenticated persona identity. | One mechanism for everything. | That item is scheduled with the kernel's move into lupin; staffing is needed for the second phase. |

**Recommended: A.**

### Solution 2: One admission check, in the kernel (Problem 2)

Admission is an ordered list of checks run under one lock with the creation of the rows. The first refusal wins and is returned verbatim to the caller.

```python
# admission.py — each check returns a refusal string or None; pure, no I/O
def admit( requested, rows, config ):
    live     = [ row for row in rows if row.state != "closed" ]
    managers = sum( row.role in ( "chief_of_staff", "manager" ) for row in live )
    room     = max( 0, config.size_cap - len( live ) )
    checks   = (
        lambda: "skeleton crew is on: no spawns; a re-spin is still allowed" if config.skeleton_crew else None,
        lambda: f"{requested} requested, per-call cap is {config.batch_cap}" if requested > config.batch_cap else None,
        lambda: ( f"fleet cap {config.size_cap}: {len( live )} live "
                  f"({managers} managers, {len( live ) - managers} workers), {room} fit, {requested} requested" )
                if requested > room else None,
        # slot: engine quota (authentication and quota item) · slot: host capacity (next item)
    )
    return next( ( refusal for check in checks if ( refusal := check() ) is not None ), None )
```

- **Configuration** is a `[fleet]` section of the kernel's own file: `size_cap` (14), `size_cap_maximum` (18), `batch_cap` (8), `skeleton_crew` (false). It is read from disk at every admission, so a changed dial needs no restart.
- **Rick's three rulings carry over unchanged:** one number, refuse and never reap, managers count. The refusal keeps the manager and worker split, so a cap consumed by managers reads as that and not as a broken spawner.
- **Every decision is logged with the census it took** (`fleet.admitted`, `fleet.refused`). Lupin's forensics of 2026-09-04 could not recover the count a refusing gate had seen.
- **The fail-open question disappears.** The census is the kernel's own memory; there is no unreadable fleet.
- **Re-spin is not admitted at all** (Principle 6). The credit file and re-spin retention are not ported.
- **The dial in Lupin** (`/api/arbiter/fleet-size-cap`) is repointed at a kernel route after the move.

| Option | For | Against |
| --- | --- | --- |
| **A. In the kernel, as above** | One process, one census, one lock. About 60 lines replace about 1,980. | The cap is per kernel; see Solution 7. |
| B. The cap lives in Lupin and the kernel asks | One number across several hosts. | Puts Lupin on the path of every spawn, against Principle 7. |
| C. Port lupin's three modules | Familiar. | They count bridge files and defend against a stale process that no longer exists. |

**Recommended: A.**

### Solution 3: Every persona gets its own worktree, outside the old lane (Problem 3)

The kernel creates the tree before the provisioner renders into it, keyed on the persona id.

```
<worktree_root>/<repository>/<persona_id>/        worktree_root default ~/.lupin/kernel/worktrees, set per host
  created:  git -C <main> worktree add --detach <path> HEAD
  locked:   git -C <main> worktree lock --reason lupin-persona:<persona_id> <path>
  then:     each command under worktree_setup: in <repository>/.lupin/project.yaml   (lupin: the virtual-environment link script)
  then:     the ruled provisioner (kit, mandates, instruction files, exclude entries)
```

- **Every persona, managers and the chief of staff included.** The main checkout belongs to the human. Reviewers read peers' commits through git, as today.
- **The tree outlives the process.** Re-spin, hibernation (Solution 6) and an engine change keep it. Only retirement touches it.
- **Failure is visible.** A failed `worktree add` refuses that child. A failed setup step is an alert-level `provision.worktree` record and one spoken line; the spawn proceeds, which is today's behaviour made loud.
- **The two axes stay apart.** Platform (the tool server's interpreter and import path) is the kernel's `lupin.root`, written into the rendered tool-server config. Work is the tree.

| Option | For | Against |
| --- | --- | --- |
| **A. Outside every repository, keyed on the id** | Outside the lane the old janitor sweeps, which matters while both harnesses share a host. Survives re-spin and engine change. No ignore entry; a search of the main checkout does not descend into persona trees. | A second place to look. The root must sit on a volume with room; on the development server that means setting it. |
| B. `<main>/.lupin/worktrees/<persona_id>` | Beside the code. | Needs an ignore entry in every repository, in a folder that also holds a committed file. Nested trees are walked by searches and test discovery in the main checkout. |
| C. Keep `<main>/.claude/worktrees/seat-<name>` | No port. | Named for one engine and for a pane that no longer exists. The old janitor would be judging whether a kernel persona is alive. |

**Recommended: A.**

### Solution 4: Dismissal is the re-spin handshake with a different ending (Problem 4)

The four gates keep their rulings and their order. What changes is that the kernel sees the turn end, so nothing polls the disk.

```
POST /personas/{id}/dismiss
  1. reports      live reports? refuse, cascade or reassign (Solution 6)
  2. memento      required → the ruled request block, worded "prepare to be dismissed";
                             wait for the turn to end (600 s); a record stamped with this id, newer than the request?
                               found        → continue
                               missed twice → withheld_no_memento: the persona stays, the caller is told why
                  skip     → continue          (a reviewer whose work is its report)
                  force    → continue whatever step 2 found
  3. branch probe commits the working line lacks → named in the result and in one line to the manager; never withholds
  4. stop         the engine process
  5. tree         uncommitted edits, ignored data files or unmerged commits → kept and reported
                  clean and merged → git worktree remove, git branch -d; never a push
  6. close        open task rows reassigned to the manager; voice released; row state closed
```

- **Result per persona:** `retired`, `withheld_no_memento` or `already_closed`, with the branch and tree outcomes beside it and one top-level line for anything kept or withheld.
- **What is not ported:** the 45-second poll, the second look before the kill, and the re-spin retention list. The first two exist because a verdict taken at ask time could be stale by kill time. The third exists because re-spin used to be a dismissal.
- **Kept trees are swept later.** A tree whose persona is closed, idle past six hours, has its work committed to its branch and its directory removed; one refused for 24 hours becomes a task row owned by the manager. Both rules are lupin's, unchanged. A tree whose persona is not closed is never swept.
- **When it is built.** Steps 1, 2, 4 and 6 are kernel code for the second phase. Steps 3 and 5 import lupin's `reap_branch`, `seat_teardown` and `worktree_reaper` after the move, with their is-the-seat-alive test answered by the registry. In the first phase `DELETE` stops the one persona and keeps its tree.

A missing memento, three options:

| Option | For | Against |
| --- | --- | --- |
| **A. Withhold, with `force`** | Lupin's ruling after two of four alarmed seats turned out to have written a record 30 seconds late. A dismissed persona cannot rebuild its account afterwards. | A fourth outcome every caller must handle. |
| B. Stop anyway and say so, as re-spin's cold fallback does | One behaviour for both verbs. | A re-spun persona continues and can rebuild from the task store; a dismissed one is gone. |
| C. Always require a memento | No flag. | Makes every finished reviewer write one. |

**Recommended: A.**

### Solution 6: A manager with live reports is not dismissed by default (Problem 6)

The dismiss route takes `reports`. The default refuses and names the reports. `cascade` dismisses each report first, through all of Solution 4. A manager id reassigns them. An engine crash orphans nobody: the row and its reports stay, and the process is started again on the next message.

| Option | For | Against |
| --- | --- | --- |
| **A. Refuse unless told** | The caller decides in one more call. Nothing is stranded and nothing is stopped by surprise. | One more round trip when a whole crew goes. |
| B. Cascade automatically | One call ends a crew. | Dismissing a manager silently ends work it did not own the decision for. |
| C. Reassign to the chief of staff automatically | Nothing is stranded. | The chief of staff inherits crews it never briefed. |

**Recommended: A.**

### Solution 7: An idle persona is hibernated, never reaped (Problem 6)

The old time limit reaped idle seats so they would stop holding a login. Under the kernel the persona and its process are separate things, so the process can go while the persona stays.

- **Hibernate.** A persona with no turn running and an empty queue for `idle_hibernate_minutes` (30) has its engine process stopped. The row stays, `process_id` is empty and `hibernated_at` is set. The next inbound message starts the process on the same conversation, behind the ruled resume check.
- **Cost.** About two seconds on the next message, the measured gain from a warm process. The Jetski family already exits and resumes after every interrupt, so the path is exercised daily.
- **Counting.** A hibernated persona still counts against the fleet cap, which limits staffing. It does not count against host capacity, which limits processes and is the next item.
- **Advice, not action.** A persona hibernated past `idle_advise_hours` (24) produces one line to its manager. The kernel never retires a persona on its own.

| Option | For | Against |
| --- | --- | --- |
| **A. Hibernate and advise** | Frees memory and loses nothing. Identity, tree, voice and task rows survive. | A two-second start on the first message after a quiet spell. |
| B. Port the idle reap | Parity. | Destroys an identity to save memory, and retires what a manager meant to keep. |
| C. Keep every process warm | Fastest. | Memory per AGY process is unmeasured and a fleet of 14 holds it all day. |

**Recommended: A.**

### Solution 8: One kernel per host, one fleet per Lupin instance (Problem 7)

| Option | For | Against |
| --- | --- | --- |
| **A. Each host is a self-contained fleet.** One kernel, one registry, one cap, attached to the Lupin instance on that host. A manager staffs only on its own host. No kernel talks to another kernel. | Matches what exists: the development server with its instance, the test VM with its instance. Jetski stays as the record has it: checked occasionally on the work cloud workstation, not part of a standing fleet.

### Solution 10: Billing is a manifest field, and Vertex stays with Claude (Problem 9)
