## Problems and options

### 1. Two modules write one grammar, and nothing sends the deferred wake's lines

The deferred wake was ruled in the morning (row 104) and the seven lines in the afternoon (row 107), so each got a module. They now hold the same two levels twice, two pairs of functions with one name and different parameters, and a test whose only job is to prove the copies agree. The sending rule (a block when there is a manager, a card every time) is code for the seven lines and prose for the deferred wake.

- **A. One sender: the deferred wake is an eighth line (recommended).** `deferred_wake.py` keeps the causes and their words (`CONFIGURATION`, `HOST_CAPACITY`, `CAUSES`, `REMEDIES`, `SETTINGS_FILE_NOTICE_LEVEL`, `check_reason`, `build_manager_sentence`) and gains one function, `build_deferral_advice( name, reason, key )`, returning the same `Advice` record the other lines use. `manager_advice.py` gains a seventh event word, `DEFERRED`. The kernel sends it with `advise_manager` like the rest. Retired: `NOTICE_LEVELS`, `BLOCK_WORDS`, `get_notice_level`, and the deferred-wake module's `build_manager_block` and `build_human_card`. *For:* one place decides who is told; the builder has nothing to invent; a row 106 cause (sign-in, quota) adds two phrases and a level. *Against:* it retires three names you confirmed on 2026-11-20 (row 104, ruling 6: `get_notice_level`, `build_manager_block`, `build_human_card`), and two specs' amendments name them. Every block and card produced is byte for byte what was ruled.
- **B. As written.** Two modules; the test keeps them in step; the kernel's wake path writes its own "manager or none" branch. *For:* nothing ruled changes. *Against:* the sending rule exists twice, once untested; two functions share a name across modules the builder imports side by side.
- **C. One module.** Move everything into `manager_advice.py` and delete `deferred_wake.py`. *For:* fewest files. *Against:* it also retires the module name you confirmed, and puts the settings file's wording in a module about managers.

### 2. The card's text field is `text`; Lupin calls it `message`

The card is "a suggestion to the client", in Lupin's taxonomy by your ruling. Two of its three fields already bear Lupin's names.

- **A. `message` (recommended).** *For:* the card is passed to `/api/notify` as it stands, with no renaming step where a field could be dropped. *Against:* one string changed in two modules and their tests.
- **B. `text`, as written.** *For:* nothing changes. *Against:* the kernel's poster must translate one field of three, and the reason is nowhere written.

Not decided here, and not on row 108: what else the posted card carries (the target user, a title, whether it is marked `payload.kind: kernel_event` as the kernel's restart notice is). I propose a new row for it rather than a thirteenth question; it bites at Kernel-3, with the first real Lupin.

### 3. The errors of the deferred-wake module

The amendment says a cause with no ruled words raises a `ValueError`, so that nothing invents words for sign-in and quota before row 106. That holds on three paths of four.

- **A. Confirm the `ValueError`, and close the two holes (recommended).** Every function checks the cause first, so the fourth path raises `ValueError` too; a key that is empty or blank is refused like a missing one. *For:* the stated behavior becomes the actual one; two tests added. *Against:* none found. (Under option A of problem 1 the fourth path disappears and only the empty key remains.)
- **B. Confirm as written.** *Against:* the amendment's sentence is false for one function.
- **C. A named error instead of `ValueError`** (as `ConfigurationError` was named for the tables). *For:* a caller can catch it apart. *Against:* these are programming errors, not conditions any caller handles; a name adds nothing.

### 4. The twelve constants of the advice module

`ALERT`, `INFO`; `CARD_LEVELS`; the six event words `PRESSURE`, `COMPACTED`, `HIBERNATED`, `UNMERGED`, `HELD`, `KILLED`; the three setting values `RESPIN`, `ADVISE`, `INTERRUPT`. Each is a noun or a state word, none abbreviated, and the values are the words you ruled.

- **A. Confirm (recommended).** (A thirteenth, `DEFERRED`, joins them if problem 1 is ruled A.)
- **B. Rename.** I have no candidate that reads better.

### 5. The sending function's three parameters and its return value

`advise_manager( persona, level, word, body, *, hhmmss, write_block, post_card )` returns whether a manager was told. The module has no clock and no network of its own, so the kernel passes the time of day and two functions in by name.

- **A. Confirm (recommended).** *For:* `hhmmss` is the parameter name the ruled turn-end policy code already uses for the same value (`render_poke_block( hhmmss, … )`, spec line 254); the two writers are verbs with their objects, as the naming rule asks of functions; the module stays dependency-free and testable. *Against:* `hhmmss` is a format, not a word.
- **B. `clock_time` for `hhmmss`.** *For:* a plain noun. *Against:* two names for one value across the kernel, or a rename in a ruled spec's code as well.
- **C. Return nothing.** *For:* no caller in the reference code uses the value. *Against:* the log record of the event can say whether a manager was told only if something reports it.

### 6. A writer that fails (on no list)

Ruling 12 of row 107 says a card Lupin refuses "is refused with a 400 and the manager's block still arrives". The code keeps that promise by order alone (block first), and then lets the refusal travel up into `assess()`, the function that decides a re-spin, or into the dismissal, or into the memory sampler. Until Lupin gains `info` (row 111), every `info` line does this.

- **A. Neither failure reaches the caller (recommended).** `advise_manager` tries the block, then the card, each on its own; a failure of either is written to the kernel's log and the other is still tried; nothing is retried. The return value stays "whether a manager was told", now meaning the block was written. *For:* a notice can never break the thing it reports on; ruling 12 becomes true by construction; no duplicate block from a retry. *Against:* a lost card is visible only in the log. The log record's name and fields would be set while recording and put to you as their own click.
- **B. As written: the error travels up.** *For:* nothing is hidden. *Against:* each of six callers must catch it, and none of the reference code does; a re-spin decision could be abandoned because a card was refused.
- **C. The card first, then the block.** *Against:* reverses ruling 12: a refused card would stop the block.

### 7. The errors of the advice module, and the order of checking

A `ValueError` for a level that is neither `alert` nor `info`, for a `pressure.action` or held-turn action outside its two values, and for a branch probe reporting fewer than one commit; the level is checked before the block is written, so a bad level sends nothing. The probe confirms all four.

- **A. Confirm (recommended).**
- **B. A named error.** As in problem 3: these are programming errors.

### 8. "1 hours" and "1 seconds" (on no list)

Ruling 13 made "1 commit" singular. The hibernation line takes its hours from `kernel fleet idle advise hours` (24 by default; nothing forbids 1), and the held-call line its seconds from the call's age.

- **A. Singular for all three (recommended):** "for 1 hour", "for 1 second". *For:* one rule; two lines of code and two tests. *Against:* none found.
- **B. Hours only.** The held-turn threshold is 600 seconds by default, so "1 second" would need a setting nobody would choose. *Against:* a rule with an exception.
- **C. As written.**

### 9. The two lines that stand in for `narrate_chain`

The context-exhaustion spec's older code calls `narrate_chain` twice. The amendment reads each call as two lines: build the line (`build_pressure_advice`, `build_compaction_advice`), then `session.kernel.advise_manager( session.persona, advice.level, advice.word, advice.body )`, the kernel supplying the clock and the writers.

- **A. Confirm (recommended).** *For:* it is the ruled function called with the ruled record.
- **B. One line: `advise_manager` takes the `Advice` record whole.** *For:* shorter. *Against:* changes the signature you ruled (row 107, ruling 7).

### 10. Which block wakes a manager that is itself hibernated

A manager with nothing to do hibernates after thirty minutes like anyone else. The record reads every kernel block as an inbound message, so each one starts the sleeping manager's engine and spends a turn. For an `alert` that is the point: you ruled that the manager reassigns unmerged commits. For an `info` it is not: your words for that level were "informing and implicitly not expecting anything to come of it". And for one `info` it is perverse: "waiting for room on the host" asks the host for room.

- **A. Only an `alert` wakes it (recommended).** An `info` block is written to the sleeping manager's inbox and read at its next wake, whatever causes that; your card arrives at once either way. *For:* it follows the level's meaning and the broadcasts precedent (a broadcast to all waits for the next wake); no engine start and no turn spent to tell a sleeping manager that its report is asleep; the no-room notice stops competing for room. *Against:* a manager may read stale news (a pressure line for a persona that has since re-spun); the inbox must hold a block without asking for a wake, which the envelope spec's queue does today only for a broadcast to all.
- **B. Every block wakes it, as written.** *For:* one rule; the manager's knowledge is never stale. *Against:* the table above; each wake of a manager restarts its own thirty-minute and twenty-four-hour clocks, so its manager is later told of its hibernation again.
- **C. No block wakes it.** *For:* cheapest. *Against:* unmerged commits and a killed process would wait on a manager that nothing else wakes, which empties your ruling that the manager acts on an alert.

### 11. When that wake is deferred in turn

Under a broken settings file no wake is admitted, so the manager woken by an `alert` is itself deferred. The amendment reads that as an ordinary deferred wake: the manager's own manager gets a block about the manager, you get a card, and so on upward until a persona that is awake, in practice the chief of staff. This does not contradict "nobody above the manager": each block is about a different persona, sent to that persona's own manager. You have by then had the file's own line once, at `urgent`.

- **A. Confirm, and state it as a test's clause (recommended).** One deferred wake, one block, one card, at every level, with no special case. *For:* no new rule; the count is bounded by the depth of the fleet (the probe: three cards for two sleeping managers). *Against:* under a broken file you receive one `high` card for each level, all with one cause.
- **B. Stop at the first manager.** A manager's own deferred wake gives you its card and tells nobody above. *For:* fewer blocks. *Against:* a special case in the wake path; the chief of staff does not learn that a manager under it cannot be reached.

### 12. "(the chief of staff for a manager)"

The fleet spec's Section 10 says a day's hibernation sends a line "to the manager (the chief of staff for a manager)". The amendment reads the parenthesis as a description, not a second rule: the block goes to the hibernated persona's own `manager_id`, which for a manager is normally the chief of staff; a persona with none gives you the card alone.

- **A. Confirm (recommended).** *For:* one rule for all eight lines, and it is what `advise_manager` does. *Against:* a manager an operator spawned with no `manager_id` tells you and nobody else.
- **B. Fall back to the chief of staff** when a persona that is not the chief of staff has no manager. *For:* some persona always hears. *Against:* a second addressing rule for one line, against "the manager and nobody above it".
