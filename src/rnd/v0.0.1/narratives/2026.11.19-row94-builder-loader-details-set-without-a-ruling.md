- **C. No trailer on the builder's commits.** Pro: shortest. Con: differs from planning's with no reason on record.

### 3. A pull while work is uncommitted

The loader's first step in every session is `git pull --rebase`, and it pulls again before each push. The host reading of 2026-11-17 found that such a pull refuses while any edit is uncommitted, on any path, and that `--autostash` succeeds. The builder commits only at green steps, so a session that ended on a red step opens the next with a pull that refuses. The loader does not say what to do.

- **A. The loader's two pulls become `git pull --rebase --autostash` (recommended).** Pro: proven on this host; unfinished work is kept and never committed red; planning never writes the builder's paths, so the stash cannot conflict. Con: a failed re-application would leave a stash to find; with disjoint paths that needs a builder error first.
- **B. Commit unfinished work as a marked commit (`[UHW] WIP …`) before any pull.** Pro: nothing lives outside the history. Con: red commits on the shared branch, against "commit at every green step".
- **C. Leave it: a refusal is reported to you.** Pro: no change. Con: a stop in the first minute of a session, for a cause already known.
