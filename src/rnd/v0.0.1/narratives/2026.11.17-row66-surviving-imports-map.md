# The forty files that outlive the old harness and still import it (row 66 of "Outstanding actions")

**As of:** 2026-11-17 · written on the test VM under Antigravity, before any ruling; the rulings column filled the same day, ten for ten as recommended · this repository at `105983d`, lupin at `27e646d0ed` (read-only) · the markdown file is the only copy.

## In brief

When the old harness is deleted, its hooks tree (`src/lupin_cli/claude_code/`) goes in one commit. Yesterday's count found 44 files elsewhere in lupin that are not deleted and import a module from that tree; four were given rows the same day, and the other forty were left as row 66, "not examined beyond the count". This session examined them: a new zero-token script lists every import, the names it takes, and where in the file it sits.

The forty sort into six kinds of want. **Five files already have a ruled replacement** and need only a row in the list. **Two more are ruled in part.** The other thirty-three want something the record has never named: nine want only a path to a data directory, five only the task store's connection settings, six only read the session files to learn who is live, nine belong to the arbiter or its mute switch, two are one-off scripts, and two want two of those things at once. Nine decisions are asked for.

The reading also found three things the count could not see: two modules the list keeps inside the tree import deleted siblings; one of yesterday's four files still has an import its new row does not cover; and the same failure exists outside the tree, where 17 surviving files import 12 other Python files the list deletes. The check that guards the Delete sees none of the three.

## Problems and options

### 1. Thirteen files want only a path, and the path rule lives in modules the Delete removes

Code that has nothing to do with the harness (the symbol index, code health, the reuse ledger, the cron switches, the commons store) asks one question, "where is this repository's data directory", and the answer is written in `heartbeat_hold.py` and `main_tree.py`. They are twelve of the forty and the kept tree module `task_store_map.py`.

- **Move the path functions to one kept module (recommended).** `fleet_data_root`, `_main_repo_path`, `_resolve_base_dir` and `main_tree_root` move into `cosa/utils/fleet_base_dir.py` at the Move; the thirteen files are re-pointed there; `heartbeat_hold` imports them back until it is deleted. *For:* one rule, one place, already half-built; the Delete then removes nothing these files need. *Against:* thirteen files touched in lupin at the Move.
- **Keep `heartbeat_hold` whole.** Change its row to "Keep and import". *For:* no caller changes. *Against:* keeps 1,512 lines of hold logic that D62 deletes, for the sake of three short functions.
- **Each caller derives its own path.** *For:* no shared module. *Against:* thirteen copies of a rule that exists because copies drifted.

### 2. Six files want the task store's connection settings from a loader that is deleted and a file that is archived

The task store's client is kept; the loader that tells it where the store is, is not. The loader reads `~/.claude/settings.json`, which the Switch archives.

- **Move the four values into `lupin-app.ini` (recommended).** Keys under the configuration manager, read by a small function beside the kept client; the six callers re-pointed at the Move; the loader deleted with the tree. *For:* matches the rule that configuration lives in `lupin-app.ini`; survives the archiving of the Claude settings file. *Against:* new keys to name and a Lupin change; the old file and the new keys must agree while both harnesses run.
- **Keep and import the loader as it is.** *For:* a one-line change to the list. *Against:* after the Switch it reads a file that has been archived and silently returns its defaults (`enabled` off).
- **Callers pass literals.** *For:* nothing to keep. *Against:* six places to change when the store moves.

### 3. Eight places in Lupin read the session files for who is live, beyond the four routes already ruled

D63 gave four routes a union read. The direct-message send path, the voice lookup, the notification queue, persona allocation, the commons start-up, the bounce broadcast, the duplicate-check command and the task router read the same files and were not named. During the mixed fleet a kernel persona is invisible to each of them.

- **One roster reader in Lupin, used by every such site (recommended).** A single module added at the Move answers "who is live" and "who is this persona" from the union of session files and kernel roster, source stamped; the four ruled routes and these eight sites all call it; its session-file half is removed at the Delete. *For:* generalizes what D63 already ruled instead of adding eight designs; one place to remove. *Against:* the roster row must carry every field the sites read, which is not yet established (the quiet-worker test); a wider Lupin change at the Move.
- **Re-point each site on its own,** in the order ruled for the task doors (grant, roster, session file). *For:* each site gets exactly what it needs. *Against:* eight small designs, eight removals at the Delete.
- **Leave them on the session files until the Delete.** *For:* no work at the Move. *Against:* a kernel persona cannot be sent a direct message or allocated a voice during the shadow and the soak, which is what those periods exist to test.

### 4. The arbiter's package has no row, and Lupin itself starts the arbiter's job

D24 retires the arbiter into the kernel's fleet-health module, and the list deletes `lupin_arbiter_app/`. The package the job lives in, and the bootstrap in Lupin's start-up that launches it, are unlisted and import six deleted modules.

- **Delete the package and the bootstrap with the arbiter remainder (recommended).** One directory row for `cosa/agents/heartbeat_arbiter/`, file rows for `arbiter_bootstrap.py` (with its call at `main.py:864`) and `follow_through_escalation_watcher.py`, all on the Delete clock after the fleet-health module. The one outside caller, the straggler tickets' manager lookup, is re-pointed at the registry. *For:* it is what D24 says. *Against:* (corrected 2026-11-17, after the ruling: this option first said "nothing else reads these files"; three unrelated files import `prune_window` from the package's `ping_throttle.py`, see decision 10) the registry must be able to name a persona's manager; that is asserted by D59's "liveness from the registry", not shown.
- **Delete all but `manager_resolver.py`.** *For:* the straggler tickets keep working unchanged. *Against:* the resolver reads session files and `session_spawner`, both deleted, so it would have to be rewritten anyway.
- **Keep the package and re-point its inputs.** *For:* no behavior lost. *Against:* contradicts D24: two fleet-health watchers.

### 5. The mute switch's router outlives the mute

`routers/heartbeat.py` serves `GET` and `PUT /api/heartbeat/poke-mute`. D62 deletes the mute, its module and its toggle script.

- **Delete the router and its registration at the Delete (recommended).** *For:* nothing is left to switch. *Against:* the browser has a switch that calls the route (found during the walk-through, 2026-11-17: `static/js/multiplexer/render/pokeMuteSwitch.ts`, `static/js/notifications.js`, `static/html/notifications.html`), so the switch is removed from the client in the same commit or it shows a control that returns 404.
- **Keep the route, answering from the kernel's configuration.** *For:* a caller keeps working. *Against:* invents a kernel setting no ruling asked for.

### 6. The voice server takes prompt text and a log writer from the hook library

`cosa_voice_mcp.py` (kept) composes its instructions and reply tag from three pieces of hook text and logs through the hook log; `kill_guard.py` (kept) logs through it too.

- **The text and the hook log leave with the tree (recommended).** At the Delete the three imports are removed and the voice server's instructions carry only what is its own; a kernel persona gets brevity, routing and direct-message style from the kernel's rendered text, as D53 rules; both files log through their own logger. *For:* one text of record; no hook vocabulary in kept code. *Against:* the voice server's instructions get shorter on the day of the Delete, which must be checked against the kernel's text so nothing is dropped.
- **Copy the three texts into the voice server as its own constants.** *For:* the server's behavior does not change. *Against:* two texts of record, the thing D53 ended.

### 7. The worktree sweep reads a creator ledger that nothing will write

`worktree_straggler_tickets.py` reads who created a worktree from a ledger written by a deleted module.

- **Remove the ledger branch at the Delete; the tree's owner comes from the registry (recommended).** *For:* consistent with D59. *Against:* the fleet spec does not say the registry records who created a tree (read during the walk-through, 2026-11-17: no such field in the T16 spec; its line 202 says a refused tree "becomes a task row owned by the manager", and line 203 that the sweep takes its lane from the row's `worktree_root`). The manager would be reached through the persona row that holds the tree; a tree made by hand, with no row, has no addressee.
- **Keep and import `worktree_creator_record`.** *For:* the sweep is unchanged. *Against:* the module's writer is a hook; with no hooks nothing calls it, so the ledger only ages.

### 8. Two scripts read what the Delete removes

`report-orphaned-dm-buffers.py` reports messages stranded in the listener's buffers; `sweep_persona_slug_canonicalization.py` finds owners from session files.

- **Delete both at the Delete (recommended).** *For:* the buffers and the session files are gone, so neither has a subject. *Against:* the slug sweep may not have been run on every host; it should be run, or declared unneeded, before then.
- **Keep both, re-pointed at the inbox ledger and the roster.** *For:* the tools survive. *Against:* two rewrites for one-off tools.

### 9. The check that guards the Delete has two blind spots

It reads only files outside the tree and only imports of the tree. It therefore misses the two kept tree modules above, and it misses 17 surviving files that import 12 Python files the list deletes elsewhere (for example `lupin_app/main.py` imports the `claude_code_queue` and `speakerphone` routers; seven files import `fleet_cap_ini_io`; `cosa_voice_mcp.py` imports six deleted modules). The script's last section lists them.

- **Widen the check to both, and open a row to map the 17 (recommended).** `t19_hook_import_survivors.sh --check` fails on either class; a new row of "Outstanding actions" maps the second class as this one maps the first. *For:* the Delete cannot break a file the check never read. *Against:* the Delete clock gains failures today, and another mapping session.
- **Widen for the two kept tree modules only.** *For:* closes the smaller gap now. *Against:* leaves 17 known breakages unguarded.
- **Leave the check as it is.** *For:* no work. *Against:* the breakages surface at the Delete commit.

### 10. Three unrelated files import one function from the arbiter's package (found after the walk-through)

Entering decision 4's directory row and re-running the script showed `cosa/agents/decision_proxy/trust_tracker.py:26`, `cosa/agents/deep_research/rate_limiter.py:23` and `cosa/rest/job_health.py:16` importing `prune_window`, a small pure function, from `heartbeat_arbiter/ping_throttle.py` (211 lines). Deleting the package whole breaks all three.

- **Move `prune_window` to a kept utility module at the Move (recommended).** The three callers re-pointed; the package deleted whole. *For:* decision 4 stands as one directory row. *Against:* three more files touched at the Move.
- **Keep `ping_throttle.py`.** *For:* no caller changes. *Against:* an arbiter throttle and its directory survive for one function.
- **Each caller carries a copy.** *For:* no shared module. *Against:* three copies of one rule.
