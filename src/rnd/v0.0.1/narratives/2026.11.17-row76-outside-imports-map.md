# The fifteen files that outlive the old harness and import a file deleted outside its hooks tree (row 76 of "Outstanding actions")

**As of:** 2026-11-17 · written on the test VM under Antigravity, before any ruling; the rulings column filled the same day, eight rulings (six as recommended, one changed by Rick's question, one on a finding made while recording) · this repository at `88368eb`, lupin at `27e646d0ed` (read-only) · the markdown file is the only copy.

## In brief

The switch-over list deletes the old harness in two places: its hooks tree (`src/lupin_cli/claude_code/`), and sixty other Python files scattered through lupin (the spawner, the fleet cap, the arbiter's package, two routers and so on). This morning's session mapped every surviving file that imports the tree. It also found the same failure outside the tree, listed it, and left it unexamined as row 76: fifteen files that are not deleted import twelve of those sixty.

This session examined them. A new zero-token script lists every such import, the names it takes, where in the file it sits, and how large the thing taken is. The fifteen files hold 35 imports. **Eighteen of the 35, in four files, already have a ruled replacement** and need only a line in the record. The other seventeen want something the record has not named, and sort into six questions: a general-purpose editor for the configuration file that happens to live in a fleet-cap module (ten imports, six files); two memento checkers whose every caller is deleted; one seven-line timestamp reader; the name matcher behind the direct-message door; the persona's own re-spin tool; and one field of the session-info tool.

Row 76 also carries the one import this morning's forty left unmapped: the voice server's four calls to the hook library's login reader. Two of the four are ruled away already; the other two are the seventh question.

Seven decisions are asked for. None changes the kernel's design; each says what lupin does at the Move or the Delete so that the Delete commit breaks nothing.

## Problems and options

### 1. Six unrelated files borrow the configuration file's line editor from the fleet cap

`fleet_cap_ini_io.py` is not about the fleet. It reads one key fresh from disk and rewrites one line of `lupin-app.ini` without disturbing the comments, refusing a key defined nowhere or twice. The scheduled jobs' on/off switches, the two reuse gates and the symbol index's librarian all use it, because the configuration manager is a process-lifetime singleton and would hand them a stale value. Four of the six also take a function from `fleet_size_cap.py` that only answers "where is the main checkout's configuration file", and that function in turn calls `_main_repo_path`, which this morning's ruling moves to `cosa/utils/fleet_base_dir.py`.

Deleting both files as listed breaks the scheduled jobs' switches and the reuse gates, none of which the kernel replaces.

- **Move the editor to a kept module under a neutral name, and the path function beside the other path functions (recommended).** `fleet_cap_ini_io.py` becomes `cosa/utils/configuration_line_editor.py` at the Move (a rename row in place of its Delete row); `main_checkout_ini_path` joins `cosa/utils/fleet_base_dir.py`, and `config_file_path`, which returns the same path, is dropped in its favour; the six files are re-pointed; `fleet_size_cap.py` is still deleted whole. *For:* the name says what it is; one path rule; the kernel can borrow the editor for `PUT /fleet/config` if row 72 so rules. *Against:* six files touched at the Move, and one more rename to carry.
- **Keep the file where it is.** Strike its Delete row; move only the path function. *For:* the six imports of the editor do not change. *Against:* a module named for a fleet cap that no longer exists in lupin, in a package the voice server owns.
- **Have the six read through the configuration manager, re-read as the kernel does.** *For:* one reader. *Against:* a writer that keeps comments is still needed for the switches; `cron_switch_read.py` is written to import only the standard library; more behaviour changes than the Delete needs.

### 2. Two memento checkers survive although every caller is deleted

`memento_slot.py` (556 lines) proves that a memento sits at the slot the reader will look in; `memento_slot_audit.py` (264) compares a memento's declared slot with where it landed. The first is imported only by `reap_memento.py`, `self_respin_core.py` (both deleted) and the second; the second is imported by nothing. Each takes names from a deleted file (`verify_seat_memento` and two defaults; five slot constants). The inventory of 2026-10-18 said "keep", before the kernel's handshake existed. Under the handshake the kernel itself looks for a record stamped with the persona id and newer than the request, asks once more, and otherwise respawns cold and logs it; the daily memento verify is a kernel job.

- **Delete both (recommended).** Two Delete rows. *For:* nothing calls them after the Delete; the kernel's own check stands where theirs stood. *Against:* reverses the inventory's "keep"; the placement audit (a diagnostic nobody runs on a schedule) is lost.
- **Keep both and move what they take into them.** `verify_seat_memento` (101 lines, plus whatever it calls inside `reap_memento.py`, not traced) and the constants. *For:* the inventory's word stands. *Against:* about 900 lines kept for no caller.
- **Keep the audit only, as an operator's script.** *For:* the diagnostic survives. *Against:* it needs `memento_slot.py` too, so this is the second option under another name.

### 3. The job-health reader takes a seven-line timestamp parser from the memento reaper

`cosa/rest/job_health.py:18` imports `_parse_iso_aware` from `reap_memento.py` and calls it six times. It returns an aware datetime and refuses a stamp with no zone. Lupin already has `cosa/utils/iso_timestamp.py:parse_iso`, which reads a zone-less stamp as UTC instead, and whose header says "Code that must refuse a zone-less stamp keeps its own stricter reader."

- **Add the strict reader to `cosa/utils/iso_timestamp.py` and re-point `job_health.py` (recommended).** *For:* both readers in one module, the difference stated side by side; no private name crosses a module. *Against:* one more public function for one caller.
- **`job_health.py` carries its own copy.** *For:* what the utility's header already prescribes. *Against:* the next file that wants it copies it again.
- **Use the existing lenient `parse_iso`.** *For:* nothing new. *Against:* a zone-less stamp, refused today, would be read as UTC; a behaviour change.

### 4. The direct-message door resolves a recipient's name with a matcher the list deletes

The list deletes `commons_persona_matcher.py` with the broadcasts, on the ground that the broadcast door "keeps a resolver of its own". But the matcher's surviving caller is the other door: `_resolve_dm_recipient` in `routers/commons.py` (line 955), which turns a written recipient name into a live persona. `lifespan_steps.py:322` installs the matcher's fallback, a language model that guesses among candidates (`lupin_mcp/commons_llm_disambiguator.py`, imported by nothing else).

- **The direct-message door uses the broadcast door's rule (recommended).** `canonical_persona_key`, then `normalize_for_match` when exactly one live persona matches, otherwise the 422 it already returns with the candidates. The matcher is deleted as listed; the model fallback and its installation leave with it (one more Delete row). *For:* one naming rule at both doors, the one the canonical-name decision ruled; no model call inside a route. *Against:* a misspelt recipient that the model would have guessed now gets the 422 and the roster.
- **Keep the matcher and its fallback.** Strike the Delete row. *For:* direct messages behave as today. *Against:* two rules for one question; a model call on the request path, which the route already has to wrap in a catch-all.
- **Keep the matcher without the model.** *For:* smaller. *Against:* still a second rule, differing from the first only by accident.

### 5. The persona's own re-spin tool is `self_respin` in lupin and `respin_request` in the design

The voice server's `self_respin( memento_path, memento_nonce, delay_seconds, cycle_window_seconds )` schedules a `/clear` typed into the persona's own pane; its whole body is `self_respin_core.py`. The design gives the persona `respin_request()`, a ticket to its approver followed by the kernel's handshake; nothing says what becomes of the old name.

- **`self_respin` is removed at the Delete; `respin_request` is the only verb (recommended).** Until then a kernel persona calling `self_respin` is refused with a line naming `respin_request`. *For:* the old arguments (a path, a nonce, a delay) mean nothing to the handshake; one verb. *Against:* skills and doctrine that say `self_respin` must be swept (the convention kit's work).
- **Keep `self_respin` as a second name for `respin_request`, its arguments ignored.** *For:* old habits keep working. *Against:* a tool whose four parameters do nothing; two names for one act.

### 6. `get_session_info` reports the skeleton-crew switch by reading the deleted module

`cosa_voice_mcp.py:2577` adds `skeleton_crew` to the session info, read fresh on every call, `None` when unreadable; managers read it before staffing.

- **Keep the field, read from the kernel's `GET /fleet/config` (recommended).** *For:* a manager still sees the switch before it asks to spawn; `None` keeps its meaning (unknown, not off). *Against:* one kernel call per `get_session_info`.
- **Drop the field.** The refusal at admission names the switch anyway. *For:* less. *Against:* a manager learns of the switch only by being refused.

### 7. The voice server reads the per-project service login through the hook library

Four call sites of `get_hook_credentials` (`cosa_voice_mcp.py:236, 336, 2680, 2854`), in a module the Delete removes. Two are answered by the record: line 236 derives the project part of the sender id from the login's email, and under the proven-identity decision the sender id is on the kernel's persona row; line 2680 logs in to flip the speakerphone, and that tool answers `noop` from the Move. Two are not: line 336 (`_validate_repo_account`, run once at start) checks that the login exists and works, and line 2854 logs in so that `request_persona` can swap the persona's voice. The credential-exposure decision keeps the login on the host as one of its four credentials.

- **Move the login reader to a kept module; two call sites re-pointed, two removed (recommended).** `get_hook_credentials` and its file reader go to `cosa/utils/service_login.py` at the Move, under the name `get_service_login`. *For:* nothing that works today is ruled away by a file move; the credential rule already accounts for this login. *Against:* a persona's tool server goes on reading a password file; whether `request_persona` should survive at all is left to a row of its own.
- **The voice server stops reading the login.** Both remaining sites are removed; a voice swap, if wanted, becomes a kernel route. *For:* one credential fewer in a persona's reach, the direction the credential-exposure decision points. *Against:* a mid-life voice swap has no design (the kernel allocates a voice at spawn only); a new item before the Delete.
- **Keep `hook_credentials.py` in place as a kept module of the tree.** *For:* no caller changes. *Against:* the tree is deleted as a directory; one kept file inside it moves anyway.

### 8. The check that guards the Delete does not see a rename (found after the walk-through)

Ruling 1 turned `fleet_cap_ini_io.py` from a Delete row into a rename row. The check reads only Delete rows, so the six files that import the editor at its old path vanished from its output (18 survivors became 14, two of them for this reason alone), though nothing in lupin had changed.

- **A renamed Python file counts as removed at its old path (recommended).** *For:* the six stay guarded until lupin re-points them; a later rename cannot open the same gap. *Against:* a change to the check and its self-test.
- **Leave the check and rely on the amendment's text.** *For:* no script change. *Against:* the check reports progress that has not happened.
- **Keep the Delete row in the script and record the rename only in the spec.** *For:* no code change. *Against:* the list and its machine form disagree about one file.
