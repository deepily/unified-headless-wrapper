## Findings

### Tool surface (framework §8)

| Purpose | AGY | Jetski | Claude |
|---|---|---|---|
| shell | `run_command`: `CommandLine`, **`Cwd`**, `WaitMsBeforeAsync` (10000) | `run_command`: `CommandLine`, `WaitMsBeforeAsync` (5000), **no `Cwd`** | `Bash` |
| read | `view_file`: `AbsolutePath` | `read_file`: `Path` | `Read` |
| write | `write_to_file`: `TargetFile`, `CodeContent`, `Overwrite` | `write_file`: `Path`, `Content`, `Overwrite` | `Write` |
| edit | `replace_file_content`: `TargetFile`, `TargetContent`, `ReplacementContent`, … | `edit_file`: `Path`, `Target`, `Replacement` | `Edit` |
| fetch | `read_url_content`: `Url` | **none observed**: the model ran `curl` through `run_command` | `WebFetch` |
| MCP | `call_mcp_tool`: `ServerName`, `ToolName`, `Arguments` | pending (C3) | `mcp__<server>__<tool>` |

Consequences:

1. **The Jetski-family adapter holds one tool table per binary.** Each table maps calls into a common shape: `shell{command, cwd}`, `read{path}`, `write{path, content}`, `edit{path, old, new}`, `fetch{url}`, `mcp{server, tool, arguments}`. Guards only ever see the common shape.
2. **Missing `Cwd` (Jetski).** Guards fall back to the session workspace from the payload's `workspacePaths`.
3. **Web access arrives as `curl` on Jetski.** Any fetch policy must parse shell command lines. No current guard depends on this.
4. **AGY's `toolAction` is absent on Jetski.** `toolSummary` appeared on `run_command` only, so spoken progress cannot assume a summary is present.

### Hook payload (framework §4, §8, §13)

- **Jetski adds seven fields to AGY's:** `agentName`, `callerContext`, `executionId`, `isBattleMode`, `lastUserInput`, `parentConversationId`, `rootConversationId`.
- **Parent and root conversation ids give guards session lineage directly.** A subagent can be told from the top-level session without a bridge file, which answers the open §8 question about subagent governance with no bridge role. Follow-up §1 confirms what the ids look like for a top-level session.
- **`agentName` may be the persona-bootstrap route** if `--agent` selects named agent definitions (follow-up §2).
- **`lastUserInput` puts the user's latest message into every hook log.** Hook logs from the work laptop stay on the work laptop.
- **What the model sees on a deny:** `Encountered error in tool execution: tool call denied by pre-tool hook: <reason>`. That is a longer prefix than AGY's, with the same meaning, and the turn still ends `SUCCESS`.

### Launch (framework §5.4)

- **Jetski launch, as measured:** `jetski --input-format stream-json --output-format stream-json --dangerously-skip-permissions`. Hooks come from `<cwd>/.agents/hooks.json`, as on AGY.
- **Jetski starts a Chrome DevTools MCP server by default** (`--use_ls_chrome_devtools_mcp`, default true). Persona launches should pass `=false` if follow-up §4 shows it's accepted.
- **Jetski has `jetski mcp add|remove|list|enable|disable`**, like AGY. The config path is pending (follow-up §3).
- **`--conversation <unknown id>` is silently replaced**, as on AGY. The §5.4 resume check applies to both binaries.

### Response format and timing (framework §7, D13)

- **8/8 well formed.** Unlike AGY, the sign-off used two spoken lines, so this model is less literal about "two supporting sentences".
- **Layer choice differs by model.**
    - The tool-use prompt got no abstract on Jetski (AGY added one).
    - The document request produced an abstract **and** a document (AGY produced only the document).
- **D13 stands.** The median gap is 0.64 s, and only the document turn gaps meaningfully (8.7 s).
- **First output on a fresh process took 14–17 s, against AGY's 9–10 s.** Network, model and machine all differ, so this isn't attributable yet. It strengthens the case for warm persona processes.
