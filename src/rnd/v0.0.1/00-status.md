## Working rhythm

One chat per T-item, titled after it. Open from this page; close by writing the design into its framework section, flipping its Section 20 row, and adding one line below. **Every item is first written up as a narrative** (ruled 11-06): plain language, decisions named in words rather than by register number, problem statements, then options each with pros, cons and a recommendation, then a decisions-requested table, so a reader coming in cold (Rick's manager included) can follow it; drafted as a Claude doc and saved as markdown under `narratives/` beside `specs/`. Rulings are taken against that narrative, one clickable choice at a time, then the design is written into the framework. **Labels (ruled 11-06):** acceptance tests and gates carry a word prefix that says what they prove (`Kernel-1` to `Kernel-8`, `Convention-1` to `Convention-9`; the archive keeps the old `A`/`B` labels); a register key (`D51`, `T37`, `C18`) is always accompanied by its name on first use in a section, never bare. **Chronicle:** every session closes by appending its narrative to `chronicle.md`, written while the context is still in hand, so the whole design process can be reconstructed and published; the status log stays the terse index. With the laptop connected, every edit is made live in the checkout at `src/rnd/v0.0.1/`; the night's changes are pushed to `origin` before the session ends. Without the laptop, read the pushed branch from GitHub.
