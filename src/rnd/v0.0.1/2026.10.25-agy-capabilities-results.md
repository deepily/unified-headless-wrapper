# AGY capabilities: C11–C14 on AGY 1.4.7 (non-snap), compared with Jetski

**Run:** 2026-10-24 · test VM (`lupin-host-test`) · **AGY 1.4.7**, non-snap · `agy_round.sh`, with C14b and C13 finished in tmux · results in `src/captures/out/*-agy-20261024*` · supersedes the invalid snap run (`2026.10.23-agy-round-results.md`)

**Bottom line:** AGY 1.4.7 now behaves like Jetski almost everywhere that matters to UHW, **including its tool names**, which changed since Part A (AGY 1.3.5). Two differences matter for the design:
- **Project hooks do not fire inside AGY subagents.** A subagent's tool calls bypass the gate, so on AGY the `invoke_subagent` veto is the only control.
- **`agy agents` lists only global agent definitions,** though project definitions still work with `--agent`.

## Consequences

1. **One tool table can serve both binaries at current versions,** but key it by name, not by binary. Accept the AGY 1.3 names as aliases, because both binaries update themselves and older installs exist (the dev server ran 1.3.5).
2. **Instructions on AGY go through `AGENTS.md`,** as on Jetski (Phase 1 spec §8: `instructions_via: agents_md` for both).
3. **Subagent governance differs by engine.** On Jetski, the gate sees subagents' tool calls, with lineage. On AGY it sees only the `invoke_subagent` call itself. For roles allowed subagents (the chief of staff), work done inside an AGY subagent is ungoverned by the gate. The decision: accept that, or deny `invoke_subagent` on AGY for every role.
4. **Global locations UHW should use for both binaries:**
   - skills: `~/.gemini/config/skills/`
   - always-on rules: `~/.gemini/config/rules/`
   - mandates: `~/.gemini/AGENTS.md`

   AGY's extra `antigravity-cli/skills/` isn't needed.
5. **The 180 s MCP limit is family-wide:** ticketed asks are required for AGY too.
6. **`agentName` is unusable on AGY.** Persona identity stays with `LUPIN_PERSONA_ID` (C3), never the payload.
