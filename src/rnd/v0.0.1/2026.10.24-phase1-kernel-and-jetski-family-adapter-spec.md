# Phase 1 spec: the Lupin kernel skeleton and the Jetski-family adapter

**As of:** 2026-10-24 · builds on the framework (D1–D34), the role table, and Phase 0 results for AGY (Part A; C11–C14 on AGY 1.4.7), Jetski (Parts B, C11–C14) and Claude · **Platform:** AGY on the GCP test VM, against the test Lupin instance (D32) · **Implementer:** a Jetski-family session working cold from this document

## 1. Goal

**Talk to one AGY persona by voice, with Lupin and nothing from AH4L in between.** The path, end to end:
1. Your words leave the web client and reach the kernel over Lupin's notifications WebSocket.
2. The kernel writes them to the persona's AGY process as a stream-json turn.
3. Every tool call passes the kernel's gate.
4. The reply is parsed into the response pyramid and posted back as one notification.
5. Everything is in the persona's session log.

An urgent message interrupts a busy persona, and a restarted persona resumes its own conversation.

## 2. Non-goals (later phases)

- **The Claude adapter:** last phase (D19, D32).
- **cosa-voice changes.** That means identity from `LUPIN_PERSONA_ID`, ticketed asks and rerouting spawns to the kernel. Personas in Phase 1 have no cosa-voice MCP server, so the model can't call Lupin tools yet; the kernel itself speaks for them.
- **Roles beyond one gate rule;** fleet health; the commands-to-skills conversion; the console client; CLI breadth; OS isolation (D25).

## 4. Types (framework §4, renamed from the prototype's `Ev`)

```python
@dataclass
class EngineEvent:
    kind: str                     # init | text | tool | tool_done | usage | result
    text: str = ""                # delta, tool name, or final response
    conversation_id: str | None = None
    status: str | None = None     # result only: success | error | interrupted
    raw: dict = field( default_factory=dict )

@dataclass
class InboundMessage:
    persona_id: str
    text: str
    urgent: bool                  # "!" prefix or priority urgent
    source: str                   # voice | console | web | cli
    received_at: float

class SessionState( str, Enum ):
    idle = "idle"; busy = "busy"; awaiting_human = "awaiting_human"
    interrupting = "interrupting"; respawning = "respawning"; closed = "closed"
```

## 5. Engine adapter (`engines/jetski_family.py`)

Measured launch shape (framework §5.4, Part A, C11–C14):

```python
def argv( binary, model, conversation_id=None, mode=None, agent=None ):
    command = [ binary, "--input-format", "stream-json", "--output-format", "stream-json",
                "--dangerously-skip-permissions", "--model", model ]
    if binary == "agy":    command += [ "--print-timeout", "0" ]
    if binary == "jetski": command += [ "--use_ls_chrome_devtools_mcp=false" ]
    if conversation_id:    command += [ "--conversation", conversation_id ]
    if mode:               command += [ "--mode", mode ]
    if agent:              command += [ "--agent", agent ]
    return command

def user_frame( text ):  return { "event": "user", "message": { "role": "user", "content": text } }
```

**Rules:**
1. **Refuse a snap binary** (D34): if `shutil.which( binary )` starts with `/snap/`, refuse to spawn.
2. **Record the binary's `--version` and the model** in the registry row and the session log at every spawn. Both binaries update themselves.
3. **Interrupt is SIGINT to the process group,** and the process exits after its result frame. The session respawns with `--conversation <id>`.
4. **One tool table maps tool *names* onto the common shape,** for both binaries. AGY 1.4.7 uses Jetski's names (C11–C14 on AGY, 2026-10-24). AGY 1.3's names are kept as aliases, because both binaries update themselves and older installs exist. The common shape is `shell{command, cwd}`, `read{path}`, `write{path, content}`, `edit{path, old, new}`, `fetch{url}`, `mcp{server, tool, arguments}`, `subagent{prompt, role, type, model, workspace}`.

| Common | Name (AGY 1.4, Jetski) | Alias (AGY 1.3) | Argument keys |
|---|---|---|---|
| shell | `run_command` | | `CommandLine`, `Cwd` (absent on Jetski: use the workspace) |
| read | `read_file` | `view_file` | `Path` · `AbsolutePath` |
| write | `write_file` | `write_to_file` | `Path`, `Content` · `TargetFile`, `CodeContent` |
| edit | `edit_file` | `replace_file_content` | `Path`, `Target`, `Replacement` · `TargetFile`, `TargetContent`, `ReplacementContent` |
| fetch | `search_web` (search only) | `read_url_content` (`Url`) | Jetski has no fetch tool; the model uses `curl` through shell |
| mcp | `call_mcp_tool` | | `ServerName`, `ToolName`, `Arguments` |
| subagent | `invoke_subagent` | | `Prompt`, `Role`, `TypeName`; AGY adds `Model`, `Workspace` |

   A tool not in the table maps to `other{name, args}`, so the gate still sees it.

## 6. Session (`session.py`)

One `asyncio` task per persona owns its process.

| Event | In state | Action |
|---|---|---|
| inbound message | idle | write a turn and go to busy |
| inbound message, not urgent | busy | queue it; consecutive queued messages merge into one turn, separated by blank lines |
| inbound message, urgent | busy | SIGINT, go to interrupting, put the message at the front of the queue |
| result frame | busy | log it, build the pyramid (§9), post one notification, go to idle, then start the next queued turn |
| process exit | interrupting | go to respawning: spawn with `--conversation` and verify `init.conversation_id` (rule below), then busy with the queued turn |
| process exit | any other | log it, alert (§9, priority `high`, type `alert`), go to closed |
| `persona stop` | any | close stdin, then SIGTERM after 10 s, then SIGKILL after 5 more; go to closed |

**Resume rule (C4, both binaries):** if `init.conversation_id` differs from the requested id, the engine started a fresh conversation silently.
- Post an alert naming the persona.
- Keep the new id **only** if the manifest says `on_resume_mismatch: continue`.
- Otherwise kill the process and go to closed.
- Never continue quietly.

**Frames:** stdout is newline-delimited JSON with lines up to 16 MiB (`LINE_LIMIT` in the prototype). Every frame goes to the session log with a monotonic timestamp. stderr goes to `<log dir>/<persona>.stderr`.

## 7. Registry (`registry.py`)

A JSON file per kernel (`~/.lupin/kernel/registry.json`), written atomically through a temp file and rename. The kernel is the only writer.

```python
@dataclass
class PersonaRow:
    persona_id: str               # stable; also the notifications job_id and the session log name
    role: str                     # chief_of_staff | manager | steward | author | implementer | reviewer | tester
    engine: str                   # agy | jetski
    engine_version: str
    model: str
    workspace: str                # absolute path
    conversation_id: str | None
    state: str                    # SessionState
    process_id: int | None
    manager_id: str | None        # lineage (D27): None only for the chief of staff
    created_at: float
    updated_at: float
```

## 8. Manifest and rendering (`manifest.py`)

```yaml
# ~/.lupin/personas/<persona_id>.yaml
persona_id: cos-a1b2c3d4
role: chief_of_staff
engine: agy
model: gemini-3.8-flash-high
mode: auto                       # passed as --mode unless "auto"
workspace: /mnt/lupin-data/work/cos-a1b2c3d4
instructions: |                  # the persona's standing instructions
  You are the chief of staff ...
rules: default                   # §10
on_resume_mismatch: stop
```

Rendering into the workspace, done at spawn, idempotently:
1. **`.agents/hooks.json`:** the shim as PreToolUse, in the named-set format measured in Part A:
   `{ "uhw-kernel": { "PreToolUse": [ { "matcher": "*", "hooks": [ { "type": "command", "command": "<python> -m uhw.shim.jetski_family_hook", "timeout": 10 } ] } ] } }`
2. **Instructions,** by the engine's capability flag `instructions_via`:
   - `agents_md` writes `AGENTS.md` (measured on Jetski, C11).
   - `first_message` prefixes the first turn of a fresh conversation.

   **Both AGY 1.4.7 and Jetski load `AGENTS.md`** (C11 on each), so the default is `agents_md` for both; `first_message` remains as the fallback flag.
3. **Spawn environment:** `LUPIN_PERSONA_ID`, `LUPIN_KERNEL_SOCKET`, `LUPIN_API_URL`. No API key in the persona's environment; the kernel holds it.

## 9. Notifications (`notifications.py`, `pyramid.py`)

**Outbound:**
- At each result, `parse_pyramid( response )` splits the reply into spoken lines, abstract and document.
- The kernel posts one notification (D13): `POST {LUPIN_API_URL}/api/notify` with `message` = spoken lines joined, `abstract` = abstract plus document, `job_id` = persona id, `priority` = `high`, `notification_type` = `task`, and `X-API-Key` from the kernel's environment.
- Every persona's reply is narrated this way. Whether it's spoken is the client's decision (D28).
- `needs_repair` is logged in Phase 1. Lupin's rewriter owns length.

**Inbound:**
- **One WebSocket per persona, all held by the kernel** in one asyncio process: `{LUPIN_API_URL as ws}/ws/queue/cc-listener-{persona_id}`. This replaces AH4L's per-session listener processes one for one. The name matters. Lupin routes persona-targeted notifications through `websocket_manager.emit_to_user_or_listener_sync`, which emits to a session named exactly `cc-listener-{job_id}`, in addition to the user-level emit. One `uhw-kernel-…` socket per host would receive persona-targeted messages only by accident, through the user-level emit. Checked against the lupin source 2026-10-26.
- **Later, optional:** one socket per kernel. That needs a small server change: the auth message registers a list of `job_id`s, and the router emits to the kernel's session for any of them.
- The first message is the auth message, carrying `type`, `token` and `subscribed_events`. **Mirror exactly what AH4L's per-session listener sends** (`grep -rn subscribed_events src/lupin_cli` in the lupin repo), and route each event to a persona by the same target field the listener uses.
- **Reconnect** with exponential backoff (1 s up to 30 s). The server replays missed notifications on reconnect (`websocket.py`, "resume replay"). Drop duplicates by notification id.

**Agent access to Lupin (later phases, recorded here so §9 isn't misread):** the kernel is on the control path, not the data path. Agents reach Lupin's REST endpoints through their own cosa-voice MCP server, as AH4L sessions do today. The kernel does not proxy REST. It does three things instead:
- **Starts and configures each persona's cosa-voice process.** `LUPIN_PERSONA_ID` goes in the MCP server's env, and the role decides which tools it registers (exposure).
- **Gates every MCP call through the hook shim (②), arguments included,** before the MCP server sees it.
- **Holds the inbound sockets above.**

Lupin endpoints stay unchanged, apart from the ticket store from the ticketed-asks spec. "No API key in the persona's environment" means the engine process, the one the model can drive with shell tools. The cosa-voice MCP process keeps loading the outbound X-API-Key from `src/conf/keys/` as it does today (`lupin_mcp/outbound_api_key.py`).

## 10. Gate (`gate.py`, `shim/jetski_family_hook.py`)

**The shim:**
1. Read the hook payload from stdin.
2. Map `toolCall` to the common shape with the binary's table. Tell the binaries apart by payload keys (Jetski adds `agentName`, `executionId` and others; Part B).
3. `POST /gate` over `LUPIN_KERNEL_SOCKET` with `{persona_id, parent_conversation_id, call}`.
4. Print `{ "allow_tool": true }` or `{ "allow_tool": false, "deny_reason": "<rule>: <reason>" }`, and **always exit 0** (Part A: a non-zero exit is a hook failure, not a denial).
5. **If the kernel is unreachable, allow and log to stderr.** That's fail-open for Phase 1, recorded in the session log as `gate_unreachable`.

**Phase 1 rules** (D25 modes):

| Rule | Matches | Mode |
|---|---|---|
| No in-process subagents for staffed roles | `subagent{…}` for any role but `chief_of_staff`; **on AGY, for every role** (D39) | **enforce** (C12: veto by name works; no fallback observed) |

**On AGY, project hooks don't fire inside subagents** (C12 on AGY, 2026-10-24), so the gate never sees an AGY subagent's own tool calls. On Jetski it does. The rule above blocks the subagent call itself on both. On AGY it applies to every role, chief of staff included (D39), so nothing runs outside the gate.
| Role exposure (placeholder) | nothing yet: no cosa-voice in Phase 1 | observe |

Every would-deny and every deny writes `{rule, persona_id, role, tool, arguments_digest, mode}` to the session log.

## 11. Kernel API (`api.py`, FastAPI on `LUPIN_KERNEL_SOCKET`, default `~/.lupin/kernel/kernel.sock`, mode 0600)

| Method and path | Body | Returns |
|---|---|---|
| `POST /gate` | `{persona_id, parent_conversation_id, call}` | `{allow, reason, rule, mode}` |
| `POST /personas` | manifest path | the registry row (spawned, idle) |
| `POST /personas/{id}/messages` | `{text, urgent}` | `{queued_position}` |
| `GET /personas` | | registry rows |
| `DELETE /personas/{id}` | | the final row |
| `GET /health` | | `{websocket: connected or retrying, personas: n, version}` |

The CLI is a thin client: `lupin persona send cos-a1b2c3d4 "Say hello"` calls `POST /personas/{id}/messages`.
