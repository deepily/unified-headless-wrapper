## Format probe v2 (rules: one sentence per line, at most 20 words, one line when it answers)

| | Claude Code (opus) | AGY (gemini-3.8-flash-high) |
|---|---|---|
| Well formed (line count) | 24/24 | 24/24 |
| One-line replies (hello, capital, thanks) | 8 of 9 (one hello took 2) | 9 of 9 |
| Spoken words, explanatory prompts (hash map, files, sleep) | 40–69 | 28–55 |
| Lines over 20 words | common on explanatory prompts | occasional |
| Two sentences on one line | once ("Hello! What can I help…") | never |
| First token (fresh process, median) | about 1.6 s | about 7 s |
| Gap spoken-close → result (median) | 0.95 s | 0.96 s |
| Document turn gap | 10–11 s | 5–7 s |

Readings:
1. **v2 cured v1's padding on both engines.** Under v1, AGY used three lines even for "Say hello". It now uses one.
2. **The 20-word ceiling is ignored on explanatory prompts,** most by Claude. The probe still scores those replies "well formed", because `needs_repair` only counts lines. The next revision should flag a line over about 25 words for the local rewrite, which is exactly the repair path the pyramid design has (`needs_repair` → silent 14B rewrite).
3. **D13 stands.** The median gap is about 1 s on both engines. Document turns gap 5–11 s, and the spoken lines are already complete by then. If that wait ever matters, the fix is to speak at spoken-close rather than at the result, and the probe now measures both points.
4. **Claude Code reaches first token in a fresh process about 4× sooner than AGY** on this server.
