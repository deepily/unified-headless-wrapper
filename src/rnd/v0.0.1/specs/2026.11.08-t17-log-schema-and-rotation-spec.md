## 3. The envelope

```json
{ "timestamp": "2026-11-08T18:04:55.123456Z",
  "monotonic": 10482.771,
  "sequence": 12345,
  "persona_id": "a1b2c3d4",
  "turn_id": 41,
  "kind": "gate.deny",
  "data": { "rule": "no_subagents", "tool": "invoke_subagent", "call_id": "…", "args_sha256": "…", "mode": "enforce" } }
```

| Field | Type | Rule |
|---|---|---|
| `timestamp` | string | UTC, RFC 3339, microseconds, `Z`. For humans and for joining against Lupin's rows. |
| `monotonic` | number | `time.monotonic()` of the kernel process. Orders records and measures durations within one kernel run; meaningless across runs (read beside `sequence`). |
| `sequence` | integer | Per log, starts at 1, strictly increasing, never reused. Survives segment rolls and kernel restarts: at start the writer reads the last line of the newest segment and continues. |
| `persona_id` | string or null | Eight hex (D46, persona id). `null` in the kernel log. |
| `turn_id` | integer or null | The persona's turn counter (D52, inbox envelope and ledger): 1-based, incremented at every envelope written to stdin, persisted in the registry row as `turn_count`, recovered from the log if the row is behind. `null` outside a turn. |
| `kind` | string | `owner.event` or `owner.noun.event`, lowercase ASCII and underscores, where `owner` is the kernel module that wrote it (Section 4). A kind not in the catalogue fails the unit test; adding one means adding a row there. |
| `data` | object | Everything the kind carries. The envelope never gains a field from a payload. |

One JSON object per line, UTF-8, `\n` terminated, no pretty printing, keys in the order above. The first line of every segment is `log.segment` (Section 6.1).

## 5. The writer (`session_log.py`)

### 5.1 Interface

```python
class SessionLog:
    """One writer per log directory. The only code path that creates, appends to or ends a segment."""

    def __init__( self, directory: Path, persona_id: str | None, settings: LogSettings, clock=time ): ...

    async def start( self ) -> None:
        """Recover `sequence` from the newest segment's last line; open a new segment with reason `start`."""

    def append( self, kind: str, data: dict, turn_id: int | None = None, durable: bool = False ) -> asyncio.Future:
        """Queue one record. The future resolves after flush, or after fsync when durable."""

    async def close( self ) -> None:
        """Drain the queue, sync, close the file."""
```

One asyncio task per `SessionLog` drains the queue in order: build the envelope, `redact()` the serialized line (T32 spec Section 4.5), apply the size cap (5.3), check the roll triggers (6.1), write, flush, sync if any record in the drained batch was durable, resolve the futures. Callers never touch the file. The redaction and the cap operate on the serialized line, so a secret split across two `data` fields is not a bypass.

### 5.2 Durability

`flush()` after every record. `os.fsync()` after a batch that holds a durable record; durable kinds are marked in Section 4 (`log.segment`, `log.swept`, every `session.*`, `inbox.written`, `gate.deny`, `gate.ask`). The session awaits `append( "inbox.written", …, durable=True )` **before** posting the receipt, which completes the inbox ruling's order: stdin write → ledger append → log sync → receipt.

### 5.3 The size cap

`log frame max kilobytes` (default 1,024) bounds the serialized `data` of `engine.stdin`, `engine.frame` and `engine.stderr`. Over the cap, the writer replaces the largest string field in `data` with its first and last quarter joined by `\n…[truncated]…\n` and adds `data.truncated = { original_bytes, sha256, field }`. Kernel records are not capped; one that exceeds the cap is a bug and fails the unit test.

### 5.4 Stderr

`session.py` reads the engine's stderr pipe with the same line limit as stdout and calls `append( "engine.stderr", { "line": … } )` per line. More than `log stderr lines per minute` (default 600) in one minute: the excess is dropped and one `log.truncated { stream: stderr, dropped }` is written at the end of the minute. The raw file is deleted from Phase 1 spec Section 6.

## 6. Segments and the sweep

### 6.1 Rolling

Directory: `~/.lupin/kernel/personas/{persona_id}/log/` (persona), `~/.lupin/kernel/log/` (kernel). File: `{yyyy.mm.dd-HHMMSS}.jsonl`, UTC, so lexical order is chronological. The writer rolls when any of three triggers fires, before writing the record that fired it: the open segment has reached `log segment max megabytes` (default 64); the writer starts (`reason: start`); the record's UTC date differs from the open segment's (`reason: day`). The new segment's first line is `log.segment`; its `previous_segment` makes the chain walkable backwards without a directory listing.

### 6.2 Retention

`log/sweep.py`, run from the kernel on an hourly timer and by `lupin kernel sweep [--apply]` (dry run by default, as Lupin's scripts are). Per log directory, oldest first:

1. A segment older than `log retain minutes` (default 20,160) is deleted unless it is one of the two newest (`reason: age`). Age is `now − mtime` in whole minutes, never days.
2. While the directory's total exceeds `log persona max megabytes` (default 1,024), the oldest segment beyond the two newest is deleted (`reason: cap`).
3. A persona directory whose registry row is `closed` and whose newest segment is older than `log retain minutes` is deleted whole, `inbox.json` and `manifest.yaml` included (`reason: closed`). The registry row stays; a later spawn from the same manifest resumes the stored conversation with a cold first turn (the bootstrap ruling's `memento.none` path).

Every deletion is one `log.swept` record in the kernel log. The sweep deletes nothing it did not list first.

### 6.3 The ledger rebuild, restated

Inbox spec Section 4's rebuild reads retained segments newest-first: the answers cursor and the DM cursor are the newest `inbox.received` of each kind; `acknowledged` is the `inbox.written` ids found, stopping at 500 or at the oldest retained line; `inbox.rebuilt { from_log_lines, ids_found }`. Fewer than 500 ids is a complete rebuild: a message older than the recovered cursor is never pulled again. The inbox spec's Section 9 row "rotation must keep at least the last 500 `inbox.written`" is withdrawn in favour of this paragraph.

## 7. The held-turn watch

Replaces `turn_age_watchdog.py`'s two signals with the session's own state. In `session.py`, on a one-second tick while `state == busy`:

```python
def held_turn( self, now: float ) -> HeldTurn | None:
    """
    Requires: self.open_call is the newest `engine.frame[tool]` without its `tool_done`, or None;
              self.last_frame_at is the monotonic time of the newest frame of any kind.
    Ensures:  returns the held call when state is busy, the call is older than the threshold,
              no frame has arrived since it, and the call id has not been advised; else None.
              Never fires in awaiting_human (a ticket is a wait, not a hang).
    """
    if self.state != SessionState.busy or self.open_call is None: return None
    if self.last_frame_at > self.open_call.at: return None
    if now - self.open_call.at < self.settings.held_turn_seconds: return None
    if self.open_call.call_id in self.advised: return None
    return HeldTurn( call_id=self.open_call.call_id, tool=self.open_call.tool, age_seconds=now - self.open_call.at )
```

On a match: `advised.add( call_id )`; `append( "watch.held_turn", { call_id, tool, age_seconds, action } )`; one advisory posted up the escalation chain (D27) with `priority: high`, `type: alert`, the rail a process exit uses; if the manifest's `watch.held_turn_action` is `interrupt`, the existing interrupt path runs (`session.interrupt { cause: held_turn, open_call_id }`) and the next envelope opens with the kernel block naming the cut call, as the inbox ruling specified. `advised` is cleared of a call id when its `tool_done` arrives, so a call that completes and a new one that hangs each advise once. Manifest:

```yaml
watch:
  held_turn_action: advise      # advise | interrupt; default advise
```

The fleet-health module (the former arbiter, D24) reads `watch.*` and `engine.frame[usage]` records and the registry; it holds no detector and polls no process. `turn_age_watchdog.py` and `context_pressure_writer.py` are deletion-list rows (T19).
