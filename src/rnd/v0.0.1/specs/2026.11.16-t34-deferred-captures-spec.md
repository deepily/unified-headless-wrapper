## 2. The data directory for each persona (ruling 1)

The October line asked for a separate `--app_data_dir` per persona with the sign-in token linked in, to isolate settings, conversations and the token. None of the three is wanted now:

|---|---|---|

| Settings | the hook file, the agent definition and the instruction files are written into the persona's worktree | framework Sections 5.1, 5.4 and 10.3 (D43, D47) |
| Conversations | resumed by an identifier the kernel holds and verifies at every start | Phase 1 spec, Section 6, the resume rule |

Identity, the "C3 partial case" the framework cited beside this line, passed on 2026-10-18 through each engine's inherited environment (D46, stable identity).

**The flag, recorded so that it is not rediscovered** (AGY 1.5.9, test VM, 2026-11-16):
- `--app_data_dir` is not among the 26 flags `agy --help` lists; the name occurs 12 times in the binary, once as `--app_data_dir=` beside `--cli_dir_name=`.
- It takes a name relative to `~/.gemini/`. Given an absolute path the engine answers `Failed to start: must not be absolute: …`, **after** it has created the path, with a `log/` directory, under `~/.gemini/`. The default is `~/.gemini/antigravity-cli/`, which also holds the sign-in file `antigravity-oauth-token`.
- Nothing in the kernel passes the flag. A manifest or adapter that tried to would be passing an undocumented flag the vendor may remove.

Not measured, and not owed: a resume inside a second directory. If several engines sharing the one directory ever interfere, the first acceptance test that runs two personas together reports it.

## 3. The stop time during a tool call (ruling 2)

The record holds one observation: about 0 seconds when the model was writing text, about 6 seconds when a shell command was open (the October design document's checklist). The vendor's release notes add that an interrupted turn's last frame carries `finished_reason: interrupted` (1.4.11) and that a headless run "finishes shutting down within 30 seconds" after its result (1.5.5); neither states the time from the signal to the exit during a tool call.

Kernel-5 gains a second leg, **Interrupt-3**: with a shell command open that sleeps for 120 seconds, an urgent message arrives; the test passes when the urgent message is answered on the same conversation and one `session.interrupt_exit` record exists with `forced: false`. Its `seconds` is the measurement. It is taken on the kernel's own launch line, on each engine the phase runs on, and again at every rerun, so the figure follows the engine's versions without a separate capture.

## 4. An interrupted engine that does not exit (ruling 3)

The Phase 1 state table had a row for "the process exits while `interrupting`" and none for an engine that does not exit: the persona stayed `interrupting` and the urgent message at the head of its queue was never delivered. The held-turn watch (D56, log schema) runs only while `busy`, and the ordered stop (D65, kernel lifecycle) has limits of its own.

The rule, for the Jetski family and for any adapter whose `interrupt_mode` is `signal`:

1. The interrupt signal goes to the engine's process group, as before; the session task notes the monotonic time.
2. While `interrupting`, each tick: the process has exited → `respawning`, as before. Otherwise, at `kernel interrupt exit seconds` (30) past the signal, the process group is sent `SIGKILL`, and the exit that follows goes to `respawning` in the same way.
3. Either way one record, `session.interrupt_exit { seconds, forced, open_call_id }`, is written when the process is gone.
4. The respawn applies the resume rule unchanged: a conversation the kill damaged shows as `session.resume_mismatch` and is handled by the manifest's `on_resume_mismatch`.
5. A forced exit is the kernel's own act and never moves the crash-loop count (D65).

Why 30: it is the limit the vendor states for a headless run to finish shutting down, so an engine killed at 30 seconds has had the time its vendor says it may take; the one observation (6 seconds) is well inside it. The worst case is an urgent message that waits 30 seconds for a hung engine, against one that is never delivered.

On an adapter whose `interrupt_mode` is `control` (Claude), the process survives an interrupt and this rule does not run; a control interrupt that brings no result frame is the held-turn watch's case.

## 6. The protocol interrupt on the Jetski family (ruling 5)

Claude takes an interrupt as a message (`control_request`) and its process survives (C6). The Jetski family takes a signal, exits and is started again. On AGY 1.5.9, at zero tokens, with no turn in flight:

| One line on standard input | The engine's answer |
|---|---|
| `{"event":"control_request","request_id":…,"request":{"subtype":"interrupt"}}` | result `ERROR`, `stream input message event "control_request" is not supported yet`, zero turns, zero tokens, exit 2 |
| `{"event":"interrupt"}` (a name the engine does not know) | no result; standard error `warning: ignoring unsupported stream input message event "interrupt"`; exit 0 |
| the same message with `type` in place of `event` | result `ERROR`, `stream input message is missing the "event" field`; exit 1 |

So the vendor still reserves the name and still refuses it. The release notes do not mention it in any version (0 of 1,248 lines), so they are not the source to watch.

**The probe.** The vetting run of D48 (once per unseen version of a binary, under the per-binary lock) gains one launch that makes no model call: the adapter's stream-mode launch line in the throwaway workspace, the one `control_request` line on standard input, a 40-second limit. The answer is classified `refused` ("not supported yet"), `ignored` (an unknown or malformed message), `accepted` (a result with no error, or nothing owed in reply) or `unreadable` (anything else), stored on the version's entry in `vetted-engines.json` as `protocol_interrupt`, and logged as `vetting.capability { binary, version, capability: "protocol_interrupt", answer, previous }` in the kernel's log.

- The probe **never fails a vetting run**; a version is admitted or refused on the tool table and the model name, as before.
- **One notice** (a card to the operator, `type: info`, `priority: low`) when the answer differs from the last vetted version's of the same binary; a first reading is a notice only when it is not `refused`.
- **The adapter does not change.** `interrupt_mode` stays a constant of the adapter. Changing the Jetski family's route to the message is a register item of its own, opened by the notice, with a capture of what the engine then does (does the process survive, what does the result frame say).

The capture driver `drive.py` sends this message with a `type` field, which AGY 1.5.9 refuses one step earlier; row 52 of "Outstanding actions".

The key lives in lupin's `lupin-app.ini` with its line in `lupin-app-splainer.ini`, as every kernel key does (D62, turn-end policy). A value outside 5 to 180 is a startup refusal: under 5 a healthy exit is killed, and 180 is the ordered stop's drain.

## 9. Reference implementation (runs; eighteen tests pass on 2026-11-16, Python 3, no dependencies)

`interrupt_exit.py`:

```python
"""D73 reference: the bound on an interrupted engine's exit, and the protocol-interrupt probe.

Dependency-free. Two rules:
  1. After the interrupt signal, an engine has `kernel interrupt exit seconds` (30) to exit. Past that the
     kernel kills its process group and starts it again on the same conversation. Either way one
     `session.interrupt_exit` record carries the seconds from signal to exit.
  2. The check on each new engine version sends one protocol-interrupt message with no turn in flight and
     classifies the answer. A change of answer is one notice. The adapter's interrupt route never changes
     because of it.
"""

INTERRUPT_EXIT_SECONDS = 30                     # kernel interrupt exit seconds
LIMIT_FLOOR, LIMIT_CEILING = 5, 180             # refused outside: under 5 kills a healthy exit, 180 is the stop's drain

WAIT, RESPAWN, KILL_THEN_RESPAWN = "wait", "respawn", "kill_then_respawn"
REFUSED, IGNORED, ACCEPTED, UNREADABLE = "refused", "ignored", "accepted", "unreadable"


def validate_limit( value ):
    """The configured limit as an integer, or ValueError naming the key."""
    try:
        seconds = int( str( value ).strip() )
    except ValueError:
        raise ValueError( f"kernel interrupt exit seconds: not an integer: {value!r}" )
    if not LIMIT_FLOOR <= seconds <= LIMIT_CEILING:
        raise ValueError( f"kernel interrupt exit seconds: {seconds} is outside {LIMIT_FLOOR} to {LIMIT_CEILING}" )
    return seconds


def interrupting_step( seconds_since_signal, exited, limit = INTERRUPT_EXIT_SECONDS ):
    """What the session task does on each tick while a persona is `interrupting`."""
    if exited:
        return RESPAWN
    if seconds_since_signal >= limit:
        return KILL_THEN_RESPAWN
    return WAIT


def interrupt_exit_record( signal_at, exit_at, forced, open_call_id = None ):
    """The data of `session.interrupt_exit`. Clocks are monotonic seconds."""
    if exit_at < signal_at:
        raise ValueError( "exit before signal" )
    return { "seconds": round( exit_at - signal_at, 2 ), "forced": bool( forced ), "open_call_id": open_call_id }


def counts_as_crash( forced ):
    """A forced exit after an interrupt is the kernel's own act: it never moves the crash-loop count."""
    return False


def classify_protocol_interrupt( result_error = None, has_result = False, stderr = "" ):
    """The engine's answer to one protocol-interrupt message sent with no turn in flight."""
    error  = ( result_error or "" ).lower()
    stderr = ( stderr or "" ).lower()
    if "not supported yet" in error or "not supported yet" in stderr:
        return REFUSED
    if "ignoring unsupported" in stderr or "missing the" in error:
        return IGNORED
    if has_result and not error:
        return ACCEPTED
    if not has_result and not stderr.strip():
        return ACCEPTED                         # the message was taken and nothing was owed in reply
    return UNREADABLE


def vetting_passes( answer ):
    """The probe informs; it never refuses a version."""
    return True


def capability_notice( binary, version, previous, current ):
    """One line for the operator when the answer differs from the last vetted version's, else None.
    A first reading (previous None) is a notice only when it is not the refusal the design assumes."""
    if previous == current or ( previous is None and current == REFUSED ):
        return None
    return ( f"{binary} {version} answers the protocol interrupt as '{current}' (was '{previous or 'never read'}'). "
             f"The adapter still interrupts by signal; changing that is a decision, not an automatic switch." )


def interrupt_mode_after_probe( adapter_mode, answer ):
    """The adapter's route is a constant of the adapter; the probe cannot change it."""
    return adapter_mode
```

`test_interrupt_exit.py`:

```python
import unittest
from interrupt_exit import *


class TheBound( unittest.TestCase ):

    def test_default_is_thirty( self ):
        self.assertEqual( INTERRUPT_EXIT_SECONDS, 30 )

    def test_waits_inside_the_limit( self ):
        self.assertEqual( interrupting_step( 6.0, exited=False ), WAIT )
        self.assertEqual( interrupting_step( 29.9, exited=False ), WAIT )

    def test_exit_respawns_whenever_it_comes( self ):
        self.assertEqual( interrupting_step( 0.1, exited=True ), RESPAWN )
        self.assertEqual( interrupting_step( 45.0, exited=True ), RESPAWN )

    def test_kills_at_the_limit( self ):
        self.assertEqual( interrupting_step( 30.0, exited=False ), KILL_THEN_RESPAWN )
        self.assertEqual( interrupting_step( 2.0, exited=False, limit=2 ), KILL_THEN_RESPAWN )

    def test_never_waits_forever( self ):
        self.assertTrue( all( interrupting_step( t, False ) != WAIT for t in ( 30, 31, 600, 86400 ) ) )

    def test_record_carries_seconds_and_whether_forced( self ):
        self.assertEqual( interrupt_exit_record( 100.0, 106.04, False, "call-7" ),
                          { "seconds": 6.04, "forced": False, "open_call_id": "call-7" } )
        self.assertEqual( interrupt_exit_record( 100.0, 130.0, True ),
                          { "seconds": 30.0, "forced": True, "open_call_id": None } )

    def test_record_refuses_a_backward_clock( self ):
        with self.assertRaises( ValueError ):
            interrupt_exit_record( 10.0, 9.0, False )

    def test_forced_exit_is_not_a_crash( self ):
        self.assertFalse( counts_as_crash( True ) )
        self.assertFalse( counts_as_crash( False ) )

    def test_limit_validation( self ):
        self.assertEqual( validate_limit( "30" ), 30 )
        self.assertEqual( validate_limit( " 10 " ), 10 )
        for bad in ( "0", "4", "181", "thirty", "" ):
            with self.assertRaises( ValueError ):
                validate_limit( bad )


class TheProbe( unittest.TestCase ):

    AGY_159 = 'stream input message event "control_request" is not supported yet'

    def test_agy_1_5_9_is_refused( self ):
        self.assertEqual( classify_protocol_interrupt( self.AGY_159, has_result=True ), REFUSED )

    def test_unknown_message_is_ignored( self ):
        self.assertEqual( classify_protocol_interrupt( None, False, 'warning: ignoring unsupported stream input message event "interrupt"' ), IGNORED )
        self.assertEqual( classify_protocol_interrupt( 'stream input message is missing the "event" field', True ), IGNORED )

    def test_a_clean_result_is_accepted( self ):
        self.assertEqual( classify_protocol_interrupt( None, has_result=True ), ACCEPTED )
        self.assertEqual( classify_protocol_interrupt( None, has_result=False, stderr="" ), ACCEPTED )

    def test_anything_else_is_unreadable( self ):
        self.assertEqual( classify_protocol_interrupt( "authentication required", True ), UNREADABLE )
        self.assertEqual( classify_protocol_interrupt( None, False, "panic: nil map" ), UNREADABLE )

    def test_no_notice_while_the_answer_holds( self ):
        self.assertIsNone( capability_notice( "agy", "1.5.9", None, REFUSED ) )
        self.assertIsNone( capability_notice( "agy", "1.6.0", REFUSED, REFUSED ) )

    def test_one_notice_on_a_change( self ):
        notice = capability_notice( "agy", "1.6.0", REFUSED, ACCEPTED )
        self.assertIn( "agy 1.6.0", notice )
        self.assertIn( "'accepted'", notice )
        self.assertIn( "still interrupts by signal", notice )

    def test_first_reading_that_is_not_a_refusal_is_a_notice( self ):
        self.assertIn( "never read", capability_notice( "jetski", "2026.11.1", None, ACCEPTED ) )

    def test_probe_never_refuses_a_version( self ):
        self.assertTrue( all( vetting_passes( a ) for a in ( REFUSED, IGNORED, ACCEPTED, UNREADABLE ) ) )

    def test_probe_never_changes_the_route( self ):
        self.assertEqual( interrupt_mode_after_probe( "signal", ACCEPTED ), "signal" )
        self.assertEqual( interrupt_mode_after_probe( "control", REFUSED ), "control" )


if __name__ == "__main__":
    unittest.main()
```
