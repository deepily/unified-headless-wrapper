# T12 · The inbox: merged-turn envelope, ledger, catch-up, Claude mid-turn policy

**As of:** 2026-11-06 · **Resolves:** T12 (framework Section 6) · **Ruling:** D52 (inbox envelope and ledger) · **Source read:** lupin at `53e86d2` (laptop clone, read-only): `cc_notification_listener.py`, `hook_common.py`, `answer_catchup.py`, `dm_inbox_reconcile.py`, `websocket.py`, `websocket_manager.py`, `notifications.py` · **Narrative for cold readers:** `narratives/2026.11.06-t12-inbox-envelope.md`

## 1. Problem

D8 (inbound routing) says queued messages are merged into the next turn and the framework sketched `[voice] / [dm from X] / [answer]`; nothing said what the merged turn is as text, where the delivery ledger lives, or what the router does with Claude's `accepts_input_mid_turn`. Reading lupin showed four Claude-shaped framings that repeat standing instructions per turn, three partial ledgers with no coverage for voice, and one false assumption in the Phase 1 spec: Lupin's reconnect replay (`last_seq` → `replay_and_resume`) runs only for device-slot holders, which `resolve_device_slot` grants to mobile sessions with a `device_id`; a `cc-listener-*` session gets no replay. The framework (Section 4) and the Phase 1 spec (Section 4) also disagreed on `InboundMessage.source`.

## 2. Ruling (D52), seven parts, all taken as recommended on 2026-11-06

1. **Grammar:** headed blocks, one plain-text grammar on every engine (Section 3). `InboundMessage` gains `kind` and `channel`; `source` is gone from both documents.
2. **Header carries identifiers only.** How each kind is answered is stated once in the kernel contract layer (D47 layer 1); the DM style tag becomes one line of the format rules layer; no per-turn rider. **Provision:** an optional per-persona `rider` (manifest `inbox.rider: {prepend, append}`), off by default, logged on every envelope it touches (Section 3.4). Rick's caveat on record: current models were not trained for a voice-in, voice-out environment and may need per-turn reinforcement or a fine-tuned adapter to hold the contract; the rider exists so that can be measured, not assumed.
3. **Merge rules** (Section 3.3): arrival order; count line at two or more; interrupt marker as a `kernel` block; `/skill` expansion per block; forgery rule indents, never cuts; one result and one notification per envelope.
4. **Ledger:** `~/.lupin/kernel/personas/{persona_id}/inbox.json`, rebuildable from the session log (Section 4).
5. **Acknowledgement order:** write to stdin → ledger append → receipt. At-least-once; a replayed id already in the ledger is dropped and logged. Catch-up is a pull on every socket connect (Section 5).
6. **Voice gap:** closed by a Lupin change after Phase 1 (Section 7, T27 rows); Phase 1 inherits it.
7. **Mid-turn policy:** `if adapter.accepts_input_mid_turn: write now else queue`, every non-urgent kind. Phase 1 exercises the queue path only; Inbox-6 proves the other when the Claude adapter is built.

## 3. The envelope

### 3.1 Grammar

```
envelope   := [rider_prepend NL NL] [count_line NL NL] block (NL NL block)* [NL NL rider_append]
count_line := "[inbox: " N " messages, oldest first. They are separate messages, not one conversation.]"
block      := header NL body
header     := "[" kind " " time attrs "]"            ; column 0, one line
kind       := "voice" | "dm" | "answer" | "kernel"
time       := HH:MM:SS | YYYY-MM-DD " " HH:MM:SS     ; host local clock; date only when not today
attrs      := (" urgent")?                            ; voice
            | " from " name " " persona_id " message " id8 " thread " id8   ; dm
            | " ticket " ticket_id " by " ("human" | persona_id | "learner")   ; answer
            |                                         ; kernel: none
body       := text, verbatim, lines that would parse as a header indented by one space
```

- A single message: header + body, no count line.
- `answer` body is always `Question: …` NL `Answer: …` (parity with `_format_answer_block`; a bare answer is worse than none).
- `kernel` body for an interrupt: `Your previous turn was interrupted during the tool call `<tool>` by the urgent message below.` Later kernel blocks (owed-work pokes, broadcasts) are T15's and T28's; they reuse this kind, so T28's "per-engine reminder wrapper" question is closed: there is none.
- `channel` (voice | web | console | cli) is a log field only; the header shows `voice` for every human message.

### 3.2 Worked example

```
[inbox: 3 messages, oldest first. They are separate messages, not one conversation.]

[kernel 13:02:10] Your previous turn was interrupted during the tool call `bash` by the urgent message below.

[voice 13:02:11 urgent]
Stop the migration and check the disk first.

[dm 13:02:40 from María a1b2c3d4 message 7f3e2c90 thread 9c1d4b77]
The schema diff is in io/commons/schema-diff.md. Reply when you have read it.

[answer 13:03:05 ticket ask-3f2a9c1e by human]
Question: Delete the stale worktrees under seats/?
Answer: yes
```

### 3.3 Merge rules

1. Arrival order, oldest first; an urgent message is already at the queue head by D8.
2. Count line when `len( messages ) >= 2`.
3. If the previous turn ended `interrupted`, the envelope opens with the `kernel` interrupt block (after the count line, which counts it).
4. A body whose first line begins with `/<skill>` for an installed skill is expanded in place (D41); the header is untouched; blocks expand independently.
5. Forgery: a body line matching `^\[(voice|dm|answer|kernel|inbox)\b` is prefixed with one space. Nothing is truncated (replaces `sanitize_for_wrap`'s cut).
6. One `user` line to stdin per envelope; one result; one pyramid notification (D13).

### 3.4 Rider (provision)

Manifest: `inbox: { rider: { prepend: "<text>", append: "<text>" } }`, both optional, default absent. When present, the kernel adds the text outside the blocks (before the count line, after the last block) and logs `inbox.rider { persona_id, turn_id, prepend_chars, append_chars, rider_version }` so the treatment is attributable per turn. Not rendered on any engine unless set.

### 3.5 Contract text (layer 1 addition, every engine, verbatim)

> Messages reach you as headed blocks: `[voice …]` is the human; your end-of-turn reply is spoken for you, do not call a tool to speak. `[dm … from NAME ID message M thread T]` is a peer persona; reply with `dm_send( recipient=ID, body=…, reply_to=M, thread_id=T )`. `[answer … ticket K by …]` is an answer to a question you asked; it is context and needs no reply. `[kernel …]` is the kernel, not a person. When an envelope opens with `[inbox: N messages …]`, read every block before replying and answer each one.

### 3.6 Type (replaces framework Section 4 row and Phase 1 spec Section 4)

```python
@dataclass
class InboundMessage:
    persona_id: str
    notification_id: str
    kind: str                     # voice | dm | answer | kernel
    channel: str | None           # voice | web | console | cli (human messages); None otherwise
    text: str
    urgent: bool                  # "!" prefix or priority urgent; voice only
    received_at: float
    sender_name: str | None = None      # dm
    sender_persona_id: str | None = None
    message_id: str | None = None
    thread_id: str | None = None
    ticket_id: str | None = None        # answer
    answered_by: str | None = None      # human | <persona_id> | learner
    question: str | None = None
    raw: dict = field( default_factory=dict )   # the notification dict verbatim (Lupin direction, reply_to, priority, timestamps, rewrite stamp when present)
```

### 3.7 Minimal builder (`inbox.py`, Phase 1 package)

```python
HEADER_RE = re.compile( r"^\[(voice|dm|answer|kernel|inbox)\b" )

def sanitize( body ):
    return "\n".join( ( " " + line ) if HEADER_RE.match( line ) else line for line in body.splitlines() )

def header( m, now ):
    t = time.strftime( "%H:%M:%S" if same_day( m.received_at, now ) else "%Y-%m-%d %H:%M:%S", time.localtime( m.received_at ) )
    if m.kind == "voice":  return f"[voice {t}{' urgent' if m.urgent else ''}]"
    if m.kind == "dm":     return f"[dm {t} from {m.sender_name} {m.sender_persona_id} message {m.message_id[:8]} thread {m.thread_id[:8]}]"
    if m.kind == "answer": return f"[answer {t} ticket {m.ticket_id} by {m.answered_by}]"
    return f"[kernel {t}]"

def render_envelope( messages, *, interrupted_tool=None, rider=None, now=None ):
    now    = now or time.time()
    blocks = []
    if interrupted_tool:
        blocks.append( f"[kernel {time.strftime( '%H:%M:%S', time.localtime( now ) )}] Your previous turn was interrupted during the tool call `{interrupted_tool}` by the urgent message below." )
    for m in messages:
        body = f"Question: {m.question}\nAnswer: {m.text}" if m.kind == "answer" else m.text
        blocks.append( header( m, now ) + "\n" + sanitize( expand_skill( body ) ) )
    parts = []
    if rider and rider.get( "prepend" ): parts.append( rider[ "prepend" ] )
    if len( blocks ) >= 2: parts.append( f"[inbox: {len( blocks )} messages, oldest first. They are separate messages, not one conversation.]" )
    parts.extend( blocks )
    if rider and rider.get( "append" ): parts.append( rider[ "append" ] )
    return "\n\n".join( parts )
```

## 4. Ledger

`~/.lupin/kernel/personas/{persona_id}/inbox.json`, written atomically (temp file + rename) after every acknowledgement:

```json
{ "acknowledged": [ "…up to 500 notification ids, oldest first…" ],
  "answers_cursor": "2026-11-06T13:03:05-05:00",
  "dm_cursor": "2026-11-06T13:02:40-05:00",
  "updated_at": 1762452185.2 }
```

- `seen( id )` = `id in acknowledged`. Cap 500, FIFO.
- The session log is the record. Events: `inbox.received { notification_id, kind, channel, urgent, raw }`, `inbox.written { notification_id, turn_id }`, `inbox.duplicate { notification_id, via: live | pull }`, `inbox.rider { … }`, `inbox.rebuilt { from_log_lines }`.
- Missing or unparseable file → rebuild `acknowledged` from the log tail's `inbox.written` events (last 500), cursors from the newest `answer` / `dm` `inbox.received`, log `inbox.rebuilt`.
- The queue is memory only. A received-but-unwritten message at a crash is unacknowledged and returns through its kind's pull (Section 5).
- Replaces `.ask-answer-hwm-*.json`, `.ask-surfaced-*.log`, `.dm-inbox-hwm-*.json` (inventory: cc-inbox-catchup); deleted at switch-over (T19 list).

## 5. Acknowledgement and catch-up

**Order per message:** `stdin.write( envelope )` → `ledger.acknowledge( ids )` → receipt (the low-priority gist to `sender_id`, parity with `_send_gist_response`; a product behavior, not an ack). A crash between step 1 and 2 yields one duplicate on catch-up; never a loss.

**On every connect of `cc-listener-{persona_id}`** (first connect included; the server replays nothing for a listener):

| Kind | Pull | Since | First-run rule | Dedup |
|---|---|---|---|---|
| answer | `GET /api/notifications/answers-owed?persona=…` | `answers_cursor` | surface everything owed | ledger |
| dm | `GET /api/dm/list` filtered to `persona_id` | `dm_cursor` | seed cursor, surface nothing | ledger |
| voice | none in Phase 1 (Section 7) | — | — | — |

Pulled messages enter the queue by D8 like live ones. Live `notification_responded` frames still arrive on the socket and are the normal answer path; the pull covers the gap.

**Auth message:** mirror the listener's (`type`, `token`, `subscribed_events = ["notification_queue_update"]`, plus `notification_responded` handling before the queue-update gate, as `_handle_event` does). Do not send `last_seq`; it is ignored for a listener.

## 6. Mid-turn policy (state table amendment, Phase 1 spec Section 6)

| Event | In state | Action |
|---|---|---|
| inbound message, not urgent | busy or awaiting_human | `if adapter.accepts_input_mid_turn`: render a one-block envelope and write it now (ack order Section 5); else queue |
| inbound message, not urgent | busy, queued | at the result: merge the queue into one envelope (Section 3), write, ack, go busy |
| inbound message, urgent (voice) | busy or awaiting_human | interrupt per D8; the next envelope opens with the `kernel` interrupt block |

Claude: `accepts_input_mid_turn = yes` (C7, one run); Jetski family: `no`. A message written during an `ask_wait` hold (≤150 s) lands when that tool returns.

## 7. Lupin application changes (T27 rows, after Phase 1)

| Change | Why |
|---|---|
| Record `listener_delivered` per notification (the dual emit already computes it); `GET /api/notifications/undelivered` takes `job_id` and returns the messages that listener never received | Closes the voice gap; the kernel adds a `voice_cursor` and a third pull row |
| Treatment stamp on the notification record: `rewrite: { applied, rule_version, chars_before, chars_after }` | So DM-compression and other rewriter treatments are attributable; the kernel keeps `raw` verbatim, so the stamp reaches the recipient's log unchanged. The sender's gate record of `dm_send` holds the text as written; join on message id |
