**As of:** 2026-11-06 · **Resolves:** T13 (framework Section 7) · **Ruling:** D53 (voice out) · **Source read:** lupin at `53e86d2` (laptop clone, read-only): `cosa_voice_mcp.py` (spoken cap), `hook_common.py` (riders), `routers/dm.py` and `agents/dm_tutor/` (the only rewriter), `notifications.js` (card rendering), `.docview.yml`, `src/scripts/sweep-io-tmp.sh`, `routers/docs_files.py` (upload door); planning-is-prompting `workflow/brevity-mandate.md`, `workflow/rnd-directory-policy.md`, `workflow/doc-viewer-links.md`; this repo's `src/captures/c9_c10_pyramid_probe.py` · **Narrative for cold readers:** `narratives/2026.11.06-t13-voice-out.md`

## 1. Problem

D12 (response pyramid) left four details open: the format text per engine, document paths and lifetime, the abstract threshold, and who repairs a malformed reply. Reading lupin showed: the probe's version 2 rules were drafted and never run; Lupin's 500-character spoken cap is enforced only in its MCP layer, so the kernel's REST posts bypass it; no rewriter exists on the notify path (the DM tutor is the only one, and it needed ten fabrication guards); a document substrate already exists (`io/tmp/`, swept daily at 7×24 h; `io/write-ups/`, kept; viewer grammar `/app/docs?path=lupin/io/…`); and the framework's Section 7.2 diagram still showed a local model rewriting spoken lines, which D12 as amended on 10-26 had already given to Lupin.

## 2. Ruling (D53), six parts, all taken as recommended on 2026-11-06

1. **One format text on every engine** (Section 3): the version 2 rule in the brevity mandate's vocabulary; markers unchanged; the DM style line spelled out at its end. It is D47 layer 4.
2. **Documents live in Lupin's `io/`** (Section 4): `transient` → `io/tmp/`, `persistent` → `io/write-ups/`, named `yyyy.mm.dd-<persona_id>-<slug>.md`; Lupin's sweep owns deletion; the kernel never deletes; one appended open-link line in the abstract; `lupin.root` in kernel config; remote hosts wait on a T27 row.
3. **Abstract spill** (Section 5): over `voice_out.abstract_spill_chars` (default 2,000) the whole abstract goes to a transient document; the card keeps the head and the link. Routing, not rewriting.
4. **Shape and repair** (Section 6): four shape rules, seven reason codes, mechanical repair only; the 14B rewrite step is deleted from Section 7.2 and the risk table; `--json-schema` remains the fallback.
5. **Spoken cap** (Section 7): the kernel logs length and cuts nothing; the enforcement point for REST senders is a T27 row.
6. **Per-turn record** (Section 8): fifteen fields, one record per result.

## 3. The format rules text (D47 layer 4)

Rendered by the kernel into `--append-system-prompt` (Claude) or the `--agent <role>` definition body (Jetski family), byte-identical. `format_rules_version` is the SHA-256 of this text, first eight hex, logged per turn.

```
Response format. You are speaking to one person through a voice interface. Your final reply has up to three parts, in this order.

1. Spoken lines. One sentence that answers, then at most two more sentences, only if the listener needs them. One sentence per line. Plain words: no markdown, lists, links, code or identifiers. One line is enough when one line answers.

2. Detail, only if there is detail worth showing. A line containing only <<<abstract, then markdown. Tables, lists, paths, links and identifiers go here, never in the spoken lines.

3. A document, only if the person asked for one or the detail is too long for a card. A line containing only <<<document persistent (they asked for it) or <<<document transient (they did not), then the full markdown.

Most replies are spoken lines only. A line is one sentence that makes a claim. Longer only when asked. Text you write between tool calls is never spoken. If a line inside your detail or document would itself begin with <<<, indent it by one space.

Direct messages to other personas: KISS, 3LoL, NoMC C2C, NoAA, WaHH. Verdict first, three lines or less; decisions, evidence, risks and required actions only; longer only when asked.
```

Notes:
- The markers are the measured ones (C9, C13: 24 of 24 on four pinned models per Jetski-family engine with version 1). The rule text is version 2 of the probe (`RULES_V2`), reworded; version 2 is measured by the Phase 1 per-turn record, not by a new capture.
- "No identifiers in speech" is Lupin's own voice rule (`cosa_voice_mcp.py`: ids and hashes belong in `abstract`, never in speech) made standing.
- The last paragraph is the DM style line D52 assigned to this layer, spelled out; `hook_common.DM_STYLE_TAG` is its ancestor. Retire the probe's `UHW_RULES=v1|v2` switch when `pyramid.py` is written; the text of record is this section.

## 4. Documents

### 4.1 Paths and lifetime

| `document_mode` | Path under `lupin.root` | Lifetime | Deleted by |
|---|---|---|---|
| `transient` | `io/tmp/yyyy.mm.dd-<persona_id>-<slug>.md` | more than 7×24 h | Lupin's `sweep-io-tmp.sh` (daily 19:00 cron plus reboot; `-mmin +10080`); unchanged |
| `persistent` | `io/write-ups/yyyy.mm.dd-<persona_id>-<slug>.md` | kept | the operator |

- `<persona_id>` is the eight-hex id (D46). `<slug>` = first spoken line, lower-cased, runs of non-alphanumerics folded to one hyphen, leading and trailing hyphens dropped, cut at 40 characters; empty → `reply`. A name collision appends `-2`, `-3`, …
- The kernel never deletes a document and never writes outside the two folders. Both are already in lupin's `.docview.yml` allow-list and gitignored (`io/**`).
- Write is atomic: temp file in the same folder, then `os.replace`.
- The file content is the document block as the model wrote it, after `redact()` (D50; same function as the log writer and the narration path). When a spill (Section 5) produced the file, the content is the whole abstract, a `---` rule, then the document block if any.

### 4.2 The link

The kernel appends one line to the abstract, after a blank line:

```
[Open: <file name>](/app/docs?path=lupin/io/tmp/<file name>)
```

(`write-ups` for persistent.) Canonical viewer grammar per `workflow/doc-viewer-links.md`; the bare `io/` scope returns 400 since Phase 4a. `notifications.js` intercepts `/app/docs?path=` anchors into the reading pane; the multiplexer client (T27) must keep that behaviour.

### 4.3 Configuration

| Key | Phase 1 value | Meaning |
|---|---|---|
| `lupin.root` | the test instance's checkout on the VM | required; `io/tmp/` and `io/write-ups/` are resolved under it; the kernel refuses to start if either folder is missing or not writable |
| `voice_out.documents` | `on` | `off` writes no files: a `<<<document` block stays on the card after the abstract under a `---` rule, and no spill happens; for a kernel host that does not share the Lupin instance's filesystem |

## 5. Abstract spill

- Threshold: `voice_out.abstract_spill_chars`, default `2000`, counted on the abstract text after `redact()` and before the link line.
- Over the threshold: write a `transient` document (Section 4.1) holding the whole abstract (and the document block, if any, after a `---` rule); the card's abstract becomes the head of the original, cut at the last blank line at or before the threshold (no blank line → cut at the threshold on a word boundary), then a blank line, then the link line.
- A model-written `<<<document` block is unaffected unless the abstract itself spills, in which case the two merge into the one file above, and the mode is the model's (`persistent` wins over `transient`).
- Logged: `abstract_spilled: true`, `abstract_chars` (original length), `document_path`.
- No word of the model's text is changed. This is the "harness moves an oversized abstract into a transient document" line of Section 7.1, now with a number.
- The number is a starting point. It is revisited when Lupin's payload-size hypothesis (row 03355649; `_payload_bytes` stamps every speaking-tool call) is answered; the per-turn record's `payload_bytes` (Section 8) feeds the same question from the kernel side.

## 6. Shape and repair (`pyramid.py`)

### 6.1 Shape

A reply is well formed when all four hold:

| Rule | Condition |
|---|---|
| (a) spoken block | one to three non-empty lines before the first marker |
| (b) spoken plain | no spoken line contains markdown emphasis, a code fence or span, a link, or list or heading syntax |
| (c) markers | each marker at most once, alone on its line, abstract before document |
| (d) document mode | a document marker is `<<<document transient` or `<<<document persistent` |

Marker grammar, unchanged from the probe: `^<<<(abstract|document(?: (?:transient|persistent))?)\s*$`, multiline. A line matching `^ <<<` (one leading space) is body text and is emitted with the space removed (the forgery rule, mirroring D52's).

### 6.2 Reason codes and mechanical repair

| Reason code | Trigger | Repair (never a model; never a new word) |
|---|---|---|
| `spoken_markup` | (b) fails | strip emphasis, code, link and list syntax from the spoken lines (link → its label); already what the parser does for speech |
| `spoken_over_three` | more than three spoken lines | speak the first three; the rest are prepended to the abstract under a `---` rule (an abstract is created if there was none) |
| `spoken_missing` | no spoken line | speak the first sentence of the abstract, else of the document, stripped per `spoken_markup`; none → speak `The reply is on the card.` |
| `marker_repeated` | a marker kind appears twice | the first abstract marker and the first document marker after it are honored; every other `<<<` line is body text |
| `marker_out_of_order` | document before abstract | same as `marker_repeated`: the first abstract marker, then the first document marker after it; a document marker before the abstract marker is body text |
| `marker_unknown` | `<<<` line matching neither kind | body text |
| `document_mode_missing` | `<<<document` with no mode | `transient` |

`needs_repair` is true when any code fired. `repair_reasons` is the list, in the order above. The spoken text after repair differs from the model's only by removed syntax or moved lines (Voice-4).

### 6.3 What is deleted

- Section 7.2's "local 14B rewrites spoken lines" step.
- The risk table's "`needs_repair` + 14B rewrite".
- `--json-schema` output stays as the fallback if compliance per model proves poor; the per-turn record is what decides that.

## 7. Length and the spoken cap

- The kernel counts `spoken_chars` (after repair, after link labels are stripped, the same count Lupin's cap uses) and `spoken_sentences` (the DM tutor's rule: a sentence is a unit that carries a claim; `cosa/agents/dm_tutor/sentences.py` is the reference implementation, re-implemented in the kernel with no lupin import under D45) and cuts nothing.
- *Resolved 2026-11-08 (D55): `/api/notify` routes the overflow to the abstract and stamps `spoken-cap-1` — T27 spec Section 5.* Lupin's cap (`cosa voice spoken char cap`, default 500) is enforced caller-side in the MCP layer only; `/api/notify` over REST is unrestricted. Row for Section 18 (T27): decide whether `/api/notify` applies the cap, a tutor-style distillation (with its guards and a `rewrite` treatment stamp, already a T27 row), or nothing, to REST senders whose `job_id` is a kernel persona. Until then the per-turn record gives the over-cap rate per model.

## 8. The per-turn record

One `voice.result` record per result frame, in the per-persona JSONL log (Section 11), beside the raw frame:

| Field | Type | Source |
|---|---|---|
| `engine`, `model`, `persona_id` | str | session |
| `format_rules_version` | 8 hex | SHA-256 of the Section 3 text |
| `inbox_rider` | bool | D52 provision, per persona |
| `spoken_lines` | int | after repair |
| `spoken_sentences` | int | Section 7 rule |
| `spoken_chars` | int | after repair, link labels stripped |
| `abstract_chars` | int | before spill, after `redact()` |
| `document_mode` | `null \| transient \| persistent` | model's, or `transient` when spilled with no document |
| `document_path` | str or null | relative to `lupin.root` |
| `abstract_spilled` | bool | Section 5 |
| `needs_repair` | bool | Section 6 |
| `repair_reasons` | list of str | Section 6.2 order |
| `payload_bytes` | int | UTF-8 length of `message` plus `abstract` as posted |

Queries this answers in one pass: compliance by model; the rider's effect (D52); over-cap rate per model (Section 7); payload size against delivery failure (Section 5).
