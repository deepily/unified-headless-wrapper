## 3. Voice gap (ruling 1)

### 3.1 Migration

One Alembic revision adding to `notifications`:

```python
listener_delivered_at: Mapped[Optional[datetime]] = mapped_column( DateTime( timezone=True ), nullable=True )
```

Semantics, in the model's comment: *the listener's receipt mark. Set only by `POST /api/notifications/undelivered/ack`, never by an emit result.* Partial index on `( job_id, created_at )` where `listener_delivered_at IS NULL AND direction = 'human_to_ai'`.

### 3.2 Pull

`GET /api/notifications/undelivered` gains:

| Param | Type | Meaning |
|---|---|---|
| `job_id` | str, optional | When present: persona mode. Rows with this `job_id`, `direction = human_to_ai`, `listener_delivered_at IS NULL`, `recipient_id` = the authenticated owner (the X-API-Key lane resolves the owner exactly as `answers-owed` does), within the age cap, oldest first. State is **not** consulted (a browser receipt marked it `delivered`). |
| `since` | ISO, optional | `created_at` cursor, exclusive. |
| `limit` | int | as today |

Without `job_id` the endpoint behaves as today. Each item is the same dict the live frame carries (`id`, `id_hash`, `type`, `notification_type`, `message`, `priority`, `job_id`, `sender_id`, `timestamp`, `direction`, `payload`), so the kernel's `inbox.received` record is identical for live and pulled messages.

### 3.3 Ack

`POST /api/notifications/undelivered/ack` with `{ "job_id": "...", "ids": [ ... ] }` sets `listener_delivered_at = now()` on each row that matches `job_id` and the owner; returns `{ acked: n, unknown: [ ... ] }`. Idempotent. Only setter of the column.

### 3.4 Kernel side (Phase 1 spec Sections 6, 9; T12 spec Section 5)

- `inbox.json` gains `voice_cursor` (ISO `created_at` of the newest acked voice row).
- Pull table gains a third row on every connect, first connect included: `GET /api/notifications/undelivered?job_id={persona_id}&since={voice_cursor}`, each id checked against the ledger.
- Order per voice message: **stdin write → ledger append → ack** (the "receipt" of D52's order, now concrete). The ack carries every id written since the last ack (batched per envelope).
- Live frames: the same ack after the same stdin write. A live frame and its pulled twin are the one duplicate the ledger drops (`inbox.duplicate`).
- The helper's `listener_delivered` stays a server log line; nothing in the kernel reads it.

### 3.5 Acceptance

Lupin-1, Lupin-2 (Section 12).

## 4. Treatment stamp (ruling 2)

```json
"payload": { "rewrite": { "applied": true, "rule_version": "dm-tutor-1", "chars_before": 1412, "chars_after": 388, "outcome": "rewrote" } }
```

| Field | Source |
|---|---|
| `applied` | true iff `delivered_text != body_text` |
| `rule_version` | the rewriter's version string (`DM_TUTOR_VERSION`; `spoken-cap-1` for Section 5) |
| `chars_before`, `chars_after` | `len()` of the text as submitted and as delivered |
| `outcome` | the rewriter's outcome word (`tutor_outcome` today: `disabled | not_fired | refused | rewrote`; Section 5 adds `routed_to_abstract`) |

Rules: written by the DM router into `payload` on the row **and** on the live frame; the key is absent when no rewriter ran on that path (`payload` stays null or keeps its other keys); the corpus row keeps all fifteen `tutor_*` fields unchanged. The kernel keeps `raw` verbatim (D52), so the stamp reaches the recipient's `inbox.received` untouched; direction analysis joins the sender's gate record of `dm_send` (text as written) to the recipient's `inbox.received` (text as delivered, with the stamp) on message id.

## 5. Spoken cap for REST senders (ruling 3)

Applied in `/api/notify` to every caller whose `job_id` is a persona (sender id carries `#`), before persistence and dispatch:

```python
cap, enforce = spoken_cap_from_ini()            # same two keys as cosa_voice_mcp.py
measured     = len( strip_markdown_links_for_speech( message ).strip() )
if enforce and measured > cap:
    head, overflow = split_at_sentence_boundary( message, cap )   # last sentence end at or before cap; none → cap on a word boundary
    abstract = ( "**Full spoken line:** " + message + "\n\n---\n\n" + ( abstract or "" ) ).rstrip()
    message  = head
    payload[ "rewrite" ] = { "applied": True, "rule_version": "spoken-cap-1",
                             "chars_before": measured, "chars_after": len( head ), "outcome": "routed_to_abstract" }
```

- No word is changed or lost: the full line is in the abstract verbatim; the card shows it one tap away.
- With the enforce key off: unchanged, no stamp (matches the MCP layer's kill-switch).
- The MCP layer keeps **rejecting** (a model is in the loop there and can correct itself); the REST layer **routes** (the turn has ended). The asymmetry is deliberate and documented in both places.
- Logged: `[NOTIFY] spoken cap routed: job_id, measured, cap`.
- The kernel changes nothing: its `voice.result.spoken_chars` already gives the per-model over-cap rate (D53).

## 6. Upload door (ruling 4)

`POST /api/docs/upload`: dependency `require_admin` → `require_api_key_or_jwt`, then:

| Caller | Allowed |
|---|---|
| JWT with admin role | today's behaviour, unchanged |
| JWT without admin | 403, as today |
| API key (fleet) | `dir` ∈ `{ "io/tmp", "io/write-ups" }` exactly (else 403); filename matches `^\d{4}\.\d{2}\.\d{2}-[0-9a-f]{8}-[a-z0-9-]+\.md$` (else 400); `on_conflict` ∈ `{ refuse, rename }` (else 403); existing size cap, credential check, atomic write, `view_url` unchanged; log line names `persona_id` (the eight hex from the filename) beside the account |

Docstring and `AUTH_REQUIREMENTS.md` updated to say admin-or-fleet.

Kernel (T13 spec Section 4.4; Phase 1 spec Section 9): `voice_out.documents: write | upload | off`, default `auto` → `write` when `lupin.root/io/tmp` and `io/write-ups` are writable on this host, else `upload` (multipart POST with `X-API-Key`, `on_conflict = rename`, the returned `view_url` used for the link line), `off` only by explicit config. `document_path` in `voice.result` records the server path either way.

## 8. Tickets in the client (ruling 6)

Depends on the ticket store (`/api/asks/{ticket}`, D37; `tool_approval` kind, D49), a kernel-phase Lupin row, not yet built. This section fixes the wire shape so the store emits what its consumer reads.

### 8.1 Wire shape

Every ticket event is a notification (`response_requested = true` for `pending`) carrying:

```json
"payload": { "ticket": { "id": "ask-3f2a9c1e", "kind": "yes_no | choice | free_text | tool_approval",
                         "state": "pending | answered | expired | escalated",
                         "deadline": "<ISO>", "approver": "human | manager:<id> | chief_of_staff:<id> | learner",
                         "asked_by": "<persona_id>", "question": "<text>",
                         "approval": { "rule": "...", "approval_key": "...", "act": "...", "learner_prediction": { "answer": "yes", "confidence": 0.86 } } } }
```

`approval` present only for kind `tool_approval` (fields per T26 spec Section 4.4).

### 8.2 Card behaviour (`ActionRequiredRenderer`)

| State / event | Behaviour |
|---|---|
| `pending` | today's card, keyed by `ticket.id` when present (else notification id); countdown from `deadline` |
| `answered` | today's `responded`; "answered in another session" grace unchanged |
| `expired` | today's expired message |
| `escalated` | the card is removed from the previous approver's view and rendered for the new one with the original question and a line *passed on by <previous approver>* |
| answer refused as late (`409`/`410` from the ticket answer route) | notice on the card: *Your answer arrived after the deadline for "<question>"* — the ruling's "told the answer arrived too late, naming the question" |
| kind `tool_approval` | the approval card: rule, persona, the normalized act, yes/no, optional message field, the learner prediction greyed when present (T26 spec Section 9) |

Mic row, submitting state and the holding area are reused as they stand.
