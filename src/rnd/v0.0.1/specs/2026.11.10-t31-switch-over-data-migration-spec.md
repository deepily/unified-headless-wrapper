## 2. The Switch clock, amended (replaces T19 spec Section 4.2 steps 1 to 4)

Day 0 unchanged: shadow baseline written; rollback rehearsed; `ah4l-final` tagged; the switch-over branch cut; Rick at the laptop console; the kernel-run Claude persona spawned on the development server.

1. **Freeze.** No AH4L spawn. Every manager closes or hands off its live reports in the store (`accountable_manager` reassigned where the work continues), completes any open sweep, and sweeps the board.
2. **Memento write.** One broadcast to all (D61): every seat runs `memento_io.py write --slot io` and acknowledges on the acks topic. A seat that does not acknowledge within the freeze is named in the snapshot's `skipped` list with `why: no memento ack` once the broadcast acks are joined to it (Section 10, open item).
3. **Snapshot.** On each fleet host, `t31_switch_over.py snapshot ~/.claude/sessions --out ah4l-roster-<host>-<date>.json`: one entry per bridge that passes lupin's liveness rule (pid alive, touched within twelve hours, a voice persona allocated), fields in Section 3. Read-only.
4. **Quiescence check.** `t31_switch_over.py check <snapshot> --lupin … --api-key-file …` exits non-zero while any seat is not quiet (Section 6). Rick pokes the named seats and re-runs; the stop waits.
5. **Stop AH4L.** D63's old step 4, unchanged: listeners, `lupin-arbiter-app.service`, `lupin-cc-memory-watch.service`, the managers' context-pressure cron entries; the planning-is-prompting sync stops deploying `~/.claude/CLAUDE.md`.
6. **Archive.** `t31_switch_over.py archive <snapshot> --apply` on each host (Section 10), then `rsync -a ~/.claude/mementos/ ~/.lupin/mementos/` and one `memento_io.py verify` against the new mirror.
7. **Flip** (D63's step 5), 8. **Rename the wire** (step 6), 9. **Spawn the kernel fleet** from the role templates (step 7, as written; each template's `voice_persona` is the name the snapshot shows for that role and project), 10. **Inventory** (step 8).

The snapshot has three readers: the quiescence check, the archive (it is a member), and Rick, who reads the name-per-role table off it when the templates are confirmed before step 9.

## 4. The voice-persona pool (a Lupin change, Move clock)

```sql
create table voice_persona_allocations (
    persona_id    text primary key,              -- eight hex (D46)
    persona_key   text not null,                 -- canonical key (T35): 'maria', 'mr radio'
    host          text not null,
    allocated_at  timestamptz not null default now(),
    released_at   timestamptz
);
create unique index voice_persona_open_name on voice_persona_allocations ( persona_key ) where released_at is null;
```

- `POST /api/cosa-voice/voice-persona/{persona_id}/allocate` takes the preference chain as today (`requested_persona_name`, `persona_chain`), checks each name against the configured pool (`cc session voice persona pool`, renamed under T38) and the open allocations, inserts one row, returns the name; 409 names the holder (`persona_id` and name), 422 names the off-pool token, exactly the body shapes the router documents today. The path parameter is the eight-hex id, not the UUID.
- `…/release` sets `released_at`; idempotent.
- `GET …/voice-persona/pool` reads the table for `occupied` and `free`; `GET …/voice-persona/{persona_id}` reads the row.
- The kernel calls allocate between the mint and the launch, with the template's `voice_persona` as the first link of the chain, and refuses the spawn (`respawn_blocked`, reason `voice_persona_unavailable`) on 409 or 422; calls release in `dismiss` (D59, Section 10.4) and never in hibernation (T16 spec Section 15 row 6). The registry row caches the returned name.
- Rollback: `truncate voice_persona_allocations`; the AH4L seats re-register their names into their bridges at their next SessionStart.

## 6. The quiescence check

Per live seat in the snapshot, through the fleet-key lane:

| Count | Query | Blocking |
| --- | --- | --- |
| `voice_after_last_turn` | `GET /api/notifications/undelivered?job_id=<id>&since=<last_interaction_at>` (D55) | yes |
| `dms_after_cursor` | `GET /api/dm/list?job_id=<id>` filtered to `created_at` after the seat's `.dm-inbox-hwm` cursor | yes |
| `buffer_lines` | non-empty lines in `cc-buffer-<id>.jsonl` | yes |

`check` exits 0 when every seat is quiet, 1 otherwise, and prints the seats that are not with their counts. A seat is drained by poking it once more (its next turn drains the buffer and surfaces the DMs) or, for a human line nobody will answer, by Rick deciding so and re-running with that seat removed from the snapshot by hand; the removal is visible in the archived snapshot.

## 8. Sweeps (a Lupin change, Move clock)

```sql
create table task_sweeps (
    id              uuid primary key,
    persona_key     text not null,
    project         text not null,
    started_at      timestamptz not null default now(),
    total_at_start  integer not null,
    board_ids       jsonb not null,              -- the frozen row set
    reviewed        jsonb not null default '[]',
    closed_at       timestamptz
);
create unique index task_sweeps_one_open on task_sweeps ( persona_key, project ) where closed_at is null;
```

The owed-rows query (D62) returns `sweep: { reviewed: len( reviewed ), total: total_at_start }` when an open row exists for the persona and project. `task_sweep_start`, `task_sweep_mark`, `task_sweep_close` are store routes behind the fleet key; the kernel's poke body reads the result. The ledger's expiry rule (a sweep older than its TTL reads as expired) becomes `closed_at := now()` by the store's daily sweep. No `board-sweep-*.json` is imported: the freeze completes open sweeps.

| Verb | Reads | Writes | Exit |

| `snapshot <sessions_dir> [--out F] [--no-pid-check]` | `cc-*.json`, the two ledgers, the buffers; `os.kill( pid, 0 )` | the roster JSON: `host`, `taken_at`, `live[]` (persona_id, name, name_as_written, role, project, model, workspace, manager_id, manager_name, topic, last_interaction_at, dm_cursor, answers_cursor, buffer_lines, pid, bridge), `skipped[]` with a reason | 0 |

Archive members, relative to the persona account's home: `.claude/sessions` (bridges, buffers, ledgers, holds, sweep ledgers, task-store map and spool, `spawned-*.json`, `cc-stable-*.id`, logs), `.claude/mementos`, `.claude/heartbeat-events`, `.claude/CLAUDE.md`, `.claude/settings.json`, `.lupin/arbiter` (the arbiter's local snapshot store, where present), the roster snapshot and the check report. **Never** `.claude/projects` (Claude's transcripts: the rollback needs them in place). A missing member is reported in the plan, not fatal. The copy of `lupin-app.ini` as of the tag is the tagged commit itself, not an archive member.

Expiry: `kernel.jobs` (T08) runs `archive.sweep` daily, deletes `~/.lupin/archive/ah4l-*.tar.gz` and its manifest older than `kernel archive retention days` (default 30, `[Lupin: Baseline]` in `lupin-app.ini`, splainer line "how long the AH4L archive is kept after the switch; the rollback is possible until it expires"), and logs `archive.expired { tarball, age_days }`.

Rehearsal: Switch-4 gains the forward half. On the test VM, before the rollback half: a snapshot of the VM's own seats, the check, the archive with `--apply`, the restore from that archive, one voice turn to an AH4L seat. The first run of the real thing on the development server is therefore the second run ever.
