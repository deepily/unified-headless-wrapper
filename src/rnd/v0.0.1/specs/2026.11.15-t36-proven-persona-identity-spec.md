## 1. Summary of the rulings

| # | Decision | Ruling |
|---|---|---|
| 1 | What proves a persona to Lupin | The kernel's signed grant, alone. The shared key keeps proving the account. Per-persona keys are closed. |
| 2 | How the grant is signed | Ed25519. A fresh key pair at every kernel start; the private half only in the kernel's memory; Lupin reads the public half over the kernel socket. |
| 3 | What one grant covers | One request: method, path with query, body hash, persona, role, gate call id; thirty seconds; single use. Several grants against one gate approval while the call is open. |
| 4 | Which requests must carry one | Any shared-key request that names a persona (a name ending in `#` and eight hex characters). Services and browser logins are unchanged. |
| 5 | How Lupin remembers a used grant | In memory, each entry dropped at expiry; a grant issued before the server started is refused; exactly one server worker, asserted. |
| 6 | How the requirement is switched on | `kernel grant required = no`, `observe` or `yes`. |
| 7 | When the kernel cannot be reached | The call fails: `grant_unavailable` to the agent, 401 `grant_required` from Lupin. No fallback to the shared key. |
| 8 | The slow key check that remains | A lupin ticket proposing a SHA-256 of each key in an indexed column, filled the first time an old key passes the slow check. Drafted in Section 12 for Rick to file. |
| 9 | The persona's name (follow-on) | The grant carries `voice_persona` in key form, read from the kernel's row at signing, so a proven grant leaves the task store no call to the kernel. |

## 2. The grant alone (ruling 1)

Lupin's account door (`require_api_key_or_jwt`, `api_key_auth.py` from line 205) returns a user id and nothing else. Eighteen routers sit behind it (123 routes); eight read a persona's name from the request: commons, decision proxy, direct messages, notifications, podcast proxy, speakerphone, tasks, voice persona. One new dependency, `require_kernel_grant`, sits beside the door on those eight. `v2_ask` and `docs_files`, which the framework listed, take a browser login only (`get_current_user`) and are not touched.

Per-persona keys are closed for three measured reasons: a sibling on the same account reads the key file; the key check tries every active key at about 345 ms each (Section 12), so eighteen personas would add up to six seconds per request; a key proves who, never which approved call.

## 3. The signature (ruling 2)

- The kernel generates an Ed25519 pair at start (`cryptography`, `Ed25519PrivateKey.generate()`), never serializes the private half, and derives `key_id` as the first sixteen hex characters of the SHA-256 of the public half.
- `GET /gate/key` on the kernel socket returns `{ key_id, algorithm: "EdDSA", public_key, started_at }`. Any caller may read it. Lupin reads it at first use and again when a grant names a `kid` it has not seen, which is how a kernel restart is absorbed. No signing material is in Lupin's configuration.
- Before generating the pair the kernel calls `prctl( PR_SET_DUMPABLE, 0 )`, so no core file is written and `/proc/<pid>/mem` is closed to its own account.
- Startup invariant, by host class (D59, the fleet): on `production` the kernel refuses to start with `host_memory_readable` when `/proc/sys/kernel/yama/ptrace_scope` is `0`; on `test` it records the value. `kernel.started` gains `grant_key: { key_id, dumpable: false, ptrace_scope }`.
- Where the persona account is an administrator (the test VM: passwordless `sudo`, `docker`), memory is not protected either. D50 (credential exposure) already accepts the host as the boundary there.
- Lupin declares `cryptography` in `pyproject.toml`; it ships today only through another package (47.0.0 in both containers).

## 4. One request (ruling 3)

The grant is three base64url parts joined by dots (header, claims, signature), sent as the request header `Lupin-Kernel-Grant`.

```
header  { "alg": "EdDSA", "kid": "<key_id>", "typ": "lupin-grant" }
claims  { "iss": "<host>", "sub": "<persona_id>", "role": "<role>", "sender_id": "<sender id>",
          "voice_persona": "<name in key form>" | null,
          "kind": "tool" | "kernel", "call_id": "<gate call id>" | null,
          "method": "POST", "target": "/api/notify?sender_id=…", "body_sha256": "<hex>",
          "jti": "<32 hex>", "iat": <seconds>, "exp": <iat + 30> }
```

- `target` is the path and the query string exactly as sent, never re-ordered; `body_sha256` is over the body bytes exactly as sent, the empty string for no body.
- `POST /gate/grant` `{ tool, args_sha256, method, target, body_sha256 }` → `{ grant }`. The persona is read from the caller's control group (D66, the control API contract), never from the body. The kernel finds the open approval by persona, tool and `args_sha256`, the same key the fleet's gate claims use (D59), so the tool server is handed no call id.
- One approval backs any number of grants up to `kernel grant per call limit` (256) until `kernel grant call seconds` (900) after the gate allowed the call, or until the tool call returns, whichever is first. Refusal: 403 `claim_refused`, `detail.cause` one of `no_open_approval`, `approval_closed`, `per_call_limit`.
- The kernel's own posts on a persona's behalf (speech out, broadcasts) carry `kind: "kernel"`, `call_id: null`, signed in process with no route.
- `role` and `voice_persona` in the claims are the two facts the task store reads (D67, the task store's manager checks): with a proven grant the store uses the claims and makes no call to `GET /personas/{id}` (ruling 9). `voice_persona` is the kernel's own value, which the kernel accepts only in key form (D69, canonical persona name); neither the kernel nor `require_kernel_grant` normalizes it. A name changed during a call is at most thirty seconds stale, the bound the roster cache already had.

## 5. Which requests (ruling 4)

`persona_of( name )` is the eight hex characters after `#` at the end of a sender, creator or actor (D46, the persona identifier), or nothing. With the switch at `yes`:

| Caller | Names a persona | Grant | Outcome |
|---|---|---|---|
| browser login | any | any | unchanged; the grant is not read |
| shared key | no | none | unchanged; a service |
| shared key | yes | none | 401 `grant_required` |
| shared key | yes or no | valid, for that persona | proven; identity and role from the grant |
| shared key | yes, another persona | valid | 403 `signature_mismatch` |
| shared key | any | invalid | 401 `grant_invalid`, `grant_expired`, `grant_replayed`, `grant_stale`; 403 `grant_mismatch`; 503 `kernel_unreachable` when the public key cannot be fetched |

The ten service call sites (the arbiter's notifier, the prediction engine, the embedding and speech-to-text providers, the heartbeat poker, the orchestrator) send no grant and name no persona. The old harness's five hook sites retire with it. The persona's tool server has seven send sites, not four (`cosa_voice_mcp.py` lines 3781, 3941, 3984, 4035; `task_store_tools.py` 94; `reuse_candidates.py` 151; `session_spawner.py` 1360); all seven go through one helper that calls `request_grant`.

## 6. Single use (ruling 5)

A dictionary of `jti` to expiry in the server process, pruned on every check. A grant whose `iat` is earlier than the server's start (less the skew) is refused `grant_stale`, which closes replay across a Lupin restart without storage. `GrantVerifier` refuses to be built with more than one worker unless the switch is `no`; Lupin runs one (`lupin_app/main.py` line 1204).

## 7. The switch (ruling 6)

`kernel grant required`: `no` (the grant header is ignored), `observe` (a present grant is checked and counts as proof; any failure, a missing grant on a persona-named request included, is logged as `grant.would_refuse` and the request proceeds unproven), `yes`. The key lands at the Move with `no`, goes to `observe` for the shadow run and the soak, and to `yes` at the switch-over once no old-harness session remains (D63, exit criteria).

## 8. Kernel unreachable (ruling 7)

`request_grant` turns any failure to reach the kernel socket into `grant_unavailable` (503 in the tool's error shape, retryable); the request is not sent. A refusal from the kernel (`claim_refused`) passes through unchanged. A kernel restart therefore pauses persona calls for its duration and nothing else.

## 9. Records and configuration

Kernel records (D56 catalogue additions): `gate.grant { kind, call_id, method, target, jti, n }`, `gate.grant_refused { tool, cause }`. Lupin's log: `grant.would_refuse { error, named, method, target }`. Task-store event rows keep `role_source`, with a third value `grant`.

Configuration, lupin's `lupin-app.ini` through the ConfigurationManager, in the inheriting blocks:

```
kernel grant required           = no
kernel grant seconds            = 30
kernel grant call seconds       = 900
kernel grant per call limit     = 256
kernel grant clock skew seconds = 5
```

`gate_claim_seconds` (D59) is unchanged: it governs the fleet tools' in-kernel claim, which stays single use and unsigned.

## 10. Reference implementation (runs; twenty-five tests pass on 2026-11-15, Python 3; the standard library only, except the signer of record, whose one test is skipped where `cryptography` is absent)

### `kernel_grant.py`

```python
"""
Kernel-signed grants: proven persona identity on Lupin's endpoints (T36).

Three parties, one module, no dependency outside the standard library:

    GrantIssuer    the kernel: signs one grant per request, against an approval its own gate recorded
    request_grant  the persona's tool server: asks the kernel, and fails closed when it cannot
    GrantVerifier  Lupin: checks the grant beside the account door (`require_api_key_or_jwt`)

A grant is three base64url parts joined by dots (header, claims, signature), sent in the
`Lupin-Kernel-Grant` request header. The signature is Ed25519; the private half lives only in the
kernel's memory and a fresh pair is made at every kernel start. `Ed25519Signer` needs the
`cryptography` package; `StandInSigner` (HMAC) exists only so the tests run without it.
"""
import base64, hashlib, hmac, json, re, secrets

HEADER_NAME      = "Lupin-Kernel-Grant"
PERSONA_SUFFIX   = re.compile( r"#([0-9a-f]{8})$" )
MODES            = ( "no", "observe", "yes" )
DEFAULTS         = {
    "kernel grant required"           : "no",   # no | observe | yes
    "kernel grant seconds"            : 30,     # life of one grant
    "kernel grant call seconds"       : 900,    # how long one gate approval stays open for grants
    "kernel grant per call limit"     : 256,    # grants one approval may back
    "kernel grant clock skew seconds" : 5,
}


def _encode( raw ):  return base64.urlsafe_b64encode( raw ).rstrip( b"=" ).decode( "ascii" )
def _decode( text ): return base64.urlsafe_b64decode( text + "=" * ( -len( text ) % 4 ) )
def _canonical( value ): return json.dumps( value, sort_keys=True, separators=( ",", ":" ) ).encode( "utf-8" )


def body_sha256( body ):
    """Hex SHA-256 of the request body exactly as sent; an absent body is the empty string."""
    return hashlib.sha256( body or b"" ).hexdigest()


def request_target( path, query="" ):
    """The path and the query string exactly as sent, never re-ordered: both ends hash what is on the wire."""
    return f"{path}?{query}" if query else path


def persona_of( name ):
    """The persona id a written name carries (`agy@lupin.deepily.ai#1a2b3c4d`), or None for a service name."""
    match = PERSONA_SUFFIX.search( name or "" )
    return match.group( 1 ) if match else None


class Ed25519Signer:
    """The signer of record. The private key is generated here and never serialized."""
    algorithm = "EdDSA"

    def __init__( self ):
        from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
        from cryptography.hazmat.primitives import serialization
        self._private   = Ed25519PrivateKey.generate()
        self.public_key = self._private.public_key().public_bytes( serialization.Encoding.Raw, serialization.PublicFormat.Raw )
        self.key_id     = hashlib.sha256( self.public_key ).hexdigest()[ :16 ]

    def sign( self, message ): return self._private.sign( message )

    @staticmethod
    def verify( public_key, message, signature ):
        from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PublicKey
        from cryptography.exceptions import InvalidSignature
        try:
            Ed25519PublicKey.from_public_bytes( public_key ).verify( signature, message )
            return True
        except ( InvalidSignature, ValueError ):
            return False


class StandInSigner:
    """Tests only: HMAC stands in for Ed25519 so the suite needs no package. Never deployed: its 'public' key signs."""
    algorithm = "stand-in"

    def __init__( self ):
        self.public_key = secrets.token_bytes( 32 )
        self.key_id     = hashlib.sha256( self.public_key ).hexdigest()[ :16 ]

    def sign( self, message ): return hmac.new( self.public_key, message, hashlib.sha256 ).digest()

    @staticmethod
    def verify( public_key, message, signature ):
        return hmac.compare_digest( hmac.new( public_key, message, hashlib.sha256 ).digest(), signature )


class GrantRefused( Exception ):
    """A refusal with the HTTP status and the error name the caller sees."""
    def __init__( self, status, error, detail="" ):
        super().__init__( f"{status} {error}: {detail}" )
        self.status, self.error, self.detail = status, error, detail


class GrantIssuer:
    """
    The kernel's half. `record_allow` is called by the gate for every allowed call; `issue` by
    `POST /gate/grant`, with the persona read from the caller's control group, never from the body.
    """
    def __init__( self, signer, host, started_at, configuration=None ):
        self.signer, self.host, self.started_at = signer, host, started_at
        self.configuration = dict( DEFAULTS, **( configuration or {} ) )
        self._allows = {}   # ( persona_id, tool, args_sha256 ) → { call_id, at, grants }
        self.records = []   # what the kernel writes to the persona's log

    def key( self ):
        """`GET /gate/key`: everything Lupin needs to verify, and nothing that signs."""
        return { "key_id": self.signer.key_id, "algorithm": self.signer.algorithm,
                 "public_key": _encode( self.signer.public_key ), "started_at": self.started_at }

    def record_allow( self, persona_id, tool, args_sha256, call_id, now ):
        self._allows[ ( persona_id, tool, args_sha256 ) ] = { "call_id": call_id, "at": now, "grants": 0 }

    def close_allow( self, persona_id, tool, args_sha256 ):
        """The tool call returned: its approval backs no further grant."""
        self._allows.pop( ( persona_id, tool, args_sha256 ), None )

    def _sign( self, claims ):
        header  = { "alg": self.signer.algorithm, "kid": self.signer.key_id, "typ": "lupin-grant" }
        signing = _encode( _canonical( header ) ) + "." + _encode( _canonical( claims ) )
        return signing + "." + _encode( self.signer.sign( signing.encode( "ascii" ) ) )

    def _claims( self, kind, persona, call_id, method, target, body_hash, now ):
        return { "iss": self.host, "sub": persona[ "persona_id" ], "role": persona[ "role" ],
                 "sender_id": persona[ "sender_id" ], "voice_persona": persona.get( "voice_persona" ),
                 "kind": kind, "call_id": call_id,
                 "method": method.upper(), "target": target, "body_sha256": body_hash,
                 "jti": secrets.token_hex( 16 ), "iat": now, "exp": now + self.configuration[ "kernel grant seconds" ] }

    def issue( self, persona, tool, args_sha256, method, target, body_hash, now ):
        """One grant for one request of an approved tool call. `persona` is the kernel's own row."""
        key   = ( persona[ "persona_id" ], tool, args_sha256 )
        allow = self._allows.get( key )
        cause = None
        if allow is None:                                                                 cause = "no_open_approval"
        elif now - allow[ "at" ] > self.configuration[ "kernel grant call seconds" ]:     cause = "approval_closed"
        elif allow[ "grants" ] >= self.configuration[ "kernel grant per call limit" ]:    cause = "per_call_limit"
        if cause:
            if cause != "no_open_approval": self._allows.pop( key, None )
            self.records.append( { "event": "gate.grant_refused", "persona_id": key[ 0 ], "tool": tool, "cause": cause } )
            raise GrantRefused( 403, "claim_refused", cause )
        allow[ "grants" ] += 1
        claims = self._claims( "tool", persona, allow[ "call_id" ], method, target, body_hash, now )
        self.records.append( { "event": "gate.grant", "persona_id": key[ 0 ], "kind": "tool", "call_id": allow[ "call_id" ],
                               "method": claims[ "method" ], "target": target, "jti": claims[ "jti" ], "n": allow[ "grants" ] } )
        return self._sign( claims )

    def issue_for_kernel( self, persona, method, target, body_hash, now ):
        """The kernel's own post on a persona's behalf (speech out, broadcasts): no gate call behind it."""
        claims = self._claims( "kernel", persona, None, method, target, body_hash, now )
        self.records.append( { "event": "gate.grant", "persona_id": persona[ "persona_id" ], "kind": "kernel", "call_id": None,
                               "method": claims[ "method" ], "target": target, "jti": claims[ "jti" ], "n": 1 } )
        return self._sign( claims )


def request_grant( ask_kernel, tool, args_sha256, method, path, query, body ):
    """
    The tool server's half: one grant for the request it is about to send, as a header dict.
    `ask_kernel( payload )` posts to `/gate/grant` on the kernel socket and returns the grant.
    Any failure to reach the kernel is `grant_unavailable`; there is no fallback to the bare key.
    """
    payload = { "tool": tool, "args_sha256": args_sha256, "method": method.upper(),
                "target": request_target( path, query ), "body_sha256": body_sha256( body ) }
    try:
        return { HEADER_NAME: ask_kernel( payload ) }
    except GrantRefused:
        raise
    except Exception as error:
        raise GrantRefused( 503, "grant_unavailable", type( error ).__name__ )


class GrantVerifier:
    """
    Lupin's half, one dependency beside the account door on the routers that read a persona's name.
    `fetch_key()` reads `GET /gate/key` from the kernel socket; it is called at first use and again
    when a grant names a key this server has not seen (the kernel restarted).
    """
    def __init__( self, fetch_key, verify, started_at, mode="no", workers=1, configuration=None ):
        if mode not in MODES:  raise ValueError( f"kernel grant required must be one of {MODES}, not {mode!r}" )
        if workers != 1 and mode != "no":
            raise ValueError( "the used-grant table is in memory: kernel grant required needs exactly one server worker" )
        self.fetch_key, self.verify, self.started_at, self.mode = fetch_key, verify, started_at, mode
        self.configuration = dict( DEFAULTS, **( configuration or {} ) )
        self._keys, self._used, self.log = {}, {}, []

    def _public_key( self, key_id ):
        if key_id not in self._keys:
            try:
                key = self.fetch_key()
            except Exception as error:
                raise GrantRefused( 503, "kernel_unreachable", type( error ).__name__ )
            self._keys[ key[ "key_id" ] ] = _decode( key[ "public_key" ] )
        return self._keys.get( key_id )

    def _verified_claims( self, grant, method, target, body, now ):
        try:
            header_part, claims_part, signature_part = grant.split( "." )
            header, claims, signature = json.loads( _decode( header_part ) ), json.loads( _decode( claims_part ) ), _decode( signature_part )
            key_id = header[ "kid" ]
        except Exception:
            raise GrantRefused( 401, "grant_invalid", "not a grant" )
        public_key = self._public_key( key_id )
        if public_key is None or not self.verify( public_key, f"{header_part}.{claims_part}".encode( "ascii" ), signature ):
            raise GrantRefused( 401, "grant_invalid", "signature" )
        skew = self.configuration[ "kernel grant clock skew seconds" ]
        if now > claims[ "exp" ] + skew:                  raise GrantRefused( 401, "grant_expired" )
        if claims[ "iat" ] < self.started_at - skew:      raise GrantRefused( 401, "grant_stale", "issued before this server started" )
        if ( claims[ "method" ], claims[ "target" ], claims[ "body_sha256" ] ) != ( method.upper(), target, body_sha256( body ) ):
            raise GrantRefused( 403, "grant_mismatch", "method, target or body differs from the grant" )
        self._used = { jti: expiry for jti, expiry in self._used.items() if expiry + skew >= now }
        if claims[ "jti" ] in self._used:                 raise GrantRefused( 401, "grant_replayed" )
        self._used[ claims[ "jti" ] ] = claims[ "exp" ]
        return claims

    def check( self, authenticated_by, names, grant, method, target, body, now ):
        """
        Requires:
            - the account door has already passed; authenticated_by is "api_key" or "jwt"
            - names are every sender, creator and actor the request writes (None entries allowed)
        Ensures:
            - returns { persona_id, role, sender_id, voice_persona, proven, would_refuse }; voice_persona is the
              kernel's own value, already in key form (D69), never normalized here
            - a browser login, or mode "no", is returned unproven and unchecked
            - mode "yes": a persona-named request without a valid grant for that persona raises GrantRefused
            - mode "observe": the same failure is logged and returned in would_refuse, and the request proceeds
        """
        named    = sorted( { persona for persona in map( persona_of, names ) if persona } )
        unproven = { "persona_id": named[ 0 ] if len( named ) == 1 else None, "role": None, "sender_id": None,
                     "voice_persona": None, "proven": False, "would_refuse": None }
        if authenticated_by != "api_key" or self.mode == "no": return unproven
        try:
            if grant is None:
                if named: raise GrantRefused( 401, "grant_required", f"the request names persona {named[ 0 ]}" )
                return unproven
            claims = self._verified_claims( grant, method, target, body, now )
            if any( persona != claims[ "sub" ] for persona in named ):
                raise GrantRefused( 403, "signature_mismatch", f"the grant is for {claims[ 'sub' ]}" )
            return { "persona_id": claims[ "sub" ], "role": claims[ "role" ], "sender_id": claims[ "sender_id" ],
                     "voice_persona": claims.get( "voice_persona" ), "proven": True, "would_refuse": None }
        except GrantRefused as refusal:
            if self.mode == "yes": raise
            self.log.append( { "event": "grant.would_refuse", "error": refusal.error, "named": named, "method": method.upper(), "target": target } )
            return dict( unproven, would_refuse=refusal.error )
```

### `test_kernel_grant.py`

```python
"""Tests for kernel_grant.py (T36). Run: python3 -m unittest test_kernel_grant -v"""
import unittest

from kernel_grant import ( GrantIssuer, GrantVerifier, GrantRefused, StandInSigner, HEADER_NAME,
                           body_sha256, persona_of, request_grant, request_target )

ANA    = { "persona_id": "1a2b3c4d", "role": "manager",     "sender_id": "agy@lupin.deepily.ai#1a2b3c4d", "voice_persona": "mr radio" }
BRUNO  = { "persona_id": "9f8e7d6c", "role": "implementer", "sender_id": "agy@lupin.deepily.ai#9f8e7d6c" }
BODY   = b'{"message":"done"}'
TARGET = request_target( "/api/notify", "sender_id=agy%40lupin.deepily.ai%231a2b3c4d" )
ARGS   = "a" * 64


class GrantCase( unittest.TestCase ):

    def setUp( self ):
        self.signer = StandInSigner()
        self.issuer = GrantIssuer( self.signer, host="lupin-host-test", started_at=1000 )
        self.issuer.record_allow( ANA[ "persona_id" ], "notify", ARGS, call_id="call-1", now=1100 )
        self.fetches = 0

    def fetch_key( self ):
        self.fetches += 1
        return self.issuer.key()

    def verifier( self, mode="yes", started_at=1050, **more ):
        return GrantVerifier( self.fetch_key, self.signer.verify, started_at, mode=mode, **more )

    def grant( self, now=1100, target=TARGET, body=BODY, persona=ANA ):
        return self.issuer.issue( persona, "notify", ARGS, "post", target, body_sha256( body ), now )

    def refused( self, error, function, *arguments, **keywords ):
        with self.assertRaises( GrantRefused ) as caught: function( *arguments, **keywords )
        self.assertEqual( caught.exception.error, error )
        return caught.exception

    # the kernel's half

    def test_grant_proves_the_persona_and_the_role( self ):
        result = self.verifier().check( "api_key", [ ANA[ "sender_id" ] ], self.grant(), "POST", TARGET, BODY, 1101 )
        self.assertEqual( ( result[ "persona_id" ], result[ "role" ], result[ "proven" ] ), ( "1a2b3c4d", "manager", True ) )

    def test_no_open_approval_is_refused( self ):
        refusal = self.refused( "claim_refused", self.issuer.issue, BRUNO, "notify", ARGS, "POST", TARGET, body_sha256( BODY ), 1100 )
        self.assertEqual( ( refusal.status, refusal.detail ), ( 403, "no_open_approval" ) )

    def test_one_approval_backs_several_requests_until_it_closes( self ):
        first, second = self.grant( now=1100 ), self.grant( now=1400 )
```

## 12. The slow key check (ruling 8), and the ticket for lupin

Measured on the test VM: one bcrypt check at cost 12 takes about 345 ms in the Lupin container; `_validate_api_key_sync` (`api_key_auth.py` from line 35, the loop at line 80) tries every active key, remembers nothing between requests and writes `last_used_at` on each success. The table has no identifying column (`id`, `user_id`, `key_hash`, `description`, `is_active`, `created_at`, `last_used_at`). Two active keys on the test database.

Ticket text, for Rick to file in lupin:

> **API-key check costs about 345 ms per active key on every request.** `_validate_api_key_sync` bcrypt-checks the incoming key against every active row (`cosa/rest/middleware/api_key_auth.py`, loop at line 80); measured 345 ms per check at cost 12 in the 1.1.7 container. Proposed: add an indexed, unique `key_sha256` column to `api_keys`; look the incoming key up by its SHA-256; when no row matches, fall back to the present sweep and, on a match, store the SHA-256 on that row. When every active row has the column, delete the sweep and stop writing bcrypt hashes for keys. Bcrypt's slowness protects short passwords; these keys are 64 or more random characters and cannot be guessed from a fast hash. Stated change of posture: a database leak would expose fast hashes of keys. No key is reissued. Lesser alternatives considered: an indexed key-prefix column with bcrypt kept (a flat 345 ms), or a one-minute in-memory memory of verified keys. Raised by the unified headless wrapper's D70 (proven persona identity): every persona tool call pays this cost.
