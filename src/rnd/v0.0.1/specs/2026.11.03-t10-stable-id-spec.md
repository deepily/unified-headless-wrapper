# T10: the persona id (D46)

**As of:** 2026-11-03 · **Resolves:** T10 (framework Section 4) · **Ruling:** D46 · **Source read:** lupin `6e737ca3d` (2026-11-02), laptop clone, read-only

## 1. The ruling

One identifier per persona: **eight lowercase hex characters**, minted once by the kernel, used unchanged as the `job_id`, the `sender_id` suffix, the inbound socket name and the persona directory name. No UUID form. Option B (a UUID whose first eight characters are the key) was rejected: it is format-identical to today and costs nothing to migrate, but keeps two widths of one identity that the roster has to join, and the client that depends on the join (`notifications.js`) is being replaced by the TypeScript multiplexer client anyway.

## 3. Derivation

| Derived | Value | Consumer |
|---|---|---|
| `persona_id` | `secrets.token_hex( 4 )`, minted at `POST /personas`; `^[0-9a-f]{8}$` | everything below |
| `job_id` | `persona_id` | `POST /api/notify` out (D13); `user_initiated_message` in; the ask ticket's asker |
| inbound socket | `cc-listener-{persona_id}` | `emit_to_user_or_listener_sync` (D36) |
| `sender_id` | `{local}@{project}.deepily.ai#{persona_id}`; local part `claude.code`, `agy`, `jetski` (D42) | narration out; client quiet mode keyed on the suffix; `parseSenderId` |
| `project` | `detect_project_for_path( workspace )` at creation; stored; never re-derived | the `sender_id` project segment |
| persona directory | `~/.lupin/kernel/personas/{persona_id}/` | `manifest.yaml` (rendered), `log/{yyyy.mm.dd-HHMMSS}.jsonl` segments (D14, D56; stderr is inside them), `inbox.json` (D52), rendered engine config (`.agents/hooks.json` goes in the workspace, not here) |
| spawn environment | `LUPIN_PERSONA_ID={persona_id}`, `LUPIN_SENDER_ID={sender_id}`, plus `LUPIN_KERNEL_SOCKET`, `LUPIN_API_URL` | hooks and cosa-voice read, never derive |
| memento match | `-{persona_id}.md` / `session_id={persona_id}` | unchanged |
| voice persona | `/api/cosa-voice/voice-persona/{persona_id}/allocate` and `/release`, called by the kernel at spawn and reap | needs the store change in Section 6 |

**Uniqueness at mint.** `taken` = registry ids (live and dismissed) ∪ `{ m[-11:-3] for m in glob( "<repo>/io/mementos/*-????????.md" ) }` over every repo root the kernel knows ∪ (during switch-over only) `stable_session_id[:8]` of every bridge. Collision probability per mint is about N / 2³²; the check makes it zero where it would matter.

```python
# identity.py — uhw_kernel now, lupin_kernel after the move; imported by cosa-voice after the move
import re, secrets

PERSONA_ID_PATTERN = re.compile( r"^[0-9a-f]{8}$" )
LOCAL_PART         = { "claude": "claude.code", "agy": "agy", "jetski": "jetski" }

def mint_persona_id( taken: set[ str ] ) -> str:
    """
    Requires:
        - taken holds every persona id the kernel must not reuse (registry, mementos, bridges at switch-over)
    Ensures:
        - returns eight lowercase hex characters not in taken
    """
    while True:
        candidate = secrets.token_hex( 4 )
        if candidate not in taken: return candidate

def sender_id( engine: str, project: str, persona_id: str ) -> str:
    return f"{LOCAL_PART[ engine ]}@{project}.deepily.ai#{persona_id}"

def listener_session( persona_id: str ) -> str:
    return f"cc-listener-{persona_id}"

def persona_id_from_bridge( bridge: dict ) -> str:          # switch-over only (Section 5)
    return bridge[ "stable_session_id" ][ :8 ]
```

## 4. What identity is not

- **Engine ids.** `conversation_id` (Jetski family) and the Claude `--session-id` are per-conversation, kept in the registry row, replaced on respin and verified on resume (framework Section 5.4). For Claude the kernel mints a fresh `uuid4` per conversation; it is never the persona id and never reused.
- **Role, name, voice.** `role` is a registry field; the voice persona (Rio, Krishna, …) is an allocated resource released at reap; neither is in the id. A role prefix in the id (`cos-a1b2c3d4` in the Phase 1 spec draft) is dropped: it would be an abbreviation, it would make the suffix the client parses longer than eight, and the role is one registry read away.
- **The process.** No pid anywhere in identity. `cc-{pid}.json` and `cc-stable-{pid}.id` have no successor.

**Lifetime rules.**

| Event | `persona_id` | `conversation_id` | `sender_id` |
|---|---|---|---|
| respawn after SIGINT (interrupt) | same | same, verified | same |
| self-respin (memento-seeded) | same | new | same |
| engine change (Claude → AGY) | same | new, per engine | local part changes, suffix same |
| dismiss, then spawn the same manifest | **new** | new | new suffix |
| kernel restart | same, from the registry | same, verified | same |

## 7. Persona names are not identity: the canonical-name problem (tracked as T35)

D46 settles the machine identity. It does **not** settle the persona's *name* (`María`, `Mr. Radio`, `Rachel`), which is a separate value that today crosses the same seams the kernel will own, in several spellings at once. Rick, 2026-11-03: multiple bugs and buggy workarounds trace to this display name being passed internally and used in method calls; at some point every representation has to reduce to one canonical internal form, and that will affect how the kernel interfaces fit together. The mapping itself is not decided here; this section records the facts and the one rule the kernel can adopt now.

**The forms in circulation (lupin `6e737ca3d`):**

| Form | Example | Where it lives |
|---|---|---|
| Display name | `María`, `Mr. Radio` | `voice_persona_helpers.display_name_for()`, stamped on the persona dict's `display_name` at allocation; cards, speech, roster |
| INI key | `maria`, `mr radio` | `lupin-app.ini` around line 2072: `cc session voice persona <key> voice id`, read through the `ConfigurationManager` singleton (`cosa/config/configuration_manager.py`), which every part of the ecosystem shares |
| Pool line | `maria, mr radio, Rachel, Tiberius, Rio, …` | the same INI, `cc session voice persona pool`: lowercase for the two renamed entries, capitalized for the rest, so the pool line is not itself in key form |
| `canonical_persona_key` | identity root for store writes, queries, dict keys, roster membership | `lupin_mcp/persona_normalization.py:37`, declared "THE single source of truth" after the 2026-06-18 heartbeat false-idle P0 (`maría` queried, `maria` stored, zero rows) |
| `normalize_for_match` | resolving typed or spoken references to a pool name | same module, line 91 |
| `persona_slug` | filenames, DM topics (`dm-<slug>`), session names | same module, line 125; the memento filename `<slug>-<persona_id>.md` uses it |
| Surviving local copies | their own NFKD folding, not the module | `register_session._persona_slugs` (line 992), `heartbeat_arbiter/respin_wake_check.persona_slugs` (line 440), `hooks/lib/board_sweep.persona_slug` (line 105), `cosa/repo/doc_lint/train_builder.py:91` |

**What this means for the kernel.**

1. **Only `persona_id` crosses a kernel interface.** No kernel endpoint, hook payload, MCP argument, registry key, directory name or socket name takes a persona *name*. `POST /personas/{id}/…`, `/gate`, `LUPIN_PERSONA_ID`, `cc-listener-{id}`, the persona directory: all eight hex. A name is never a routing argument. This is already implied by D46; it is stated here because the AH4L code it replaces does route on names (`dm-<slug>`, memento slot `io/mementos/<slug>.md`, `persona_chain` and `requested_persona_name` on the voice-persona endpoint, `declared_managers` rosters).
2. **The registry stores exactly one name field, `voice_persona`, in canonical-key form**, and derives the display form for humans at the edge (`display_name_for`). The kernel never stores or compares a display form.
3. **The kernel imports `lupin_mcp.persona_normalization` after the move (D38) and copies nothing.** Under D45 the Phase 1 package does not touch names at all (no voice persona allocation in Phase 1), so no copy is needed before the move. The four local folding copies above are on T35's list to delete, not to port.
4. **Lupin-side seams that still take a name** (voice-persona endpoint parameters, DM topics, memento slot names, task store `accountable_manager`, the manager roster `COSA_VOICE_MANAGERS__<PROJECT>`) are where the canonical form must be declared and enforced. That declaration, and whether the INI pool line and per-persona keys are rewritten into one key form, is T35.

**Open under T35:** which of the three derivations is *the* canonical internal representation (the module's own rule says `canonical_persona_key` for identity, `persona_slug` for names on disk and in topics); whether the configuration manager should expose the pool already normalized so no caller folds a name again; and the audit of every seam that compares a name with `==`.
