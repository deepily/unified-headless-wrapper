# T11 spec: launch per persona (D47)

**Status:** ruled 2026-11-03 (D47). Resolves T11. Summary in framework Section 5.4; this document is the detail.
**Inputs:** C11, C11b, C11c on Jetski 2026.10.16 and AGY 1.4.7 (`../evidence/`), C12 (`--mode plan`), D43 (instruction files in worktrees), D44 (default models), the role table (`2026.10.18-uhw-role-table.md`), the Phase 1 manifest (`2026.10.24-phase1-…-spec.md` Section 8).

## 1. What this decides

Two things the kernel must know before it can spawn anything: in which engine mode a persona runs, and how its standing instructions reach the model on each engine. Claude answers both with flags (`--permission-mode`, `--append-system-prompt`). The Jetski family has no system-prompt flag and a four-valued `--mode`.

## 2. Rulings

| | Ruling | Why |
|---|---|---|
| `--mode` | **`auto` for all seven roles.** Manifest validation admits no other value until a later item asks for one. `--mode auto` is passed explicitly on every spawn | `plan` (C12) parks its artifact in the engine's brain directory outside the worktree and its approval is an ordinary user turn, so it would be a second approve-then-execute loop nested inside the cascade review's own; `bestn` is unmeasured and by its name N times the tokens; `accept-edits` governs permission prompts, which every persona skips (C15 confirms it is a no-op). Explicit `--mode` keeps the recorded argv self-describing on binaries that update themselves |
| Claude counterpart | ~~`mode: auto` maps to `--permission-mode`, whose value T26 owns~~ **Ruled 11-05 (D49):** `--dangerously-skip-permissions`, and the role allow-list is `--tools`, not `--allowedTools` (ignored under `bypassPermissions`) | T26 spec Section 7 |
| Instruction layers | Six layers, rendered by the kernel, **identical text on every engine** (Section 3) | one source per layer; parity is measured on Claude (D19) |
| Channels | Layers 1–4 → `--append-system-prompt` (Claude) · the `--agent <role>` definition body in the worktree (Jetski family). Layer 5 → the worktree's `CLAUDE.md` (Claude) · kernel-written `AGENTS.md` (Jetski family, D43). Layer 6 → the first user turn | the two Jetski channels mirror Claude's two: flag ↔ agent body, `CLAUDE.md` ↔ `AGENTS.md` |
| Native tools | The role's allow-list (role table Section 1) rides in the agent definition's `tools:` frontmatter (Jetski family) or `--allowedTools` (Claude) | C11b/C11c: no `tools:` means no tools; `["*"]` and `call_mcp_tool` are launch errors; MCP is reachable regardless |
| Agent name | the role (`.agents/agents/<role>.md`, `name: <role>`) | one worktree is one persona, so the role is the informative name in `jetski agents`; identity still comes only from `LUPIN_PERSONA_ID` (C3, D46; `agentName` is `"None"` on AGY) |
| Global files | **The kernel depends on no global instruction file.** `~/.gemini/AGENTS.md`, `~/.gemini/config/rules/`, `~/.claude/CLAUDE.md` may exist on a host; the rendered set is complete without them | a fleet host also runs ad hoc sessions; global state is not per persona and not recorded per spawn |

## 3. The instruction layers

| # | Layer | Content | Text owned by | Changes when |
|---|---|---|---|---|
| 1 | Kernel contract | who the persona is (`persona_id`, role), what the kernel is (D33), gate denials, ticketed asks (D37), task store only (D21/D22), skills (D41), ask routing (D27) | this spec, Section 4 | kernel version |
| 2 | Role charter | one paragraph per role from the role table, with the role's ask route | role table | role table |
| 3 | Persona instructions | manifest `instructions:` | the manifest author | per persona |
| 4 | Response format | the format rules text of record (T13 spec Section 3; D53), the DM style line spelled out at its end | `specs/2026.11.06-t13-voice-out-spec.md` | `format_rules_version`, the text's hash, logged per turn |
| 5 | Project mandates | what Claude loads from the worktree: `CLAUDE.md`, `CLAUDE.local.md`; planning-is-prompting's deployed mandates | T18 (installer) | per project |
| 6 | First turn | memento rehydration, charter brief | T18 | per spawn |

Layers 1–4 are rendered once per spawn into `~/.lupin/kernel/personas/{persona_id}/system-prompt.md`, the record of what the model was told, and sent through the engine's channel. Layer 5 is copied, not authored: on the Jetski family `AGENTS.md` carries exactly what Claude would load from the worktree, so there is no second source. Layer 6 is prepended to the first user turn of a fresh conversation (the Phase 1 spec's `first_message` path).

## 4. Layer 1: the kernel contract

Rendered with `{persona_id}`, `{role}` and `{ask_route}` filled; the text is the same on every engine.

```
# You are a Lupin persona

- Your persona id is {persona_id} and your role is {role}. The kernel set both; never derive, guess or change them.
- The Lupin kernel brokers everything: voice, tools, spawns and Lupin itself. You act through its system calls, the cosa-voice tools. The kernel sees every tool call before it runs and may deny it with a reason; a denial is final for that call. Say what was denied and continue.
- All work is narrated. Use `notify` for progress; your end-of-turn reply is spoken, so write it in the response format below.
- Asks are ticketed. `converse`, the `ask_*` tools and `commons_ask_sync` return `pending` with a ticket after about 150 seconds. Call `ask_wait( ticket )` to keep waiting, or end your turn; the answer then arrives as your next message. An answer that arrives after the ticket's deadline is rejected, and you will be told.
- Owed work lives only in the task store (`task_*`). The engine's own task, question, scheduling, messaging and subagent tools are not yours; do not look for them.
- Skills are installed in your workspace. A slash command is expanded by the kernel before it reaches you; follow the expanded instructions.
- Questions for the human: {ask_route}
- Messages reach you as headed blocks. `[voice …]` is the human; your end-of-turn reply is spoken for you, do not call a tool to speak. `[dm … from NAME ID message M thread T]` is a peer persona; reply with `dm_send( recipient=ID, body=…, reply_to=M, thread_id=T )`. `[answer … ticket K by …]` answers a question you asked; it is context and needs no reply. `[kernel …]` is the kernel, not a person. When a message opens with `[inbox: N messages …]`, read every block before replying and answer each one.
```

`{ask_route}` by role (D27): `chief_of_staff`, `manager` → "ask directly with `converse` or an `ask_*` tool"; `steward` → "ask your manager by DM; the manager asks the human"; `author`, `implementer`, `reviewer`, `tester` → "ask your manager by DM (`dm-<manager>`); only managers and the chief of staff ask the human".

## 5. Rendering per engine

| Written at spawn | Claude | Jetski family |
|---|---|---|

| `<worktree>/AGENTS.md` | — | layer 5, copied from `CLAUDE.md` and `CLAUDE.local.md` when present; excluded from git (D43) |
| `<worktree>/CLAUDE.md` | lupin's own file, loaded natively | — |
| skills | `<worktree>/.claude/skills/` (D41) | `<worktree>/.agents/skills/` (D41) |
| hook shim | `~/.lupin/kernel/personas/{persona_id}/settings.json` (D4) | `<worktree>/.agents/hooks.json` (Phase 1 spec Section 8) |
| MCP | `…/mcp.json` with `--strict-mcp-config` (D4) | `~/.gemini/config/mcp_config.json` (host-global; per-persona identity through env, C3) |

Launch shapes, final:

```
agy    --input-format stream-json --output-format stream-json --dangerously-skip-permissions --print-timeout 0 \
       --model <D44> --mode auto --agent <role> [--conversation <id>]
jetski --input-format stream-json --output-format stream-json --dangerously-skip-permissions --use_ls_chrome_devtools_mcp=false \
       --model <D44> --mode auto --agent <role> [--conversation <id>]
claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages \
       --session-id <id> --setting-sources project,local --settings <persona>/settings.json --strict-mcp-config --mcp-config <persona>/mcp.json \
       --dangerously-skip-permissions --tools "<role native list>" --model <D44> --append-system-prompt "<layers 1–4>"          # D49 (11-05)
```

Spawn environment on every engine: `LUPIN_PERSONA_ID`, `LUPIN_SENDER_ID`, `LUPIN_ENGINE` (`agy` | `jetski` | `claude`, read by the shim, D48), `LUPIN_KERNEL_SOCKET`, `LUPIN_API_URL`. No API key.

## 6. Code: `launch.py`

```python
# launch.py — renders one persona's launch from its manifest and registry row. No state of its own.
from dataclasses import dataclass
from pathlib import Path

LAYER_FILES = ( "kernel-contract.md", "role-charter.md", "instructions.md", "format-rules.md" )   # layers 1–4, in this order
MODES       = { "agy": { "auto" }, "jetski": { "auto" }, "claude": { "auto" } }                    # D47; widened per item, never per persona


class ManifestError( ValueError ): pass


@dataclass
class Launch:
    argv  : list
    env   : dict
    files : dict           # Path → text, written idempotently before the process starts


def validate( manifest, native_tools_by_engine ):
    """
    Requires: manifest has engine, role, model, mode, native_tools
    Ensures: raises ManifestError naming the field and the ruling; returns nothing
    """
    if manifest.mode not in MODES[ manifest.engine ]:
        raise ManifestError( f"mode {manifest.mode!r} is not admitted on {manifest.engine} (D47); admitted: {sorted( MODES[ manifest.engine ] )}" )
    unknown = set( manifest.native_tools ) - native_tools_by_engine[ manifest.engine ]
    if unknown:
        raise ManifestError( f"native_tools not in the {manifest.engine} table: {sorted( unknown )}" )
    if manifest.engine != "claude" and "call_mcp_tool" in manifest.native_tools:
        raise ManifestError( "call_mcp_tool must not be listed: a launch error on the Jetski family (C11c); MCP is reachable regardless" )


def system_prompt( persona_dir ):
    """
    Requires: layers 1–4 already rendered into persona_dir
    Ensures: one string, layers in order, one blank line between, trailing newline; also written to system-prompt.md
    """
    text = "\n\n".join( ( persona_dir / name ).read_text().strip() for name in LAYER_FILES ) + "\n"
    ( persona_dir / "system-prompt.md" ).write_text( text )
    return text


def mandates( workspace ):
    """
    Ensures: layer 5 for the Jetski family: exactly what Claude would load from the worktree, in Claude's order
    """
    parts = [ p.read_text() for p in ( workspace / "CLAUDE.md", workspace / "CLAUDE.local.md" ) if p.exists() ]
    return "\n\n".join( parts ) + ( "\n" if parts else "" )


def spawn_env( persona, manifest, kernel ):
    return { "LUPIN_PERSONA_ID": persona.persona_id, "LUPIN_SENDER_ID": persona.sender_id, "LUPIN_ENGINE": manifest.engine,
             "LUPIN_KERNEL_SOCKET": str( kernel.socket ), "LUPIN_API_URL": kernel.api_url }


def jetski_family_launch( manifest, persona, workspace, persona_dir, kernel ):
    body  = system_prompt( persona_dir )
    front = ( f"---\nname: {manifest.role}\ndescription: Lupin persona, role {manifest.role}.\n"
              f"tools: [{', '.join( manifest.native_tools )}]\n---\n\n" )
    argv  = [ manifest.engine, "--input-format", "stream-json", "--output-format", "stream-json", "--dangerously-skip-permissions",
              "--model", manifest.model, "--mode", manifest.mode, "--agent", manifest.role ]
    if manifest.engine == "agy":    argv += [ "--print-timeout", "0" ]
    if manifest.engine == "jetski": argv += [ "--use_ls_chrome_devtools_mcp=false" ]
    if persona.conversation_id:     argv += [ "--conversation", persona.conversation_id ]
    files = { workspace / ".agents" / "agents" / f"{manifest.role}.md": front + body,
              workspace / "AGENTS.md": mandates( workspace ) }
    return Launch( argv, spawn_env( persona, manifest, kernel ), files )


def claude_launch( manifest, persona, workspace, persona_dir, kernel ):
    argv = [ "claude", "-p", "--input-format", "stream-json", "--output-format", "stream-json", "--verbose", "--include-partial-messages",
             "--session-id", persona.engine_session_id, "--setting-sources", "project,local",
             "--settings", str( persona_dir / "settings.json" ), "--strict-mcp-config", "--mcp-config", str( persona_dir / "mcp.json" ),
             "--dangerously-skip-permissions", "--tools", ",".join( manifest.native_tools ),       # D49: --tools, not --allowedTools
             "--model", manifest.model, "--append-system-prompt", system_prompt( persona_dir ) ]
    return Launch( argv, spawn_env( persona, manifest, kernel ), {} )
```

`.git/info/exclude` gets `AGENTS.md`, `.agents/`, `.claude/settings*.json` at provisioning (D43). Rendering is idempotent: files are rewritten on every spawn, so a changed manifest or kernel version takes effect at the next respawn without a provisioning step.
