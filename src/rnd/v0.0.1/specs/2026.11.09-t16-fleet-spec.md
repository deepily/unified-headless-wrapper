## 1. What this decides

How a persona is staffed, admitted, housed, dismissed and left idle once the kernel starts every engine; whether a fleet spans hosts; which account runs it on a production host; what replaces the launcher's `--vertex`. Re-spin itself was ruled with persona bootstrap (D54) and context exhaustion (D57); this item places it on a route and states what it keeps.

Not decided here: host capacity (T25), system broadcasts and the DM tutor (T28), the rest of the control API (T09: error model, versioning, interrupt, status), kernel restart (T08), engine authentication and quota (T22).

## 4. Who is asking: gate claims

A persona's tool server sends its `LUPIN_PERSONA_ID` and the SHA-256 of the call's arguments. The kernel accepts a fleet route from a persona only against an unused allow that its own `/gate` recorded for that persona, tool and hash, at most `gate_claim_seconds` old. A request with neither field is the operator (the CLI on the socket) and is logged `actor: operator`.

```python
# gate_claims.py — a fleet route called by a persona is accepted only against the gate's own allow (D59 part 1)
import hashlib, json, time
from collections import defaultdict, deque

def arguments_sha256( arguments: dict ) -> str:
    return hashlib.sha256( json.dumps( arguments, sort_keys=True, separators=( ",", ":" ) ).encode() ).hexdigest()

class GateClaims:
    def __init__( self, seconds=30, clock=time.monotonic ):
        self.seconds, self.clock, self.allows = seconds, clock, defaultdict( deque )

    def record_allow( self, persona_id, tool, sha256 ):          # /gate calls this on every allow of a fleet tool
        self.allows[ ( persona_id, tool, sha256 ) ].append( self.clock() )

    def claim( self, persona_id, tool, sha256 ) -> bool:          # a fleet route calls this once; single use, oldest first
        allows = self.allows[ ( persona_id, tool, sha256 ) ]
        while allows:
            if self.clock() - allows.popleft() <= self.seconds: return True
        return False
```

- Fleet tools: `spawn_sessions`, `dismiss_sessions`, `harvest_ack`, `respin_request`. A refused claim is `403` with `fleet.claim_refused` in the kernel log.
- `manager_id` on a spawned row is the claimed persona; on an operator spawn it is the body's `manager_id` or empty.
- This is the in-kernel half of T36 mechanism (b) (kernel-signed single-use grants): same key (persona × tool × `args_sha256`), no signature because both ends are the kernel.
- **One check at the build:** the tool server must hash the arguments as the hook saw them (`call_mcp_tool`'s `Arguments` on the Jetski family, the tool input on Claude), before the tool framework fills defaults.
- Under D25 this guards against confusion. A sibling on the same account can still read the socket.

## 5. Admission

```python
# admission.py — each check returns a refusal string or None; pure, no I/O
def admit( requested, rows, config ):
    live     = [ row for row in rows if row.state != "closed" ]
    managers = sum( row.role in ( "chief_of_staff", "manager" ) for row in live )
    room     = max( 0, config.size_cap - len( live ) )
    checks   = (
        lambda: "skeleton crew is on: no spawns; a re-spin is still allowed" if config.skeleton_crew else None,
        lambda: f"{requested} requested, per-call cap is {config.batch_cap}" if requested > config.batch_cap else None,
        lambda: ( f"fleet cap {config.size_cap}: {len( live )} live "
                  f"({managers} managers, {len( live ) - managers} workers), {room} fit, {requested} requested" )
                if requested > room else None,
        # check 4: host capacity — capacity_refusal( requested, engine, rows, host, table ) from capacity.py (D60, T25 spec Section 2)
        # slot 5: engine quota (T22)
    )
    return next( ( refusal for check in checks if ( refusal := check() ) is not None ), None )
```

- Runs under the registry lock together with the creation of the admitted rows (state `provisioning`), so two concurrent batches cannot both fit into the same room.
- `[fleet]` is re-read from disk at each admission; no restart to move the dial.
- Counts every row not `closed`: hibernated, `provisioning`, `dismissing`, `respinning` included.
- Records, in the kernel log: `fleet.admitted` and `fleet.refused`, each with `{ requested, live, managers, size_cap, batch_cap, skeleton_crew, actor, refusal? }`. The census a decision saw is always recoverable (lupin could not recover it on 2026-09-04).
- No fail-open rule: the census is the kernel's memory. A registry the kernel cannot load is a kernel that did not start (T08).
- Re-spin never calls `admit` (same row). `respin_credit.py` and `dismiss_sessions( respin_personas=… )` have no counterpart.
- The D49 table's `enforce` row "spawn beyond the fleet cap" is this check; the gate does not duplicate it.

## 6. The persona worktree

```
<worktree_root>/<repository>/<persona_id>/       worktree_root: [fleet], default ~/.lupin/kernel/worktrees, set per host
```

```python
# worktree.py — one private tree per persona, outside every repository (D59 part 3). Runs before provision.py.
import subprocess
from pathlib import Path

def _git( directory, *arguments ):
    return subprocess.run( [ "git", "-C", str( directory ), *arguments ], capture_output=True, text=True )

def create_worktree( main: Path, worktree_root: Path, persona_id: str, setup=() ) -> dict:
    """
    Requires: main is a git main checkout; persona_id matches identity.PERSONA_ID_PATTERN
    Ensures:  returns { path, status: created | reused | refused, reason?, base_commit?, setup: [ { command, exit_code } ] };
              never raises; a refused tree leaves nothing behind; the main checkout's working tree is untouched
    """
    path   = ( worktree_root / main.name / persona_id ).resolve()
    listed = _git( main, "worktree", "list", "--porcelain" ).stdout.splitlines()
    if f"worktree {path}" in listed:
        status = "reused"
    elif path.exists():
        return { "path": str( path ), "status": "refused", "reason": "path exists and is not a worktree of this repository" }
    else:
        path.parent.mkdir( parents=True, exist_ok=True )
        added = _git( main, "worktree", "add", "--detach", str( path ), "HEAD" )
        if added.returncode != 0:
            return { "path": str( path ), "status": "refused", "reason": added.stderr.strip() }
        status = "created"
    _git( main, "worktree", "lock", "--reason", f"lupin-persona:{persona_id}", str( path ) )   # already locked is not a failure
    steps = [ { "command": command, "exit_code": subprocess.run( command, shell=True, cwd=path, capture_output=True ).returncode }
              for command in setup ]
    return { "path": str( path ), "status": status, "base_commit": _git( path, "rev-parse", "HEAD" ).stdout.strip(), "setup": steps }
```

- **Every persona**, the chief of staff and managers included. The main checkout belongs to the human.
- **`main`** is the project's main checkout (`overrides.project` resolved through kernel config, as `lupin.root` is). Created detached at its `HEAD`, as `provision-seat-worktree.sh` does; the kit's conventions decide the branch.
- **`setup`** is `worktree_setup:` in `<repository>/.lupin/project.yaml` (optional list of shell commands, run in the tree). Lupin's entry is its virtual-environment link script. This replaces `worktree_venv.py`.
- **Refused** → that child fails, nothing is started. **A failing setup step** → `provision.worktree` at level `alert`, one spoken line, the spawn proceeds (lupin's fail-open, made loud).
- **Record:** `provision.worktree { path, status, base_commit, setup }` in the persona's log, before `provision.rendered` (D54).
- **Lifetime:** the tree outlives the process. Re-spin, hibernation and an engine change keep it. Only dismissal step 5 touches it.
- **Axes:** platform (the tool server's interpreter and import path) comes from kernel config `lupin.root`, written into the rendered tool-server config; work is the tree. Nothing activates an environment in the engine's shell.
- **Why outside the repository:** AH4L's janitor sweeps `<main>/.claude/worktrees/` and judges a seat gone partly by the absence of a pane; both harnesses share the test VM through Phase 1.
- Two repositories with the same directory name on one host would collide on `<repository>`; the kernel refuses to register the second (config validation).

## 7. Dismissal

```
POST /personas/{id}/dismiss                                        state: dismissing from step 2 to step 6
  1. reports       live reports and reports = refuse → refused_has_reports, naming them (Section 9)
  2. memento       required → [kernel dismiss <time> request=<rid>] block, urgent, the D54 respin wording with
                              "prepare to be dismissed"; wait for turn end ≤ respin.timeout (600 s);
                              a record stamped persona_id=<id> with written_at > request time?
                                found        → continue
                                first miss   → repeat once
                                second miss  → withheld_no_memento; state returns to idle; the caller is told why
                   skip     → continue
                   force    → continue whatever step 2 found
  3. branch probe  commits the working line lacks → in the result and one type: info line to the manager; never withholds
  4. stop          the engine process (SIGTERM, then SIGKILL after 10 s; process group)
  5. tree          uncommitted edits | ignored data files | unmerged commits → kept, reported
                   clean and merged → git worktree unlock, git worktree remove (no --force), git branch -d
  6. close         open task rows reassigned to the manager through Lupin's task routes; voice released;
                   row: state closed, closed_at, closed_reason; inbound socket closed
```

```python
# fleet_rules.py — the pure verdicts of D59 parts 4, 6 and 7
def dismissal_verdict( live_reports, reports, memento, force, record_found ):
    if live_reports and reports == "refuse":                             return "refused_has_reports"
    if memento == "required" and not record_found and not force:         return "withheld_no_memento"
    return "proceed"

def should_hibernate( row, queue_length, now, idle_hibernate_minutes ):
    return ( row.state == "idle" and row.process_id is not None and queue_length == 0
             and now - row.updated_at >= idle_hibernate_minutes * 60 )
```

- **Result per persona:** `status` (`retired`, `withheld_no_memento`, `already_closed`, `refused_has_reports`), `branch: { unmerged_commits, ref }`, `tree: { kept, reason }`, and one top-level `notice` naming everything kept or withheld. A caller handles four values; a withheld persona is alive and unchanged.
- **Not ported from `reap_memento.py`:** the 45 s disk poll, the freshness window and the pre-kill second look. The kernel knows when the turn ended and compares the record's stamp with its own request time.
- **Kept trees are swept later.** A tree whose row is `closed`, idle past `kept_tree_sweep_hours` (6): work committed to its branch as `WIP: auto-saved at reap <stamp>`, directory removed, branch kept unless merged. One refused for 24 h becomes a task row owned by the manager (`worktree:<path>` correlation key). Lupin's rules, unchanged. A tree whose row is not `closed` is never swept.
- **Build:** steps 1, 2, 4, 6 are kernel code (Phase 2). Steps 3 and 5 and the sweep import lupin's `reap_branch`, `seat_teardown`, `worktree_reaper`, `worktree_straggler_tickets` after the move (D38), with `seat_is_alive` answered by the registry and the lane taken from `worktree_root`. In Phase 1 `DELETE` stops the one persona and keeps its tree.
- A hibernated persona is woken for step 2 (it must write its own record) unless `memento: skip`.
- D49's `ask` row "dismiss a peer (`approver: manager`)" still runs first, in the gate.

## 8. Harvest

- Tool `harvest_ack( persona_id )`, exposed to `steward` only (role table Section 2). The tool server calls `POST /personas/{id}/harvest` with its gate claim. The kernel sets `harvested_at` and `harvested_by` on the target row and writes `fleet.harvest_ack`.
- Gate rule `dismiss_unharvested`: matches `dismiss_sessions` naming a persona whose `manager_id` has a live `steward` report and whose row has no `harvested_at`. Mode `observe`; would-deny counts are read before any change of mode (D25).
- The `harvest-complete` direct message stays as the notice people read. Built with the crew layer (Phase 2, D51).

## 9. Reports

- `reports: refuse` (default): `refused_has_reports` with the reports' ids, roles and states.
- `reports: cascade`: each report is dismissed first through all of Section 7, depth first; a withheld report withholds its manager.
- `reports: <manager id>`: each report's `manager_id` is set to it (`fleet.reassigned`), then the dismissal proceeds. The target must be a live `manager` or `chief_of_staff`.
- An engine crash orphans nobody: the row and its reports stay; the process starts again on the next message (T08).
- `PATCH /personas/{id} { manager_id }` is the standalone reassignment. D25 row "dismiss naming a session the caller didn't spawn" becomes: the claimed caller is not on the target's `manager_id` chain; mode `observe`, unchanged.

## 10. Hibernation

- A sweep every minute applies `should_hibernate`. A match stops the engine process (as step 4), clears `process_id`, sets `hibernated_at`, writes `session.hibernated`. State stays `idle`.
- The next inbound message starts the process on the stored conversation (`--conversation <id>` on the Jetski family, the session id on Claude), behind the resume check of framework Section 5.4, and writes `session.resumed { hibernated_seconds }`. A failed resume check is D54's cold start, narrated.
- An open ask ticket does not prevent hibernation; its answer is an inbound message.
- Counts against `size_cap` (staffing). Does not count against host capacity (D60), which limits running processes; **a wake re-acquires room** through check 4 and is deferred (`session.resume_deferred`, message queued, manager advised, retried each sampler pass) when there is none. Under host pressure the timer is `idle_hibernate_minutes_under_pressure` (5); a busy persona is never stopped for memory (D60).
- Hibernated past `idle_advise_hours`: one `watch.idle_advised` record and one `type: info` line to the manager (the chief of staff for a manager). Once per hibernation. The kernel never dismisses on its own.
- `idle_hibernate_minutes: 0` disables it. Manifest override `hibernate: false` keeps a persona warm (the chief of staff, by default template).
- Replaces `reap_stale_spawned` and the idle-TTL keys.
- **D61 (2026-11-10):** a broadcast whose `to` names the persona is an inbound message and wakes it; a broadcast to all is queued for the next wake and acknowledged `deferred` (T28 spec Section 5).

## 11. Hosts

- One kernel per host; one registry, one `[fleet]`, one cap; attached to the Lupin instance at `lupin.url`, which in every deployment today is on the same host.
- A manager staffs only on its own host. No kernel calls another kernel.
- `host` (the machine's hostname) is written in `kernel.started` and on every row, so rows from two kernels could be told apart later.
- **The kernel does not serve its own tail.** T17 spec Section 11's and T20 spec Section 13's fallbacks are closed as not needed. The console keeps one SSH session per host (D58).
- Jetski stays as D32 has it: checked occasionally on the work cloud workstation, not a standing fleet.

## 12. The persona account on a production host

- Kernel config `[host] class: production | test`. Default `test`.
- **Startup invariant (D50's list gains one):** on `production`, `persona_account_privileged` true (passwordless `sudo`, or membership of `docker`) → the kernel refuses to start, naming what it found. On `test` it records the flag and starts, as ruled 11-09.
- A production host that holds a human's credentials runs the kernel and every engine under a dedicated account with no `sudo` and no `docker` membership, owning `~/.lupin` and `worktree_root`.
- **Applied at switch-over** (a T19 checklist row), not before. The test VM stays as accepted.
- **First step, before any detail is ruled:** `src/captures/t16_account_inventory.sh` on the development server, reporting (a) the fleet account's `sudo -l` and groups, (b) every `sudo` and `docker` invocation in the last 30 days of hook logs, by script, (c) the repositories the fleet writes and the owner and mode of each `.git`. Not yet written.
- Known costs, to be sized by the inventory: worktrees share the main checkout's object store, so each repository must be group-writable by the account (`core.sharedRepository=group`); test tiers that drive Docker need a short `sudoers` list of named scripts.
- I have not seen the development server's accounts; everything in this section past the invariant is conditional on the inventory.
