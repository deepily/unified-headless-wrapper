## 3. The shadow, the mixed fleet and the soak

**The shadow (Phase 4).** Kernel personas run the development server's roles beside the AH4L seats that still hold them, on the same Lupin instance, for long enough to record a baseline for every measure below (at least five working days). The baseline is computed from the kernel's own records, by the same query the soak will use, and written to `src/rnd/v0.0.1/evidence/` as the soak's thresholds before the switch-over week begins.

**The mixed fleet.** Permitted only in the shadow and the soak, with an end date written into the switch-over runbook. For that period:

- `GET /api/arbiter/fleet-state`, `GET /api/arbiter/context-pressure`, `GET /api/commons/active-sessions` and the broadcast door's fan-out read the union of the bridge files and the kernel roster (`GET /personas`), each row stamped `source: bridge | kernel`. One Lupin row (Section 8), removed at the Delete clock.
- DMs need nothing: the sender id's local part differs by engine (D42) and routing is by id.
- The task store needs nothing: it is engine-blind.
- Voice: two listeners per human until the Switch clock, one bridge listener and the kernel's receipt-gated pull (D55). The human hears each message once because the recipient is a persona id, not a human; the pull and the bridge path serve different personas.
- Broadcasts: a broadcast to all reaches both populations; the acknowledgment topic carries both.

**The soak (Gate G2's operating half).** Five working days (Rick, 2026-11-10). The kernel fleet carries the whole daily load; AH4L seats are stopped (listeners down, arbiter down) but startable from the tag. The measures:

| Measure | Source record | Pass |
| --- | --- | --- |
| Out-of-memory kills | `session.oom_killed` | zero |
| Stalled personas left unattended | `turn_end.stalled` with no manager action within one tick | zero |
| Unexplained gate denies | `gate.deny` not matching a rule the operator expected | zero after review; every deny is reviewed |
| Memento verify | the daily `kernel.jobs` run of `memento_io.py verify` | green every day |
| Voice round-trip | `inbox.received` to the matching `voice.result` | 95th percentile no worse than the shadow baseline |
| Turn-end pokes per persona per day | `turn_end.poke` | no worse than the shadow baseline |
| Human terminal attach | the kernel's console log and `tmux` process table | none |

A failed measure stops the clock; the fix is made; the clock restarts from zero. Five consecutive passing working days end the soak and open the Delete commit for merge.

## 6. The inventory script

`src/captures/t19_switch_over_inventory.sh <lupin checkout> [--clock move|switch|delete] [--trace <pid>]` carries every path, INI key, route and unit name of Section 5 as rows `kind|clock|disposition|target`. For each row it prints `present <lines>`, `gone` or `unknown` (a row whose kind it cannot resolve). Run without `--clock` it reports every row; with a clock it reports that clock's rows and exits non-zero when a row that should be gone is present or a row that should be present is gone. `--trace <pid>` is the proof-workload check: it watches the process tree under the kernel for a `tmux` process and the bridge directory for a new `cc-*.json` while the workload runs, and prints both counts, which must be zero. Output goes under `src/captures/out/t19-inventory-<host>-<date>.txt`; the Delete commit's review attaches it. Grouped rows in Section 5 are expanded one target per line in the script, so a count is exact.
