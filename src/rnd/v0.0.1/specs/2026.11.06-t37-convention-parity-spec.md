# T37 · Convention parity before the AGY handoff: the kit, the port, the B gate

**As of:** 2026-11-06 · **Resolves:** T37 (framework Sections 13, 15) · **Ruling:** D51, amending D40 · **Source read:** `planning-is-prompting` at `9d8bf4f` (laptop checkout, read-only; same commit as inventory Section 19) · **Narrative for cold readers:** `narratives/2026.11.06-t37-convention-parity.md`

## 1. Problem

D40 hands implementation to an AGY persona after Kernel-1 to Kernel-8. Kernel-1 to Kernel-8 prove kernel plumbing (spawn, voice loop, interrupt, one gate deny, reconnect, resume) and nothing about behavior; the conventions an implementer needs are Phase 2's deliverable (T18). The handoff was scheduled before the thing it depends on. Inventory Section 19.1 sized the dependency: of 64 workflows, 52 name `~/.claude` paths, 18 use `/clear`, 15 use Claude hook events, 6 use `TodoWrite`, 5 use plan mode, 4 use `AskUserQuestion`; the cosa-voice calls (53 files) are already engine-neutral.

## 2. Ruling (D51), five parts, all taken as recommended on 2026-11-06

1. **Placement:** a minimum convention kit is ported, then a conventions gate (Convention-1 to Convention-9) sits between Kernel-1 to Kernel-8 and the handoff. D40 now reads "after Kernel-1 to Kernel-8 and Convention-1 to Convention-9". The crew layer stays in Phase 2, built by the AGY implementer once it lives under the kit.
2. **The kit** is the solo-implementer subset (Section 3), with the rule that a convention missed in the first week is added to the kit, never improvised around.
3. **Convention-1 to Convention-9** (Section 4) is the handoff's acceptance set; Convention-5 and Convention-9 carry a short rubric.
4. **The Phase 1 Claude Code session builds the port** (Section 5) as its last job after Kernel-8, before the handoff; T18 supplies the rules it follows.
5. **One workflow set**, with the engine-specific plumbing behind kernel verbs (Section 6); not a Claude set and an AGY set.

## 4. Acceptance Convention-1 to Convention-9 (test VM, an AGY `implementer` persona under the kernel, after Kernel-1 to Kernel-8)

| # | Do this | Pass when |
|---|---|---|
| Convention-1 | `lupin persona spawn ~/.lupin/manifests/implementer.yaml` | The session-start ritual runs unprompted: start notification, configuration load, workflow discovery, a session-manifest entry; nothing user-facing before them |
| Convention-2 | `lupin persona send <id> "/plan-session-checkpoint"` | The kernel expands the skill (D41); the persona performs the checkpoint as written; the session log shows the expanded turn |
| Convention-3 | By voice: "add a `--version` flag to the kernel CLI" | A task-store item exists (`task_*`) before the first `write`/`edit` passes the gate |
| Convention-4 | By voice: "plan it first" | A plan file under `src/rnd/<version>/` at the path `rnd-directory-policy` names, in `plan-serialization`'s format |
| Convention-5 | Let it make the edit | Code Style (spaces inside parentheses, aligned assignments, Requires/Ensures docstrings per `docstring-content`) and POST-EDIT VERIFICATION reported; rubric: three style checks, one verification line |
| Convention-6 | By voice: "commit" | `/plan-test-baseline` runs first; a planted red test blocks the commit; green lets it through |
| Convention-7 | `lupin persona respin <id>` mid-task | The memento was written at the checkpoint; the respawned persona rehydrates from it and resumes the same task-store item |
| Convention-8 | By voice: "wrap up" | Session-end ritual: `history.md` entry, `TODO.md` update, memento sweep; the retained PUSH gate arrives as a `tool_approval` ticket (D49), not a prompt |
| Convention-9 | Leave two open design questions in the brief | `ask_multiple_choice`, one question at a time, each with pros, cons and a marked recommendation (`decision-walkthrough`); rubric: one call per question, recommendation present, none batched |

Run order: Convention-1, Convention-3, Convention-4, Convention-5, Convention-6, Convention-2, Convention-7, Convention-8, Convention-9 (Convention-2 after Convention-6 so the checkpoint has something to record). Half a day. A failure names the workflow; the fix is to the port or the kit, never to the test.

## 5. The port (built by the Phase 1 Claude Code session after Kernel-8; framework Section 15 step 8)

| Task | What changes |
|---|---|
| Paths | `~/.claude`, `.claude/`, `CLAUDE.md` references in the kit's files become harness-owned names resolved by the kernel: `$LUPIN_WORKSPACE`, `$LUPIN_SKILLS_DIR` (`.agents/skills/` on the Jetski family, `.claude/skills/` on Claude, D41), `$LUPIN_MANDATES_FILE` (`<worktree>/.lupin/mandates.md` on every engine, D54), `$LUPIN_MEMENTO_MIRROR`; project values (prefix, history and to-do files) from `<repo>/.lupin/project.yaml` (D54) |
| Commands → skills | the kit's commands become `SKILL.md` files; the kernel's `/name` expansion (D41) serves both engines; `install-cosa-voice.sh` and the deploy scripts (`sync_deployed_claude_md`, `doc_deploy_parity`, `nightly_deploy`) gain the per-engine target |
| `/clear` (18 files) | "cold start" → spawn without the stored conversation; "rehydrate" → respin with the memento (Section 10 fleet); the workflows say the verb, the kernel does the act |
| Hook events (15 files) | SessionStart → the kernel's first turn (D47 layer 6); Stop → turn-end policy (T15); PreToolUse → the gate; the three hook-shaped guards (`memento_record_guard`, `rnd_write_guard`, `worktree_creation_guard`) move to the common tool shape (Section 8) |
| `TodoWrite` / `TaskCreate` (6 files) | the task store (D21, D22) |
| Plan mode (5 files) | an explicit plan step through `p-is-p-01` and `plan-serialization`; no engine plan mode (D47 admits only `--mode auto`) |
| `AskUserQuestion` (4 files) | cosa-voice `ask_*` (D5, D37) |
| Scripts | `memento_io` takes its identity from `LUPIN_PERSONA_ID` before any bridge file, mirrors under `$LUPIN_MEMENTO_MIRROR` and stamps `persona_id=` (readers accept `session_id=` too), D54; `memento_sweep` paths become harness-owned; `last_call`, `last_call_window` deliver through the inbox; `stop_poke` becomes a turn-end setting |
| Kit data | `workflow/KIT.yaml` (group → skill → workflow file) and `workflow/skill-templates/<skill>.md` per kit skill, so the kernel's provisioner renders `SKILL.md` beside `WORKFLOW.md` from data in the kit (D54, T18 spec Section 3) |

Verification of the port is Convention-1 to Convention-9 itself. Lupin-side changes: none; the kit's cosa-voice calls are unchanged.

## 6. One set, behind kernel verbs

The kit's documents stop naming engine primitives and name the verb; a short table in `p-is-p-00-start-here` maps each verb to its act per engine. AH4L honors the same verbs until switch-over, which is the one cost of a single set and the reason the port touches Claude sessions too.

| Verb in the workflow | Claude under AH4L (until switch-over) | Any engine under the kernel |
|---|---|---|
| start cold | `/clear` | spawn without `--conversation` |
| rehydrate | `/clear` then memento read | respin with memento |
| add a task | `TodoWrite` → task store (already mandated) | `task_create` |
| ask the human | `AskUserQuestion` or `ask_*` | `ask_*` (ticketed, D37) |
| plan first | plan mode | `p-is-p-01` + `plan-serialization` |
| mandates file | `~/.claude/CLAUDE.md`, `CLAUDE.md` | `$LUPIN_MANDATES_FILE` |
| skills directory | `.claude/skills/` | `$LUPIN_SKILLS_DIR` |
| prepare for re-spin | the three beats by hand: checkpoint, `memento_io.py write`, DM acknowledgment; the manager reaps and respawns | `lupin persona respin <id>`: the kernel runs the three beats and verifies the record (D54) |

## 8. Alternatives considered

| Alternative | Why not |
|---|---|
| Hand off after Kernel-1 to Kernel-8 as written (D40 unamended) | the persona follows no convention; the operator loses history, to-do, checkpoints and the decision format, the management surface the wrapper exists to preserve |
| Hand off after Phase 2 | a whole phase on paid tokens, waiting on the crew layer the solo implementer does not need |
| Port the whole layer first | about 2.5× the kit, most of it for roles the implementer does not play |
| The AGY persona ports its own conventions | builds what it does not follow; unmanageable meanwhile |
| Two workflow sets | every edit twice; drift within a month |
