Not decided here: proven persona identity (T36); renaming the `cc session voice persona …` configuration keys, which carry an engine's name (T38, engine-neutral naming); the two separators (hyphen in file and session names, underscore in DM topics), which stay.

**A word used throughout.** To *normalize* a name is to convert it, as written, into its key form by lupin's one rule: decompose accents, drop the accent marks, lowercase, turn every run of characters outside `a-z0-9` into one space, trim the ends. `María` becomes `maria`; `Mr. Radio` becomes `mr radio`. Rick ruled the word during the walk-through; earlier documents say "fold" for the same thing.

## 1. Summary of the rulings

| # | Ruling |
|---|---|
| 1 | **The key is the stored form.** `mr radio`, as `canonical_persona_key` returns it. The match form (`mrradio`), the slug (`mr-radio`) and the DM topic (`dm-mr_radio`) are computed from it and never stored as identity. |
| 2 | **A name the rule cannot carry is refused at the door.** A pool entry must be non-empty, already in key form and unique; the pool loader refuses the configuration otherwise and names the entry. Such a persona gets a hand-chosen key (`soren`) and its spelling from ruling 3. No transliteration table, no Unicode keys. |
| 3 | **The display spelling is an optional configuration key, the present rule its default.** `cc session voice persona maria display name = María`. The two-entry table in code goes. A configured spelling must normalize to the persona's key, unless the rule cannot carry it, where it is taken as given. |
| 4 | **The configuration file is rewritten into key form and the loader refuses anything else.** One lupin edit (`Rachel` to `rachel` on the pool line and in the key names); the loader returns the pool in key form, so no caller normalizes again. |
| 5 | **A written name resolves by the key first, then by the space-free match form when that names exactly one live persona; otherwise it is refused with the roster.** The broadcast door's interim `normalize_name` is replaced by lupin's two functions. |
| 6 | **The store enforces the form itself.** The repository normalizes a persona value on every write and every query, the tables carry a check that the value is in key form, and one migration at the switch-over normalizes what is already stored. |
| 7 | **The kernel checks and never normalizes.** It accepts a name only when it is already in key form and refuses anything else with the control interface's error body. Normalizing stays in lupin, in one module. |
| 8 | **Ruling 6 covers every stored persona-name column** (follow-on, same day), the notification store's `sender_persona` included. |

## 2. The stored form (ruling 1)

The key form is exactly the strings matching `^[a-z0-9]+( [a-z0-9]+)*$`: words of lowercase ASCII letters and digits, separated by single spaces, no space at either end. Every non-empty output of `canonical_persona_key` matches it, and the function is idempotent on it.

| Form | Function in `lupin_mcp/persona_normalization.py` | `Mr. Radio` | Stored |
|---|---|---|---|
| Key | `canonical_persona_key` | `mr radio` | yes, the only stored form |
| Match | `normalize_for_match` | `mrradio` | never; resolution only (ruling 5) |
| Slug | `persona_slug` | `mr-radio` | never as identity; file and session names |
| DM topic | `dm_topic_for` | `dm-mr_radio` | never as identity; the topic string |
| Display | `display_name_for` and ruling 3 | `Mr. Radio` | never; derived at the edge |

The earlier rule stands unchanged (D46, the stable persona identity): only `persona_id` crosses a kernel interface, and a name is never a routing argument.

## 3. Refusal at the door (rulings 2 and 4)

`load_persona_pool_from_config` checks the pool line before it reads any per-persona key:

| Cause | Example | The loader says |
|---|---|---|
| `empty` | `maria, , rachel` | which position is empty |
| `not_key_form` | `Rachel`, `Søren`, `mr-radio` | the entry, and the key the rule would give when it gives one |
| `duplicate` | `maria, maria` | the entry |

A refusal is a refused start on the server that reads the file, by design: the next drift is caught at start and not in production. Today the loader "never raises on a single bad entry"; that contract changes for these three causes only. A missing voice id still skips the entry as it does now.

The rule itself does not change. `Søren` is not transliterated; whoever adds the persona writes the key `soren` on the pool line and the spelling in the display key.

**The edit (lupin, development server).** As read on the test VM on 2026-11-15, seven of the fourteen pool entries are not in key form (`Rachel`, `Tiberius`, `Rio`, `Tiffany`, `Krishna`, `Clayton`, `Cheech`), and thirty-two per-persona keys carry a capital: four each for those seven and four for `Arnold`, which has keys and no pool entry. The edit lowercases the seven pool entries and the key names. `Arnold` is an open item (Section 13).

## 4. The display spelling (ruling 3)

```ini
cc session voice persona maria display name = María
cc session voice persona chloe display name = Chloé
```

- Absent, the present rule applies: each word capitalized, a period after an honorific (`mr`, `mrs`, `ms`, `dr`, `prof`, `sr`, `jr`, `st`). `mr radio` gives `Mr. Radio`.
- Present, the loader normalizes the value and compares it with the persona's key. `María` normalizes to `maria`: accepted. `Rachel` under `maria`: refused (`display_mismatch`).
- Where the rule cannot carry the spelling (after accents are dropped, a non-ASCII letter remains: `Søren`, `Straße`, `李`), the value is taken as given. This is the hand-chosen key of ruling 2.
- `_DISPLAY_OVERRIDES` is deleted; its two entries become the two lines above, in the same lupin change.

The key already exists for the overflow persona (`voice_persona_helpers.py`, the overflow loader), so the pool loader gains what the overflow loader has.

## 5. Addressing a persona in writing (ruling 5)

For each written name, against the live roster (running or hibernated personas, by key):

1. Normalize it. If the key is on the roster, that persona.
2. Otherwise remove the spaces. If exactly one roster key, with its spaces removed, equals the result, that persona.
3. Otherwise refuse: `unknown` when none matched, `ambiguous` when more than one did, with the roster in the refusal.

`@Mr. Radio:`, `@mr radio:`, `@mrradio` and `@mr-radio` all reach `mr radio`. The door's reply to an unknown name is unchanged in shape (422 with the live roster, D61, broadcasts and application notices); only the resolving function changes. `@all`, `@everyone` and the colon-delimited written form are untouched. The DM router resolves by the same two steps.

A consequence, not a decision: two pool keys that share a match form (`mr radio` and `mrradio`) are both legal under ruling 2. Each is reachable by its own key; the space-free form of a third spelling then reaches neither and is refused as `ambiguous`.

## 6. The stores (rulings 6 and 8)

| Store | Columns | Today |
|---|---|---|
| Task store | owner, accountable manager | the router normalizes (`routers/tasks.py:99`); the repository compares raw (`task_repository.py:1001`, `1005`) |
| Sweep table (`task_sweeps`, lands at Move) | `persona_key` | new; starts clean |
| Pool table (`voice_persona_allocations`, lands at Move) | `persona_key` | new; starts clean |
| Notification store | `sender_persona` | written as given from several callers; the answers-owed query compares raw (`notification_repository.py:558`) |

Three layers, each closing what the one above could miss:

1. **The repository's door.** Every method that writes or queries one of these columns passes the value through `canonical_persona_key` first. A value with no key form is refused there. No caller can forget, and callers that already normalize lose nothing (the function is idempotent).
2. **The database.** Each column carries `CHECK ( <column> ~ '^[a-z0-9]+( [a-z0-9]+)*$' )`. A null passes, as a check does. The two tables that land at Move are created with it.
3. **One migration at the switch-over.** For the existing tables: list every distinct stored value not in key form, normalize each, stop before writing if any has no key form, then add the check. The plan is printed before it is applied.

Non-pool senders are stored the same way: the DM grader's pseudo-persona `DM Quality Judge` is stored as `dm quality judge`. Any screen that prints `sender_persona` straight from the row must print the display name instead; whether one does is unverified (Section 11).

## 7. The kernel (ruling 7)

The registry's one name field, `voice_persona`, is accepted only when it matches the key-form pattern of Section 2. Anything else is refused before anything changes, with the control interface's body (D66, the control API contract) and a code already in its catalogue:

```json
{ "error": { "code": "invalid_value",
             "message": "The voice_persona 'Mr. Radio' is not in key form (lowercase letters and digits, single spaces).",
             "retryable": false,
             "detail": { "field": "voice_persona", "rule": "key_form", "value": "Mr. Radio" } } }
```

HTTP 422. The kernel holds one regular expression and no normalization: no `unicodedata`, no copy of lupin's module, before or after the move into lupin. Every caller that sets the field is lupin code, which has the module.

### `persona_name.py`

```python
"""
T35 reference: one canonical persona name. Python 3, no dependencies.

Seven rulings (2026-11-15), one function or constant each:

  1. the stored form is the key          : KEY_FORM, is_key_form
  2. refuse at the door                  : check_pool
  3. display spelling from configuration : display_name
  4. the configuration file in key form  : check_pool (the same refusal)
  5. addressing a persona in writing     : resolve_address
  6. the store's own door                : at_store_door, STORE_CHECK, plan_migration
  7. the kernel checks, never normalizes : kernel_accepts

canonical_persona_key and normalize_for_match restate lupin's
lupin_mcp/persona_normalization.py so this file runs alone. In lupin they are
imported, never copied. The kernel imports neither: it uses is_key_form only.
"""

import re
import unicodedata

KEY_FORM         = re.compile( r"^[a-z0-9]+( [a-z0-9]+)*$" )
STORE_CHECK      = "CHECK ( {column} ~ '^[a-z0-9]+( [a-z0-9]+)*$' )"
HONORIFIC_TOKENS = { "mr", "mrs", "ms", "dr", "prof", "sr", "jr", "st" }


class NameRefused( Exception ):
    """A name refused, with a cause word and a detail a caller can print."""

    def __init__( self, cause, message, **detail ):
        super().__init__( message )
        self.cause   = cause
        self.message = message
        self.detail  = detail


# ---------------------------------------------------------------- the rule

def canonical_persona_key( name ):
    """Lupin's rule, restated: accents dropped, lowercased, runs outside a-z0-9 to one space."""
    if not name or not isinstance( name, str ):
        return ""
    decomposed = unicodedata.normalize( "NFKD", name )
    unmarked   = "".join( c for c in decomposed if not unicodedata.combining( c ) )
    return re.sub( r"[^a-z0-9]+", " ", unmarked.lower() ).strip()


def normalize_for_match( name ):
    """Lupin's space-free match form, restated."""
    return canonical_persona_key( name ).replace( " ", "" )


# ---------------------------------------------------------------- ruling 1

def is_key_form( name ):
    """True when name is already the stored form: 'maria', 'mr radio'."""
    return isinstance( name, str ) and KEY_FORM.match( name ) is not None


# ---------------------------------------------------------------- rulings 2 and 4

def check_pool( entries ):
    """
    The pool loader's refusal. Every entry must be non-empty, in key form and unique.

    Returns the entries unchanged, so no caller normalizes again.
    Raises NameRefused naming the first offending entry.
    """
    seen = set()
    for position, entry in enumerate( entries ):
        if not isinstance( entry, str ) or not entry.strip():
            raise NameRefused( "empty", f"Pool entry {position + 1} is empty.", position=position )
        if not is_key_form( entry ):
            raise NameRefused(
                "not_key_form",
                f"Pool entry '{entry}' is not in key form; write a key such as "
                f"'{canonical_persona_key( entry ) or 'a hand-chosen key'}'.",
                entry=entry, position=position
            )
        if entry in seen:
            raise NameRefused( "duplicate", f"Pool entry '{entry}' appears twice.", entry=entry, position=position )
        seen.add( entry )
    return list( entries )


# ---------------------------------------------------------------- ruling 3

def rule_can_carry( display ):
    """True when the rule loses no letter of display: accents drop, 'ø', 'ß' and '李' do not."""
    decomposed = unicodedata.normalize( "NFKD", display )
    unmarked   = "".join( c for c in decomposed if not unicodedata.combining( c ) )
    return all( ord( c ) < 128 for c in unmarked )


def default_display_name( key ):
    """The present rule: capitalize each word, a period after an honorific."""
    words = [ ]
    for word in key.split():
        words.append( word.capitalize() + "." if word in HONORIFIC_TOKENS else word.capitalize() )
    return " ".join( words )


def display_name( key, configured=None ):
    """
    The display spelling of a persona.

    configured is the value of `cc session voice persona <key> display name`, or None.
    Absent, the default rule applies. Present, it must normalize to the key, unless
    the rule cannot carry its spelling (a hand-chosen key), where it is taken as given.
    """
    if not is_key_form( key ):
        raise NameRefused( "not_key_form", f"'{key}' is not in key form.", entry=key )
    if configured is None:
        return default_display_name( key )
    if not configured.strip():
        raise NameRefused( "empty", f"The display name configured for '{key}' is empty.", entry=key )
    if rule_can_carry( configured ) and canonical_persona_key( configured ) != key:
        raise NameRefused(
            "display_mismatch",
            f"The display name '{configured}' normalizes to "
            f"'{canonical_persona_key( configured )}', not to '{key}'.",
            entry=key, configured=configured
        )
    return configured


# ---------------------------------------------------------------- ruling 5

def resolve_address( written, live_keys ):
    """
    Resolve a written name ('@Mr. Radio', 'mrradio', 'mr-radio') to one live key.

    The key first; then the space-free match form when it names exactly one live
    persona; otherwise NameRefused carrying the roster.
    """
    roster = sorted( live_keys )
    key    = canonical_persona_key( written )
    if key and key in roster:
        return key
    match      = key.replace( " ", "" )
    candidates = [ k for k in roster if match and k.replace( " ", "" ) == match ]
    if len( candidates ) == 1:
        return candidates[ 0 ]
    cause = "ambiguous" if candidates else "unknown"
    raise NameRefused(
        cause,
        f"'{written}' names {'more than one' if candidates else 'no'} live persona.",
        written=written, roster=roster, candidates=candidates
    )


# ---------------------------------------------------------------- ruling 6

def at_store_door( name ):
    """What the repository does to a persona value on every write and every query."""
    key = canonical_persona_key( name )
    if not key:
        raise NameRefused( "empty", f"'{name}' has no key form.", entry=name )
    return key


def plan_migration( stored_values ):
    """
    The one migration at the switch-over, as a plan: stored value -> key.

    Values already in key form are left out. A value with no key form is refused,
    so the migration stops before it writes.
    """
    plan = { }
    for value in stored_values:
        if value is None or is_key_form( value ):
            continue
        plan[ value ] = at_store_door( value )
    return plan


# ---------------------------------------------------------------- ruling 7

def kernel_accepts( name, field="voice_persona" ):
    """
    The kernel's whole part: accept a name already in key form, refuse anything else.

    Returns the name. On refusal returns nothing and raises NameRefused whose
    error_body() is the control interface's body (422 invalid_value).
    """
    if is_key_form( name ):
        return name
    raise NameRefused(
        "invalid_value",
        f"The {field} '{name}' is not in key form (lowercase letters and digits, single spaces).",
        field=field, rule="key_form", value=name
    )


def error_body( refusal ):
    """A NameRefused as the control interface's error body."""
    return { "error": {
        "code"      : refusal.cause,
        "message"   : refusal.message,
        "retryable" : False,
        "detail"    : refusal.detail,
    } }
```

"""T35 reference tests. Run: python3 -m unittest test_persona_name -v"""

import unittest

import persona_name as pn
from persona_name import NameRefused


class TestTheRule( unittest.TestCase ):

    def test_four_spellings_one_key( self ):
        for written in ( "Mr. Radio", "mr radio", "MR_RADIO", "mr-radio" ):
            self.assertEqual( pn.canonical_persona_key( written ), "mr radio" )
        self.assertEqual( pn.canonical_persona_key( "María" ), "maria" )

    def test_key_form( self ):
        for good in ( "maria", "mr radio", "r2 d2" ):
            self.assertTrue( pn.is_key_form( good ) )
        for bad in ( "", "Rachel", "maría", "mr  radio", " maria", "mr-radio", "mr. radio", None ):
            self.assertFalse( pn.is_key_form( bad ) )

    def test_every_key_is_in_key_form_or_empty( self ):
        for written in ( "María", "Mr. Radio", "Søren", "Straße", "李", "O'Brien" ):
            key = pn.canonical_persona_key( written )
            self.assertTrue( key == "" or pn.is_key_form( key ) )


class TestThePool( unittest.TestCase ):

    def test_a_pool_in_key_form_is_returned_unchanged( self ):
        pool = [ "maria", "mr radio", "rachel" ]
        self.assertEqual( pn.check_pool( pool ), pool )

    def test_todays_pool_line_is_refused_at_its_first_capital( self ):
        today = [ "maria", "mr radio", "Rachel", "Tiberius" ]
        with self.assertRaises( NameRefused ) as caught:
            pn.check_pool( today )
        self.assertEqual( caught.exception.cause, "not_key_form" )
        self.assertEqual( caught.exception.detail[ "entry" ], "Rachel" )
        self.assertIn( "'rachel'", caught.exception.message )

    def test_duplicate_and_empty_are_refused( self ):

            pn.check_pool( [ "maria", "maria" ] )
        self.assertEqual( caught.exception.cause, "duplicate" )
        with self.assertRaises( NameRefused ) as caught:
            pn.check_pool( [ "maria", " " ] )
        self.assertEqual( caught.exception.cause, "empty" )

    def test_a_name_the_rule_cannot_carry_is_refused_not_damaged( self ):
        for written in ( "Søren", "Straße", "李" ):
            with self.assertRaises( NameRefused ):
                pn.check_pool( [ written ] )

## 14. Alternatives considered

- **The slug as the stored form:** safe everywhere, but two separators are already in use and every stored row and configuration key would be rewritten.
- **The display name stored, normalized at each comparison:** the arrangement that produced the bugs.
- **A transliteration table** (`ø` to `o`, `ß` to `ss`): never complete, changes the meaning of existing keys, and non-Latin scripts still fail.
- **Unicode keys:** topics, file names and the server's topic pattern are ASCII.
- **The display table kept in code,** or the display name stored in the kernel registry: a release per name, or two fields that can disagree against the one-name-field rule.
- **Normalizing the configuration on read:** the per-persona key lookup must be normalized too, and the file keeps teaching the wrong form.
- **Key-only addressing,** or keeping the interim `normalize_name`: `@mrradio` refused, or a second rule that differs on punctuation.
- **Leaving the form to callers,** or the database check alone: each new caller a new chance for the bug, or callers passing a display name failing where they work today.
- **A copy of the module in the kernel with a parity test,** or waiting for the move: a second copy, which is how the local copies began, or no rule in the registry until then.
