## 4. The background-task tool (ruling 2)

`manage_task` is the second half of `run_command`. A command started with a wait shorter than its run time continues as a background task; `manage_task` lists such tasks, reads one's status and recent output, sends it input, or kills it.

- **It is never written into a tool list.** The engine attaches it to every persona definition; the validator refuses it in a list (Section 6) so the record of what the kernel wrote stays the list of grants.
- **It is expected wherever `run_command` is granted,** which is every role. `expected_tools( granted )` adds it.
- **The "native duplicates" rule no longer matches it.** That rule covers the seven never-listed tools of Section 3.
- **The gate has a shape for it:** `task{ action, task_id }` for every call. A `kill` also carries `task_kill{ task_id }`, read by the process-and-service rule: a task of the persona's own conversation is inside the persona's own tree, so the rule does not match and the kill is allowed; the shape is there so the rule sees it and the log records it.
- **An action outside `list`, `status`, `send_input`, `kill` is denied,** under ruling 5's reasoning: an action the gate has no shape for.
- **The argument names are provisional** (`Action`, `TaskId`, `Input`): they are the names the tool was declared with to a session on AGY 1.5.9, not names read from a hook payload. `Tools-6` captures them on both engines before the gate is built.

## 5. Text sent to a running command (ruling 3)

A `send_input` call carries `shell_input{ task_id, command }`, where `command` is the text sent. **Every rule that reads a `shell` command line reads `shell_input.command` in the same way, in the same mode:** history rewrite, branch lock, merge head, destruction outside the worktree, process and service, and the rest of the destructive-act taxonomy (T26 spec, Section 6). An `ask` rule that matches opens the same ticket, keyed on the same normalized command, so an approval given for the command line is the approval consumed by the typed text and conversely.

The working directory for repository-resolving rules is the session workspace, as for a `run_command` call without one (framework Section 8, port rule 1): the gate does not know the running task's directory.

Text sent to a program that is not a shell may match a rule and be held for approval. That cost was accepted with the ruling.

## 6. Names in a persona definition (ruling 4)

The per-engine table of built-in tools (`native_tools_by_engine` in the launch-per-persona spec's `validate`) holds, for `agy` and `jetski` alike: `run_command`, `read_file`, `write_file`, `edit_file`, `search_web`, `invoke_subagent`. `validate_tool_list( engine, names )` refuses, before any launch and naming every fault at once:

| Name | Refusal |
|---|---|
| `view_file`, `write_to_file`, `replace_file_content` | retired; write `read_file`, `write_file`, `edit_file` |
| `notebook_edit`, `grep_search`, `find_by_name`, `list_dir`, `read_url_content`, `code_search` | retired; the engine accepts the name and delivers no tool |
| `manage_task` | never listed; it arrives with `run_command` |
| `generate_image`, `skill_search` | granted to no role |
| `call_mcp_tool` | a launch error in a tool list (C11b, C11c) |
| a name listed twice; any other name | refused |

So a retired name beside its current name, which stops the engine with `tool name conflict`, cannot reach a launch. The gate's adapter keeps the retired aliases for calls a hook reports under them: `canonical_name` maps them to the current name before any rule reads the call. The framework's tool map keeps its old-name column on that footing.

Whether `invoke_subagent` is delivered was not measured by C17; it stays in the table on the October captures and is subject to Section 8's check like any other granted name.

## 7. A built-in tool the gate does not know (ruling 5)

A call whose tool name is not a current grantable name, a retired alias, `manage_task` or `call_mcp_tool` is **denied**, with the reason `built-in tool not in the <engine> table: <name>`. The rule is `unknown_builtin_tool`, mode `enforce` from the first day. The first denial for a tool on an engine version writes `gate.unknown_tool` and one notice; later denials write the gate's ordinary record only.

This reverses the default for built-in tools only: the role table's "first matching rule decides; default allow" continues to hold for a call the gate can shape. `generate_image`, `skill_search` and any retired no-op that a later version revives are refused by this rule if they ever reach a persona. Admitting a new tool is a change to the adapter's table, made with a shape for the gate.

## 8. A granted tool that does not arrive (ruling 6)

The vetting run for an unseen engine version (D48, engine vetting at spawn) launches with the widest role's tool list and, in the turn it already spends, asks the model to name every tool it has, each in backticks, and to put nothing else in backticks. `compare_vetting_reply( granted, reply )` decides:

| Finding | Outcome |
|---|---|
| The reply names no tool | the version is refused |
| A granted core tool (`run_command`, `read_file`, `write_file`, `edit_file`) is not named | the version is refused, as for any other vetting failure (the persona enters `respawn_blocked`, the reason is narrated) |
| Another expected name is not named (`manage_task` included) | admitted; the name is recorded in `not_delivered` for that version, narrated once, and left out of what a persona on that version is told it has |
| A name is reported that was neither granted nor expected | admitted; recorded in `unexpected` and narrated once. Section 7 refuses it at its first use |

A reply under a retired alias counts as the current tool. The result is stored with the version's entry in `vetted-engines.json` and written as one `vetting.tools` record. The comparison rests on a model's account of itself; thirteen replies across the two engines stated the tool set consistently.

## 9. Records and configuration

Two records, in the log catalogue's form (D56, log schema):

```
gate.unknown_tool { engine, engine_version, tool, persona_id }          once per ( engine, engine_version, tool )
vetting.tools     { engine, engine_version, granted, reported, not_delivered, unexpected, verdict }
```

One rule, `unknown_builtin_tool`, mode `enforce`, in the rule table of record. No new configuration key: the per-engine table and the aliases are adapter constants, changed with the adapter. The notices are `type: info`, `priority: low`, as D73 (the deferred captures) set for a vetting notice.

**Set by this spec without a click** (row 54 of "Outstanding actions"): the two records' names and fields; the rule's name; the shapes' names (`task`, `task_kill`, `shell_input`); a denial for an unknown `manage_task` action; the vetting prompt's wording; an unexpected name admitted at vetting rather than refusing the version; the reply naming no tool refusing the version; `manage_task` refused in a tool list rather than tolerated.

`builtin_tools.py`:

```python
"""Built-in tools of the Jetski-family engines: the per-engine table, the launch check, the gate's
handling of the background-task tool and of an unknown tool, and the vetting comparison (D74, T14).

Dependency-free. Measured on AGY 1.5.9 and Jetski 2026.11.13 (capture C17, 2026-11-16).
The argument names of the background-task tool are PROVISIONAL: they are the names the tool was
declared with to a session on AGY 1.5.9, not names read from a hook payload.
"""
import re

# Names the kernel may write into a persona definition's tool list (ruling 4): current names only.
GRANTABLE = frozenset( { "run_command", "read_file", "write_file", "edit_file", "search_web", "invoke_subagent" } )
# Tools without which no role can work; one missing refuses an engine version (ruling 6).
CORE = frozenset( { "run_command", "read_file", "write_file", "edit_file" } )
# Tools the engine attaches to every persona definition, granted or not (ruling 2).
ARRIVES_UNGRANTED = frozenset( { "manage_task" } )
# The second half of a granted tool: present wherever its first half is.
COMPANION_OF = { "manage_task": "run_command" }
# Retired names the vendor still accepts and maps to a current tool.
RETIRED_ALIAS = { "view_file": "read_file", "write_to_file": "write_file", "replace_file_content": "edit_file" }
# Retired names the vendor still accepts as a no-op: the launch succeeds and the model receives nothing.
RETIRED_NO_OP = frozenset( { "notebook_edit", "grep_search", "find_by_name", "list_dir", "read_url_content", "code_search" } )
# Tools that exist and are granted to no role (ruling 1 and the launch ruling).
UNGRANTED_BY_POLICY = { "generate_image": frozenset( { "agy", "jetski" } ), "skill_search": frozenset( { "jetski" } ) }
# The generic tool-server call; never written into a tool list (a launch error) and shaped elsewhere.
TOOL_SERVER_CALL = "call_mcp_tool"
ENGINES = frozenset( { "agy", "jetski" } )

TASK_ACTION, TASK_ID, TASK_INPUT = "Action", "TaskId", "Input"      # provisional, see the module docstring
TASK_ACTIONS = frozenset( { "list", "status", "send_input", "kill" } )


class ToolListError( ValueError ):
    """A persona's tool list the kernel refuses before launch."""


def validate_tool_list( engine, names ):
    """
    Check a role's built-in tool list before it is written into a persona definition.

    Requires: engine in ENGINES; names is a list of strings
    Ensures: returns the list unchanged when every name is a current, grantable name, once
    Raises: ToolListError naming every fault: a retired name with its current name, a retired
            no-op, a tool that is never granted, a duplicate, an unknown name
    """
    if engine not in ENGINES: raise ToolListError( f"unknown engine: {engine}" )
    faults = []
    seen   = set()
    for name in names:
        if name in seen:                         faults.append( f"{name}: listed twice" )
        elif name in RETIRED_ALIAS:              faults.append( f"{name}: retired; write {RETIRED_ALIAS[ name ]}" )
        elif name in RETIRED_NO_OP:              faults.append( f"{name}: retired; the engine accepts the name and delivers no tool" )
        elif name in ARRIVES_UNGRANTED:          faults.append( f"{name}: never listed; it arrives with {COMPANION_OF[ name ]}" )
        elif name in UNGRANTED_BY_POLICY:        faults.append( f"{name}: granted to no role" )
        elif name == TOOL_SERVER_CALL:           faults.append( f"{name}: a launch error in a tool list" )
        elif name not in GRANTABLE:              faults.append( f"{name}: not in the {engine} table" )
        seen.add( name )
    if faults: raise ToolListError( "; ".join( faults ) )
    return list( names )


def expected_tools( granted ):
    """
    The tools a persona should report having: those granted, and each ungranted arrival whose first half is granted.

    Requires: granted is an iterable of current names
    Ensures: returns a frozenset; manage_task is in it exactly when run_command is granted
    """
    granted = frozenset( granted )
    return granted | frozenset( t for t in ARRIVES_UNGRANTED if COMPANION_OF[ t ] in granted )


def known_to_gate( engine, name ):
    """
    Whether the gate has a shape for a built-in tool name on this engine (ruling 5).

    Requires: engine in ENGINES
    Ensures: True for current grantable names, their retired aliases, the ungranted arrivals and the tool-server call
    """
    return name in GRANTABLE or name in RETIRED_ALIAS or name in ARRIVES_UNGRANTED or name == TOOL_SERVER_CALL


def canonical_name( name ):
    """The current name for a call the hook reports under a retired alias; any other name unchanged."""
    return RETIRED_ALIAS.get( name, name )


def gate_shapes( engine, name, arguments ):
    """
    Turn one built-in call into the common shapes the gate's rules read.

    Requires: engine in ENGINES; arguments is a dict
    Ensures: returns ( "deny", reason ) for a tool the gate does not know (ruling 5)
    Ensures: returns ( "shapes", [ ... ] ) otherwise; for the background-task tool the list holds
             task{action, task_id} and, for send_input, shell_input{task_id, command} whose command
             is the text sent, to be judged by the command-line rules (ruling 3); a kill carries
             task_kill{task_id} for the process rule (ruling 2)
    Ensures: an action outside the four known ones is denied
    """
    if not known_to_gate( engine, name ):
        return ( "deny", f"built-in tool not in the {engine} table: {name}" )
    name = canonical_name( name )
    if name != "manage_task":
        return ( "shapes", [ { "shape": "builtin", "tool": name, "arguments": arguments } ] )
    action  = arguments.get( TASK_ACTION )
    task_id = arguments.get( TASK_ID )
    if action not in TASK_ACTIONS:
        return ( "deny", f"manage_task action not in the {engine} table: {action}" )
    shapes = [ { "shape": "task", "action": action, "task_id": task_id } ]
    if action == "send_input":
        shapes.append( { "shape": "shell_input", "task_id": task_id, "command": arguments.get( TASK_INPUT ) or "" } )
    if action == "kill":
        shapes.append( { "shape": "task_kill", "task_id": task_id } )
    return ( "shapes", shapes )


_NAME = re.compile( r"`([a-z][a-z0-9_]*)`" )


def names_in_reply( reply ):
    """The tool names a model's reply puts in backticks, as a set."""
    return set( _NAME.findall( reply or "" ) )


def compare_vetting_reply( granted, reply ):
    """
    Compare the tools a model says it has with the tools it was given (ruling 6).

    Requires: granted is the tool list the vetting launch wrote; reply is the model's answer to
              "name every tool you have, each in backticks, and nothing else in backticks"
    Ensures: verdict "refuse" when a core tool that was granted is missing, or the reply names no tool at all
    Ensures: verdict "admit" otherwise, with not_delivered (granted, absent), unexpected (present,
             neither granted nor a known ungranted arrival) and told (what the persona is told it has)
    """
    expected = expected_tools( granted )
    reported = { canonical_name( n ) for n in names_in_reply( reply ) }
    missing    = sorted( expected - reported )
    unexpected = sorted( reported - expected )
    core_gone  = sorted( ( CORE & frozenset( granted ) ) - reported )
    if not reported:
        return { "verdict": "refuse", "reason": "the reply names no tool", "not_delivered": missing, "unexpected": [], "told": [] }
    if core_gone:
        return { "verdict": "refuse", "reason": "core tool not delivered: " + ", ".join( core_gone ),
                 "not_delivered": missing, "unexpected": unexpected, "told": [] }
    return { "verdict": "admit", "reason": "", "not_delivered": missing, "unexpected": unexpected,
             "told": sorted( frozenset( granted ) & reported ) }
```

import unittest
from builtin_tools import ( validate_tool_list, ToolListError, expected_tools, known_to_gate, canonical_name,
                            gate_shapes, names_in_reply, compare_vetting_reply )

AGY_REPLY    = "The tool `grep_search` is not available in my toolset (only `read_file` and `manage_task` are provided)."
JETSKI_REPLY = "The only tools declared here are `read_file`, `edit_file`, and `manage_task`."


class ToolList( unittest.TestCase ):
    def test_current_names_pass( self ):
        names = [ "run_command", "read_file", "write_file", "edit_file", "search_web" ]
        self.assertEqual( validate_tool_list( "agy", names ), names )
        self.assertEqual( validate_tool_list( "jetski", [ "run_command", "read_file", "invoke_subagent" ] )[ 2 ], "invoke_subagent" )

    def test_retired_alias_names_its_current_name( self ):
        with self.assertRaises( ToolListError ) as c: validate_tool_list( "agy", [ "view_file" ] )
        self.assertIn( "write read_file", str( c.exception ) )

    def test_alias_beside_current_name_is_refused_before_the_engine_sees_it( self ):
        with self.assertRaises( ToolListError ): validate_tool_list( "jetski", [ "view_file", "read_file" ] )

    def test_retired_no_op_is_refused( self ):
        for name in ( "notebook_edit", "grep_search", "find_by_name", "list_dir", "read_url_content", "code_search" ):
            with self.assertRaises( ToolListError ) as c: validate_tool_list( "agy", [ "read_file", name ] )
            self.assertIn( "delivers no tool", str( c.exception ) )

    def test_manage_task_is_never_listed( self ):
        with self.assertRaises( ToolListError ) as c: validate_tool_list( "agy", [ "run_command", "manage_task" ] )
        self.assertIn( "arrives with run_command", str( c.exception ) )

    def test_ungranted_tools_and_unknown_names( self ):
        for name in ( "generate_image", "skill_search", "call_mcp_tool", "uhw_no_such_tool_7731", "ask_question" ):
            with self.assertRaises( ToolListError ): validate_tool_list( "jetski", [ name ] )

    def test_duplicate_and_every_fault_reported( self ):
        with self.assertRaises( ToolListError ) as c: validate_tool_list( "agy", [ "read_file", "read_file", "view_file", "bogus" ] )
        text = str( c.exception )
        for part in ( "listed twice", "retired; write read_file", "bogus: not in the agy table" ): self.assertIn( part, text )

    def test_unknown_engine( self ):
        with self.assertRaises( ToolListError ): validate_tool_list( "other", [ "read_file" ] )

            verdict, reason = gate_shapes( "jetski", name, {} )
            self.assertEqual( verdict, "deny" ); self.assertIn( name, reason )

    def test_known_names( self ):
        for name in ( "run_command", "read_file", "write_file", "edit_file", "search_web", "invoke_subagent",
                      "manage_task", "view_file", "write_to_file", "replace_file_content", "call_mcp_tool" ):
            self.assertTrue( known_to_gate( "agy", name ), name )

    def test_alias_is_shaped_under_its_current_name( self ):
